Companion to `docs/plans/v1.4-plan.md`. Records the actual message, state, and
error flows for the settings migration runner, param-contract enforcement,
PermissionGate deletion, and the action-envelope consolidation.

## §A — Migration runner

```
boot / explicit `allbert admin settings migrate`
  v
Settings.MigrationRunner
  +-- read stored settings version
  +-- select ordered pending migrations
  +-- for each:
  |     journal BEGIN (id, from, to, timestamp)
  |     apply
  |     journal COMMIT  (or ROLLBACK on failure)
  +-- write new stored version
  v
{:ok, %{applied: [...], from: v, to: v'}}
```

**Resumability.** The journal is the source of truth. A migration interrupted
between BEGIN and COMMIT is detected at next start and rolled back before the
ordered sequence resumes — never re-applied on top of partial state.

**Failure modes**

| Condition | Outcome |
| --- | --- |
| Migration raises | Journal ROLLBACK; stored version unchanged; boot fails closed with the migration id |
| Rollback itself fails | Fail closed and refuse to start; the operator gets the journal path and the failing id. Never proceed on unknown state |
| Version ahead of the binary | Fail closed — a newer Allbert wrote these settings |
| No pending migrations | No-op, no journal entry |

**Non-additive change** remains governed by ADR 0046 as narrowed at v1.3 M9.b:
annotation-only `deprecated?: true` with a non-empty reason is additive; type,
default, validation, writability, safety, incomplete annotations, and later
removal are not.

## §B — Runner consumers

```
M2 consumer 1: telegram/email plugin-owned settings
  old plugin-local shapes -> Settings Central fragment rows
  PRESERVES operator values; never rewrites a stored value silently

M2 consumer 2: legacy intent.*model_profile removal
  read legacy key -> map to model_roles.* (v1.8) -> remove legacy key
  rollback restores the legacy key with its original value
```

**Binding:** an operator's stored value survives migration and rollback
byte-identically. A migration that cannot preserve a value fails rather than
guessing.

## §C — Param-contract enforcement

```
action invocation -> Actions.Registry -> Actions.Runner.run/3
  |
  +-- resolve capability metadata
  +-- validate params against the declared schema     <- now ALL actions
  |     invalid -> {:error, {:param_contract, details}}   never reaches run/2
  +-- run
```

M0 resolves what v0.59 actually shipped versus the full v0.54 cross-action scope.
The delta is the M3 work. Acceptance requires proving the v0.59 subset is
strictly contained in what now runs — not merely that the new scope is larger.

## §D — PermissionGate deletion (highest-risk change)

```
BEFORE                          AFTER
action -> PermissionGate  \     action -> param contract -> Security.Policy
       -> param contract  /                (one path)
```

Ordered, and the order is binding:

1. M3 completes enforcement.
2. M6 enumerates every former `PermissionGate` call site.
3. For each, a **red-first** row proves the decision is identical through the
   param contract — the row must fail before deletion and pass after.
4. Only then is the module deleted.
5. Adversarial rows attempt to reach each covered action through a path the gate
   previously guarded.

**If any call site cannot be proven identical, deletion stops.** A partial
deletion leaving two authority paths is worse than the current state.

## §E — Action envelope consolidation

```
use AllbertAssist.Action, permission: :memory_write, name: "update_memory_entry", ...
  |
  +-- capability metadata (already stored today as capability/0)
  |
  +-- NOW ALSO GENERATES:
        denied/1, error/2, action/3,
        the standard four-key output_schema,
        the confirmation-summary helper,
        the request-context normalizer
        — all defoverridable
```

**Behaviour-preservation is the acceptance bar.** For a representative sample
across every action category, the full response envelope is captured before and
after — `message`, `status`, `permission_decision`, `error`, `actions` — on the
completed, denied, and error paths. Any difference is a defect.

Outliers keep hand-written helpers, each recorded with the reason it differs.

## §F — Divergent primitive disposition (M5)

Not a refactor. Each needs a semantics decision first.

| Primitive | Divergence | Decision needed |
| --- | --- | --- |
| `truthy?/1` | 50 definitions, 8 truth sets. `Runtime.truthy?` (`runtime.ex:647`) accepts integer `1`; `Security.Policy.truthy?` (`security/policy.ex:558`) does not. Others accept `"yes"`, `"on"`, `"all"`, `"enabled"` | Which truth set is correct for a security-adjacent predicate? |
| `json_safe/1` | 12 implementations. `conversations.ex:701` handles `Date`/`Time` and improper lists; `jobs/runner.ex:355` neither; `plan_build.ex:210` passes tuples through unchanged and can emit non-JSON-encodable output | Which is correct, and are the other two latent encoding bugs? |

Each is unified with a recorded decision, or deferred with a recorded reason. No
silent unification — changing a security predicate's truth set by refactor is
exactly the failure this milestone exists to avoid.

## §G — Security eval rows (`:v14`, gate-bound, behavioral)

| Row | Assertion |
| --- | --- |
| `spine-migration-rollback-001` | A failed migration rolls back and leaves the stored version unchanged |
| `spine-migration-resume-001` | An interrupted migration rolls back before the sequence resumes; never re-applied on partial state |
| `spine-migration-preserves-values-001` | Operator-authored values survive migrate and rollback byte-identically |
| `spine-migration-version-ahead-001` | Settings written by a newer Allbert fail closed |
| `spine-param-contract-complete-001` | Every registered action validates params before `run/2` |
| `spine-gate-parity-001` | Each former PermissionGate call site yields an identical decision through the param contract (red-first) |
| `spine-gate-no-bypass-001` | No path reaches a previously gated action without a param-contract decision |
| `spine-envelope-preserved-001` | Generated envelopes match hand-rolled ones across completed, denied, and error paths |

## Smoke Checklist

```bash
# migration applies and is reversible
allbert admin settings migrate --dry-run
allbert admin settings migrate
# PASS: reports applied ids and the new version

allbert admin settings migrate --rollback
# PASS: stored version returns to its prior value; operator values intact

# param contract covers everything
allbert admin actions list --format json | jq -r '.[].name' | wc -l
# PASS: count matches the number of contract-checked actions

# gate is gone
grep -rc "PermissionGate" apps/allbert_assist/lib || echo "0 — deleted"
```

## §H — Focused operator validation (FV)

### FV-01 — a real migration, reversed

Operator runs a migration against a settings tree containing their own
non-default values, then rolls it back. **Records:** whether any value changed,
and whether the journal made the sequence understandable.

### FV-02 — interrupted migration

Operator interrupts a migration mid-sequence and restarts. **Records:** whether
Allbert recovered without manual repair.

### FV-03 — nothing else changed

Operator exercises a representative slice of normal use after the envelope
consolidation and PermissionGate deletion. **Records:** any behavioural
difference at all. The expected result is none — this is a change nobody should
notice.

### Result template

```
FV-0N  PASS | BLOCKED
host:
build:
observed:
notes:
```
