# Allbert v1.4.0 Spine Enablers And Kernel Foundation

Foundational flagship: the kernel application and Pack contribution boundary.
The settings/action-spine enablers and three worked pack extractions prove that
flagship rather than competing with it, and the release is sequenced first
because every later release builds on the resulting boundary.

Constraining ADRs: **ADR 0046** (settings schema migration policy), **ADR 0065**
(central action param-contract enforcement) — both already Accepted. This
release applies ADR 0046's admission rule and keeps its runner deferred because
M0 found no eligible real consumer; it reconciles ADR 0065 against the current
shipped action catalog rather than assuming its already-shipped central
enforcement was partial. **One new ADR ships here — ADR 0098** (kernel
application, pack contract, and tier model), written and accepted for
implementation 2026-08-06 per the kernel-redo analysis §13.2 decision 10. It
amends ADR 0017 (plugin contract) and ADR 0031 (settings schema fragments and
authority) and supersedes neither. Its §7 carries the post-1.0 rule: v1.4 adds a
topology supplement while the v1.0 Tier-1/Tier-2 inventory remains binding.

Companion: `docs/plans/v1.4-request-flow.md`.

## Purpose

Land the spine changes that everything after 1.4 depends on, take the one large
mechanical cleanup that shares their blast radius, and land the kernel
foundation so that new capability code has somewhere correct to go.

**Why the kernel work merged here (operator decision 2026-08-06).** The
kernel-redo analysis was accepted and its foundation phase merged into this
release rather than becoming a separate one. The reason is measured, not
aesthetic: the param-contract reconciliation and envelope consolidation touch
the same generated action roster, and the analysis's own rationale for its
foundation release is that these passes should not be paid twice. M0 generates
and freezes that roster at build-start; historical counts are sizing evidence,
never the contract. One coordinated sweep, not three.

The second reason is sequencing. The releases immediately after this one build
new subsystems — Knowledge Stage 1 and Knowledge Central. If the pack pattern
does not exist when they start, they land in the monolith and have to be moved
later, which is exactly the coupling regrowth the analysis diagnoses. This
release therefore ships a **proven pack extraction**, not just the inversions.

1. **Current-catalog param-contract reconciliation.** ADR 0065's central Runner
   enforcement already shipped in v0.59. M0 regenerates the current static
   shipped-action roster and M2 closes any concrete drift it finds. If the
   roster is already complete, M2 records a no-op parity result rather than
   manufacturing a historical containment premise.
2. **PermissionGate facade retirement.** Param validation does not replace
   authorization. Direct callers move to `AllbertAssist.Security.authorize/2`
   while action-local Security checks, confirmation semantics, and denial
   behavior remain in place. The only intentional observable change is
   `decision.source: AllbertAssist.Security` rather than the retired facade.
3. **The action response envelope, consolidated.** Folded in deliberately — see
   the sequencing note below.
4. **Registry and pack-contract inversion.** A kernel-owned contribution
   contract makes shipped pack actions/settings/gates discoverable without a
   kernel list. The old hand-maintained action list is deleted only after the
   generated M0 roster, ordering, resolution, and exposure are proven identical.
5. **Settings and gate inversion, `apps/allbert_kernel`, and relocation.** M1.a
   creates the minimal kernel/composition application boundaries and Pack
   substrate. After dependency closure, M8 relocates Home/Paths, Security
   Central with `HttpPolicy`, and the remaining Capability plane into the
   existing kernel.
6. **Three proven pack extractions.** `notes_files`, then telegram and email.
   Not cleanup — the template the next two releases build against.
7. **A v1.4 topology supplement to the public-contract freeze.** The v1.0
   Tier-1/Tier-2 inventory remains authoritative and `release.v1` remains a hard
   stop. v1.4 records application ownership, pack contributions, and relocation
   hashes without reclassifying or removing a frozen public contract, and adds
   the compiled `AllbertAssist.Pack` descriptor as a new additive Tier-2
   contract. Declared Home packs reuse the frozen `allbert_plugin.json` schema/
   Validator through a data-only subset rather than inventing a new shape (LD4).

**Not built in this release:** the preflight gate and the release-sequence rules
(AGENTS.md Release Sequence) land in **v1.3.2**, not here. M0 refuses to open
implementation until their shipped/tagged state is proven. v1.4 inherits their
local preflight attestation, advisory compatibility probe, fixture-drift
registry, fail-closed change-scope selector, and `model_roles` work. v1.3.1 and
v1.3.2 are source-only, so v1.4 packaged FV is their first binary-carrier proof.
It includes v1.3.1's offline answering-head qualification, bounded Memory
full-build metadata, and paused-managed-due correction as well as v1.3.2's
model-role behavior and source/package provenance. Preflight remains source
tooling and is proved by the inherited source gate, not by a packaged operator
row. What
remains for v1.4 on the testing side is the deeper problem preflight does not
solve — absolute suite duration. Preflight makes failures *cheap to find*; it
does not make the authoritative aggregate shorter. If the aggregate still peaks
near its recorded 47.7 minutes, M4's test-hygiene work is where that is attacked,
informed by recorded metrics rather than impression. No intermediate v1.4 point
tag exists merely to divide this release by size: clean-SHA checkpoints and
rejoin evidence provide the rollback boundaries, and `v1.4.0` is the one product
tag.

## Locked Decisions

1. **The kernel foundation merges into this release (operator, 2026-08-06).**
   Not a separate release, because param-contract reconciliation, envelope
   consolidation, and the inversions share the same generated roster and the
   sweep must be paid once. Major rejoin points produce exact-clean-SHA evidence
   checkpoints with a named rollback, not product/source tags. `v1.4.0` remains
   one binary release and is not split merely because the implementation is
   large.

2. **Registry inversion is a provable no-op and establishes the pack contract
   (derived).** Historical measurements found 246 action modules using the macro
   and 248 declaring `exposure:`. M0 regenerates the real roster. The inversion
   derives from kernel-owned contribution metadata, preserves deterministic
   `modules/0,1`, `agent_modules/0,1`, internal partitions, and `resolve/1,2`
   behavior element-for-element, and fails closed on
   duplicate action names, pack IDs, setting owners, or gate owners. Kernel
   lists are deleted only after every shipped core and legacy-path pack has a
   contribution and the derived roster matches the frozen M0 roster.

3. **Relocation is not deferred (operator, 2026-08-06).** Deferring it was
   proposed and rejected: the releases immediately after this one build new
   subsystems, and without the kernel boundary in place they would land in the
   monolith and need moving later. Because module names are independent of
   application names on the BEAM, relocation itself is a pure file move. A
   dependency-closure milestone first inverts or relocates every forbidden
   dependency, then freezes content hashes. **M8 accepts zero content diff on
   any relocated module relative to that immediately preceding checkpoint.**
   A content change during M8 means something other than relocation happened.

4. **v1.0 contracts remain frozen; v1.4 adds topology evidence.** The post-1.0
   release model and ADR 0098 §7 agree: `release.v1` is a hard stop, Tier-2
   evolves additively only, and a Tier-1 change requires a major version plus an
   ADR. Closeout records a v1.4 topology supplement mapping the unchanged frozen
   symbols to their final OTP applications/packs and relocation hashes. It does
   not reclassify, replace, or waive the v1.0 inventory.

5. **The ADR 0046 runner remains deferred (operator, 2026-08-06).** M0 found no
   eligible real non-additive consumer, so the operator selected migration
   option A. v1.4 removes the runner, maintenance projection, migration FV, and
   migration DoD while retaining the kernel/Pack/settings-ownership work. A
   future release may admit the runner only with a real consumer that satisfies
   ADR 0046; ownership moves, fixtures, and active compatibility aliases do not.
6. **PermissionGate retires directly into Security Central (operator,
   2026-08-06).** Param validation is orthogonal to authorization. Every caller
   that authorizes continues to call Security at the same action-local point;
   policy vocabulary comes from `AllbertAssist.Security.Policy`, response
   mapping from `AllbertAssist.Runtime.Response.permission_status/1`, and an
   allowed-decision predicate remains local or moves to one canonical helper.
   `decision.source` intentionally becomes `AllbertAssist.Security`; all other
   authorization, confirmation, denial, and response semantics are preserved.

Numbering is local to this plan. Decisions 1, 3–6 carry the 2026-08-06 operator
direction; the remaining implementation consequences are binding unless a
readiness finding reopens them explicitly.

7. **Param-contract work reconciles the current catalog.** M0 establishes the
   generated denominator; M2 fixes any concrete gap or records complete parity.
   Historical roster containment is not an acceptance requirement.
8. **PermissionGate deletion begins only after red-first authorization
    characterization and M2 roster reconciliation.** It is not coupled to a
    claim that param validation grants permission.
9. **The envelope consolidation is generated by the existing macro**, with
   `defoverridable` for genuine outliers. No new abstraction layer, no new
   module.
10. **Envelope consolidation is behaviour-preserving.** Any site whose generated
   envelope would differ from its hand-rolled one is an outlier and keeps its
   override, recorded with the reason.
11. **Divergent primitives are not silently unified.** `truthy?/1` and
   `json_safe/1` each get an explicit decision about correct semantics before any
   consolidation, or are deferred with the reason recorded.
12. **This release is additive at the public contract throughout.**
    `release.v1` stays green as a hard stop at M0, after every milestone/named
    M1 phase, and at release—not merely at multi-milestone rejoins. The v1.4
    topology supplement carries every v1.0 obligation, adds ownership/hash
    evidence, and inventories the new compiled Pack descriptor as Tier 2. The
    declared tier remains a validated data-only subset of the frozen
    `allbert_plugin.json` contract. Module names are independent of application names
    on the BEAM, so inversion and relocation must not move, remove, or
    semantically change a frozen symbol.
    From M1.a1 onward, every numbered implementation milestone and named source
    checkpoint uses the request flow's adjacent tested-implementation `A` plus
    docs-only evidence `B` handoff and pushes the pair before its successor;
    dirty-tree metrics are never handoff evidence. Artifact-only R4a/R4b/R5
    phases remain external-evidence phases, and tracked remediation returns to
    a new source pair.
13. **Counts are generated evidence, not contracts.** M0 commits the action,
    pack, setting-fragment, gate-owner, and PermissionGate-caller rosters used by
    every later proof. Milestones cite roster digests and deltas rather than
    embedding a historical count as their denominator.
14. **Final action acceptance uses the closeout roster, not only the predecessor
    baseline.** M0 freezes the predecessor roster. Every v1.4 action addition,
    removal, or ownership move enters an append-only delta ledger with module,
    action id, pack, order token, exposure, param contract, Security placement,
    envelope owner, and focused-test owner. The final generated roster plus this
    reconciled ledger is the denominator for M14 and closeout.

## Security Posture

PermissionGate deletion retires a facade, not authorization. That is the
highest-risk caller migration in this release and is gated accordingly:

- M0 inventories every production caller and classifies authorization, policy
  vocabulary, response mapping, and allowed-decision usage;
- every authorization caller is characterized red-first at its existing
  action-local point, then moved to `AllbertAssist.Security.authorize/2`;
- `decision.source` is asserted to change to `AllbertAssist.Security`; every
  other decision field, confirmation path, denial reason, response status, and
  trace/audit event is asserted identical;
- the deletion milestone carries adversarial rows attempting to reach an action
  through every path the facade previously covered.

The envelope consolidation must not change any `permission_decision`,
`response_status`, or denial reason. Any difference is a defect, not an
improvement.

## Non-Goals

OAuth, MCP parity, and new network-hardening behavior (all v1.7). Knowledge
(v1.5/v1.6). Any new product feature. Any Tier-1 semantic break. Loading or
compiling code from declared/Home packs. A runtime settings migration engine,
maintenance projection, or automatic boot migration. Extracting the M0-rostered
non-extracted legacy-path plugins. Dead-code
removal not proven by M0's re-run and M4's production-reference analysis.

## Validation Design (churn guardrails, binding)

- All automated tests and release rehearsals use temporary Allbert Homes and
  never mutate a real `~/.allbert`.
- PermissionGate rows are red-first against the facade snapshot and green only
  after direct Security migration. They assert the deliberate `decision.source`
  delta and exact parity of all other decision, confirmation, response,
  audit/trace, and effect-blocking behavior. Param validation has its own tests
  and is never used as the authorization oracle.
- Envelope consolidation compares every rostered module's full maps and exposed
  serialization for success, denial, confirmation, invalid-param, domain-error,
  and exception paths. Representative sampling alone is insufficient.
- Pack tests prove component-row/`.rel`/raw-`.app`-reconciled
  `Application.load/1` (including already-loaded
  apps), permute diagnostic loaded-application order, and cover missing/
  duplicate/unknown contribution metadata, deterministic action resolution,
  component/`.rel`/`.app`/descriptor disagreement, `.app` digest drift,
  forbidden effective-env override, legacy compatibility scans,
  declared metadata without code loading,
  and preservation of every M0-rostered non-extracted legacy plugin.
- Relocation validation compares R2 hashes, module/public inventories, xref and
  compile dependency graphs, application startup, `priv` lookup, configuration,
  license/release assets, and package loading. A content change belongs before
  R2 or after M8, never inside the move.
- Real configured provider/endpoint validation is required for Telegram and
  email; `notes_files` uses a real disposable filesystem tree. Fakes remain
  automated-test fixtures only. External smokes are opt-in, run after preflight,
  and record endpoint/provider identity without secrets.
- Every gate/lane/partition run records the structured metrics required by
  `docs/developer/test-strategy.md`. Any executable byte change invalidates the
  candidate and re-enters the one-batch remediation cadence before the sole
  aggregate.

## Definition Of Done

1. **D1 — Entry and handoff evidence:** v1.3.1 and v1.3.2 are shipped/tagged;
   R0, R1, R2, R3, R4, R4a, R4b, and R5 identify exact clean SHAs/artifact
   generations, roster/hash/gate evidence, owners, rejoin status, and a bounded
   rollback/discard boundary; no intermediate tag exists merely to split v1.4
   by size.

   valid compiled descriptor and every surviving legacy plugin has one adapter;
   composition-host applications are explicitly classified and do not pretend
   to be packs; declared manifests remain data-only. Ordering, exact Registry

   typed `home_roots/0` policy is containment-validated and grants no authority;
   no kernel existence list remains.

   have an explicit disposition.

   gone; action-local `Security.authorize/2` checks and confirmation/effect
   boundaries remain; only the documented `decision.source` value changes.
