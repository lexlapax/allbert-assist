# Allbert v1.5.0 Knowledge Stage 1 — LLM Wiki Over Claims

Minor release carrying one flagship, per the release model. Stage 1 of the
Knowledge Central feature; Stage 2 is v1.6.

Originally slotted as a `1.6.x` point release. Corrected on 2026-07-30 after a
dependency analysis: Stage 1 shares no code and no dependency with the v1.7
connectivity line, so the number asserted a relationship that does not exist,
and Stage 1 is flagship-shaped — new subsystem, new CLI group, new settings
namespace, new tile, new operator guide. It is a minor.

The two stages stay separate rather than merging into one flagship because their
risk profiles differ sharply: Stage 1 is deterministic, zero-egress, no model,
no new permission class; Stage 2 is LLM calls, egress, untrusted third-party
documents, and injection containment. Merging would prove Stage 1's page model
inside Stage 2's blast radius, and the most likely thing to be wrong — the page
granularity constants — is exactly what Stage 1 exists to calibrate cheaply.

Constraining ADRs: **ADR 0094** (Knowledge Central and the derived wiki
projection), **ADR 0095** (schema authority and untrusted source ingestion — the
schema half is Stage 2; Stage 1 is bound only by its "no authority from derived
artifacts" posture). Companion: `docs/plans/v1.5-request-flow.md`.

Status: **planned — triad drafted 2026-07-30, readiness passes not yet run.**
No Locked Decision below is operator-signed. Build must not start until a
readiness pass signs the LDs and M0 records current-HEAD drift.

## Purpose

Ship the first browsable artifact Allbert has ever produced from its own
knowledge: a derived, interlinked markdown page graph over v1.3 kept claims that
an operator can open in any editor and read.

1. **A page graph, derived.** Concept, entity, and comparison pages generated
   from current kept claims, with frontmatter, provenance, and relative-markdown
   cross-references. Never an authority; rebuildable; deleting it loses nothing.
2. **Navigation that works in `vi`.** Backlinks written into each page as text
   and a human-navigable `index.md`, so the graph is traversable without an
   editor plugin, a viewer, or an index server.
3. **Deterministic lint.** Contradictions, orphans, unresolved links, stale
   pages, and under-populated pages found without a single model call, because
   bi-temporal claims with supersession make contradiction a computable
   property rather than a judgement.
4. **Edits that do not vanish.** A page the operator edits is detected by digest,
   never overwritten, and offered for promotion into a claim proposal or a
   connected-root note — so corrections land where they are versioned and
   survive the next rebuild.
5. **One new operator surface.** Workspace tile, `allbert knowledge` CLI group
   with TUI parity, and launch prompts. `knowledge.enabled` default false.

What this release deliberately is not: any use of a model, any egress, any
document ingest, any new source policy, any new permission class, and any new
database. Stage 1 is a projection over data v1.3 already owns.

## Locked Decisions

Numbering is local to this plan. None is operator-signed yet.

1. **Pages are a derived projection.** No confirmation for page authorship. The
   wiki is rebuildable in full at any time. (ADR 0094 §2)
2. **Storage split.** Derived pages, `index.md`, and the backlink index live
   under `<HOME>/projections/knowledge/`. Durable Knowledge state lives under
   `<HOME>/knowledge/`. Stage 1 creates the durable root but writes only
   promotion bookkeeping into it. (ADR 0094 §3)
3. **`<HOME>/knowledge/` is added to export inclusion.** The one portability
   change in this release. `projections/knowledge/` is excluded for free.
4. **Relative markdown links, not wikilinks.** Backlinks are written into each
   page as text. No proprietary format, no editor-specific feature. (ADR 0094 §4)
5. **No fourth database.** The page and backlink index is derived JSON beside
   `index.md`. The three-database one-writer contract is untouched. (ADR 0094 §5)
6. **One named writer owner** for the Knowledge projection, matching the Memory
   and Search projection pattern.
7. **Edit divergence never overwrites.** Digest per page; a diverged page is
   preserved and surfaced. Promotion offers exactly two typed destinations — a
   claim proposal through v1.3 review, or a connected-root note through the v0.65
   confirmation-gated path. No third authority concept. (ADR 0094 §6)
8. **Page granularity is a frozen constant, not a heuristic.** A page exists when
   its subject has at least `N` current kept claims or at least `M` inbound
   references. `N` and `M` are frozen at M6 calibration, not chosen at
   implementation time.
9. **Lint is deterministic.** Stage 1 performs no model call. Contradiction is
   defined as two current kept claims sharing subject and predicate with
   incompatible values.
10. **Stage 1 queries its own pages only.** The composite query across Memory,
    Search, and pages (ADR 0094 §9) is Stage 2 scope. Stage 1 must not
    pre-build it.
11. **Knowledge never enters prompt assembly.** Memory retrieval remains the sole
    prompt-time path and the prompt budget is unchanged.
12. **`knowledge.enabled` defaults false**, and the existing `search.enabled`
    true / `memory.consolidation.enabled` false asymmetry explanation is extended
    to cover all three wherever it appears.
13. **Latency and scale bounds are frozen at M6 and measured on both packaged
    hosts**, reported separately, neither averaged away — the LD 82 method from
    v1.3.

## Operator-Visible Win

The operator runs one command or clicks one tile and gets a folder of markdown
they can open in whatever they already use. Every page says what it derives from
and where to edit instead. Lint tells them where their own knowledge contradicts
itself — something no surface has ever told them before.

## Security Posture

Stage 1 introduces no new authority. Specifically:

- No new permission class. Rebuild and query resolve under existing Memory read
  authority; promotion resolves under the existing claim-proposal and note-write
  authorities.
- No egress. No model call. No network.
- Derived pages grant nothing; they are output, not input to any decision.
- Promotion is the only effectful path and it terminates in two existing
  confirmation-gated spines.
- Redaction: pages inherit whatever redaction the source claim already carries;
  Stage 1 must not widen disclosure. A page must never contain content a claim
  would have redacted.

## Non-Goals

Documents, ingest, any model call, egress, the synthesis cache, `sources/`
pages, `log.md`, the schema document, LLM-assisted lint, composite query,
knowledge-in-prompt, semantic or embedding retrieval, the guided persona,
multi-user wikis, and any editor-specific integration. All are Stage 2 or later.

## Validation Design (churn guardrails, binding)

- Lint rows are red-first: each lint class must fail against a seeded defect
  before it passes against a clean graph.
- Divergence rows use real filesystem writes, not mocked digests — the whole
  point is that any editor works.
- Redaction parity is adversarial: a claim with redacted content must not surface
  that content on a page under any page type.
- Latency uses the v1.3 `bench-v13-latency` harness extended with a `knowledge`
  consumer, so the method and metrics-store shape are shared, not reinvented.

## Definition Of Done

- A derived page graph builds from current kept claims, is idempotent, and is
  traversable by relative links and written backlinks with no editor, plugin, or
  viewer.
- `index.md` is human-navigable and distinct from `.graph.json`.
- Lint finds contradictions, orphans, unresolved links, stale pages, and
  under-populated pages with zero model calls.
- An operator edit is detected, never overwritten, and promotable into a claim
  proposal or a connected-root note; discard and keep-mine paths work.
- No page discloses content its source claim redacts.
- Forget of a contributing claim retires the derived page through the existing
  generation machinery.
- Export excludes `projections/knowledge/` and includes `<HOME>/knowledge/`;
  restore rebuilds pages from claims.
- Frozen granularity constants and dual-host latency bounds are recorded in the
  metrics store, per host, neither averaged away.
- Tile, CLI, and TUI reach parity; `knowledge.enabled` false is clean everywhere.
- `release.v15` composes the exact `release.v17` prefix and is green at one
  clean pushed SHA; `v1.5` is built, signed, published, tap-installed, and
  revalidated.
