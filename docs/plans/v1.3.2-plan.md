## Purpose

v1.3.2 is complete only when all four outcomes hold:

1. `mix allbert.test preflight` exists as one cheapest-first gate that
   completes under two minutes and can be made the mandatory predecessor of
   every expensive phase;
2. every recorded predecessor stop cause has a red-first row proving preflight
   catches its class;
3. `model_roles.fast|capable|thinking` resolve as an additive naming layer over
   the ADR 0088 catalog, with existing concrete purpose chains byte-for-byte
   unchanged; and
4. the accepted code is tagged source-only without creating artifacts or moving
   the packaged v1.3.0 release/tap.

### Why these two are together

They have nothing in common as features. They are together because they share
one property that nothing else in the profiling release has: **other releases
are blocked on them.**

- **preflight** is what makes v1.4's sweep over 249 action modules cheap to
  fail. v1.3 M9.b burned six authoritative release attempts, none stopped by a
  product regression; every one was cheap, deterministic, repo-wide, and ran
  late or was not in a gate at all. Landing preflight *before* the largest
  mechanical sweep on the ladder is the entire point.
- **`model_roles`** is a hard dependency of Knowledge Central (v1.6 ingest uses
  `model_roles.capable`) and the consumer that makes hosted-provider OAuth
  meaningful (v1.7).

Shipping them as one small source-only tag costs one release cycle and unblocks
four.

## Locked decisions

1. **Source-only, `[skip-artifacts]`, v1.3.1's precedent.** The source version
   advances to 1.3.2; the installed product line remains v1.3.0 until v1.4
   packages the accumulated source changes. Consequence stated plainly: an
   operator cannot use `model_roles` from a packaged build until v1.4.
2. **preflight is tooling, not authority.** It gates when expensive work may
   start. It grants nothing, denies nothing at runtime, and has no ADR because
   it decides no boundary.
3. **This release ships the resolution layer only.** `model_roles.*` resolve;
   nothing *proposes* a remap. The suggestion-driven remap path, its allowlist
   entry, and the egress-class guard (same provider/endpoint/locality) stay in
   v1.8 with the rest of ADR 0090's confirmed-customization machinery. Landing
   resolution early is additive; landing the remap path early would ship half of
   an authority boundary.
4. **Nil-default, concrete-profile-only.** Role mappings accept concrete
   profiles only, so cycles are impossible. Unconfigured or disabled roles skip
   with a diagnostic rather than falling back silently. Resolution retains both
   the requested role and the concrete profile so a later consumer can report
   which it asked for.
5. **Existing behavior is byte-for-byte unchanged.** Purpose keys that name
   concrete profiles today keep resolving exactly as they do. This is provable
   and must be proved, not asserted.
6. **preflight dogfoods itself.** This release runs its own preflight before its
   own expensive phases. A gate that has never gated anything is not evidence.
7. **v1.3.1's temporary bridge retires here.** v1.3.1 M0 ran a named
   constituent bundle precisely because `preflight` did not exist. Once
   red-first rows prove equivalence, the bridge is removed rather than left as a
   parallel convention.
8. **No aggregate per fix.** Focused owners per milestone; the bounded
   `release.v132` delta once; exactly one `mix allbert.test release` aggregate
   at the final rejoin.

### M1 — Executable preflight and scope selection

`[code]` `[gate]`

Implement one cheapest-first `mix allbert.test preflight`: warnings-as-errors
compile on the pinned production pair, format/whitespace, docs,
registry/param contract, inventory/tag/manifest, fixture drift, and lane checks.
The local gate runs warm-cache on pinned Elixir 1.19.5/OTP 29.0.x **in under two
minutes**. A separate advisory probe runs Elixir 1.20.2/OTP 29.0.x; it is
neither in the local budget nor a public support promise.

Emit and validate an attestation over HEAD, worktree state, lockfile, and
gate-definition fingerprints; expensive gates fail on missing or stale
attestations. Add the central fixture-drift registry and executable
`mix allbert.test scope --base <sha>`; unknown paths fail closed to the shared
spine/full aggregate.

**The recorded stop causes are enumerated, not left to interpretation.** The
canonical list is the seven-row table in `docs/developer/test-strategy.md`
§ "Release Sequence And Re-Run Scope", which records each v1.3 M9.b attempt by
SHA, what stopped it, and its class. It is cited rather than copied so the two
cannot drift. Every row maps to the preflight check that must catch it, and each
mapping needs one red-first row:

| Recorded attempt | Class | Catching preflight check |
| --- | --- | --- |
| cumulative 1 (`42adfef3`) | document/inventory | docs gate + inventory/manifest |
| authoritative 1 (`70b9bbf8`) | registry consistency | registry/param-contract check |
| authoritative 2 (`b9f60352`) | fixture drift | central fixture-drift registry |
| authoritative 3 (`a86d721c`) | coverage inventory | inventory/tag/manifest reconciliation |
| authoritative 4 (`10f392de`) | test harness | lane classification check |
| authoritative 5 (`34c7452f`) | fixture drift | central fixture-drift registry |
| attempt 6 (`e9a39696`) | compile check | advisory Elixir 1.20.2/OTP 29.0.x probe |

Two rows share a class, so six distinct checks cover seven attempts. The last
row is the reason the advisory second-version probe exists at all: nine compiler
warnings under a second Elixir version stopped an authoritative attempt and were
surfaced only from pasted terminal output.

Acceptance: each of the seven recorded attempts has a red-first row proving its
catching check fails on a reintroduction of that class; the pinned-pair run
completes under two minutes on the reference host with the number recorded from
the metrics store, not from recollection; scope classification is deterministic
and fails closed on unknown paths; no expensive phase starts with a red or stale
preflight; and v1.3.1's constituent bridge is removed once equivalence is proven.

### M2 — Nil-default model roles

`[code]` `[docs]`

Implement `role:fast|capable|thinking` as nil-default fragments plus
`Settings.Models` alias resolution. Purpose keys may reference `role:fast`
without changing existing concrete values. Role mappings accept **concrete
profiles only**, so cycles are impossible. Unconfigured or disabled roles skip
with a diagnostic. Resolution retains both the requested role and the resolved
concrete profile.

Explicitly **not** in this release (LD3): any path by which a suggestion, card,
or automated process proposes a remap; the customization-allowlist entry for
`model_roles.*.profile`; and the same provider/endpoint/locality egress guard.
Those are one authority boundary and ship whole in v1.8.

Acceptance: nil, disabled, cycle-attempt, and out-of-boundary rows all pass;
**existing concrete purpose chains resolve byte-for-byte unchanged**, proven by
a comparison row rather than asserted; the chooser renders roles without
implying they are configured; operator documentation states that setting a role
changes nothing until a purpose key references it.

## Explicitly out of scope

- Any profiling, usage-event, distill, suggestion, or confirmed-customization
  work. That is v1.8 and stays whole there.
- The suggestion-driven role-remap path and its egress guard (LD3).
- Kernel inversions, param-contract enforcement, PermissionGate deletion, and
  the migration runner. Those are v1.4.
- Making preflight part of CI or of any aggregate. It is the predecessor of
  expensive phases, not a phase inside one.
- Raising or changing any shipped default model profile.
