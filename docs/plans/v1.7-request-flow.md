## §A — OAuth authorization (operator-initiated, always)

```
operator: allbert admin oauth authorize --provider google --consumer email
  |            (or the equivalent web/TUI action — never model, channel, schedule)
  v
:oauth_authorize action  (registered, Registry -> Runner)
  |
  +-- Security.Policy decision                         <- normal permission class
  +-- generate PKCE verifier/challenge + random `state`
  +-- bind EPHEMERAL LOOPBACK listener                 <- LD 13
  +-- open provider consent URL in the operator's browser
  |
  v  operator approves at the provider
  |
  +-- callback received on loopback
  |     `state` mismatch  -> reject, tear down, no token exchange
  |     timeout exceeded  -> fail closed, tear down
  +-- exchange code + verifier for tokens
  +-- store refresh token in tier vault                <- LD 12
  +-- record granted scopes as DIAGNOSTIC ONLY         <- LD 11
  +-- tear down listener                               <- always, all exits
  v
{:ok, %{provider: :google, consumer: :email, scopes_recorded: [...], expires_at: ...}}
```

**The listener is torn down on every exit** — success, `state` mismatch, timeout,
exchange failure, and operator abort. There is no path that leaves it bound.

**Failure modes**

| Condition | Outcome |
| --- | --- |
| Policy denies | No listener bound, no browser opened, no exchange |
| `state` mismatch | Callback rejected; listener torn down; no exchange attempted |
| Timeout | Fail closed; listener torn down; grant not recorded |
| Exchange fails | No partial grant recorded; operator sees the provider error |
| Operator aborts at provider | Listener torn down on timeout; no grant |

## §B — Token use and refresh

```
consumer needs a call (email fetch, model request)
  v
OAuth.Grant lookup
  +-- access token cached and unexpired -> use
  +-- expired -> refresh with the vault refresh token
  |     success -> cache new access token, proceed
  |     revoked/expired grant -> §C
  v
consumer proceeds under its OWN permission class
```

**Binding (LD 11):** the granted scopes are never consulted to decide whether
Allbert may act. The consumer's normal permission decision governs. A grant with
broad scopes and a grant with minimal scopes produce identical Allbert authority.

## §C — Revocation and expiry

```
refresh fails: invalid_grant / revoked / expired
  v
mark grant NEEDS_REAUTHORIZATION      <- typed, not a generic auth error
  +-- surface provider + consumer in doctor and settings
  +-- NO automatic re-authorization                     <- LD 14
  +-- consumer operation fails with the typed reason
```

**Mid-batch revocation.** A long-running consumer — a fan-out, or a v1.6
Knowledge ingest run — halts at a resumable boundary rather than failing every
remaining item individually and burning the batch.

## §E — Network hardening

### Private-address table consolidation

```
BEFORE                                  AFTER
external/http_policy.ex:164     \
voice/provider_http.ex:401       >  ->  one owner
settings/model_doctor.ex:496    /
```

**Ordered and binding:**

1. M0 confirms all three copies are currently in sync.
2. The merged table is run against every input all three previously handled.
3. Only after behaviour is proven identical are the copies removed.

Consolidation must not widen what is reachable. A merge that accidentally drops a
range is an SSRF hole, which is precisely the risk three copies already carry —
patching one leaves two.

### Free-form provider URLs

```
operator: set providers.local_ollama.endpoint_url = http://192.168.1.50:11434
  v
external-network approval path                          <- LD 18
  +-- private/LAN address? STILL an egress decision      no "local" exemption
  +-- operator confirms
  v
endpoint usable
```

### Non-local bind

```
public surface bind
  +-- public.bind.non_local_allowed = false (default) -> loopback only
  +-- true -> explicit operator decision, recorded
```

The OAuth callback listener obeys this same policy. There is no OAuth exception.

## §F — Security eval rows (`:v17`, gate-bound, behavioral)

| Row | Assertion |
| --- | --- |
| `oauth-scope-not-authority-001` | A grant with broad provider scopes does not widen any Allbert permission decision |
| `oauth-refresh-token-never-exported-001` | Refresh tokens absent from export, backup, trace, log, audit body, and model context |
| `oauth-callback-loopback-only-001` | The listener binds loopback only and is unreachable from a non-loopback interface |
| `oauth-callback-state-matched-001` | A callback with a mismatched `state` is rejected without token exchange |
| `oauth-callback-torn-down-001` | The listener is torn down on success, mismatch, timeout, and exchange failure |
| `oauth-no-autonomous-authorize-001` | Model output, a channel message, and a schedule each fail to initiate an OAuth flow |
| `oauth-revoked-fails-closed-001` | A revoked grant yields a typed needs-re-authorization state, not a retry loop |
| `oauth-midbatch-resumable-001` | Revocation mid-batch halts at a resumable boundary |
| `oauth-shared-substrate-001` | Both consumers resolve through one implementation (shared contract test) |
| `net-private-table-parity-001` | The consolidated table matches all three prior copies on every previously handled input |
| `net-freeform-url-approval-001` | A LAN or loopback provider URL is still an egress decision |
| `net-bind-default-loopback-001` | Public surfaces bind loopback unless explicitly allowed |

# authorize an OAuth-only mailbox
allbert admin oauth authorize --provider microsoft --consumer email
# PASS: browser opens; after approval, grant recorded; listener gone

allbert serve --status

## §G — Focused operator validation (FV, real providers)

Fakes are automated-test fixtures only. These rows use configured real endpoints.

### FV-01 — real OAuth-only mailbox

Operator authorizes a genuine Gmail or Microsoft OAuth-only mailbox and sends and
receives. **Records:** provider, whether consent was understandable, time to
first successful fetch.

### FV-02 — real subscription LLM provider

Operator authorizes a Claude, OpenAI, or Gemini subscription plan and completes a
chat turn through it. **Records:** provider, whether the plan was used rather
than a metered key.

### FV-03 — revocation, live

Operator revokes the grant **at the provider**, then exercises the consumer.
**Records:** whether the resulting state named the provider and consumer, and
whether re-authorization was obvious. Not simulated with a synthetic 401.

### FV-04 — LAN model endpoint

Operator points Allbert at Ollama on another machine through the approval path.
**Records:** whether approval was required and whether the endpoint then worked.
