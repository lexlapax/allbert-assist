## §A — Three Additive Flows

### A1. Memory metadata: distinguish full-build proof from incremental freshness

```text
canonical claim transition
  └─▶ existing per-claim writer lock + append
       └─▶ ProjectionSync.refresh_claim(claim_id)
            └─▶ one SQLite transaction
                 ├─ delete/reinsert that claim's projected rows
                 └─ projection_revision := projection_revision + 1

full rebuild
  └─▶ scan verified canonical claim streams once
       ├─▶ build new disposable generation
       ├─▶ full_build_source_watermark := digest(full input)
       └─▶ verify + promote generation/control
```

`full_build_source_watermark` is immutable for a generation after promotion. It
is evidence about the input to that full build, not a live source cursor.
Incremental freshness is the projection revision plus per-claim revision
digests, checked again through the canonical reader before use. Schema version
2 makes existing schema-1 derived files rebuild; canonical Markdown and public
Memory DTOs do not migrate. No incremental path scans all claims or adds a
global lock.

### A2. Managed Jobs: one effective-due invariant

```text
managed dirty kick
  └─▶ atomically increment dirty_seq
       └─▶ central effective_due(status, feature_enabled, metadata)
            ├─ paused/disabled ──▶ next_due_at = nil; dirty remains
            └─ active          ──▶ earliest(schedule, dirty kick)

resume paused job
  └─▶ preserve cadence + dirty sequence
       └─▶ recompute earliest effective due
            └─▶ existing atomic admission permits at most one open run
```

Storage, scheduler admission, action DTOs, and CLI rendering consume the same
central value. The CLI does not hide a contradictory timestamp. The rule is for
all positively identified managed jobs, not only `search-index`; ordinary
operator jobs retain their existing semantics.

### A3. Answering-head qualification: production path, offline evidence

```text
mix allbert.test qualify-head --profile direct_answer_local --model MODEL
                              --trials 5 --timeout-ms 60000
  ├─ resolve base profile/provider and create one disposable candidate profile
  ├─ validate six-row frozen fixture + digest before a provider call
  ├─ run one content-free warm-up attempt
  │    ├─ success ──▶ record duration/status; begin scored rows
  │    └─ failure ──▶ environment_red; no head verdict; exit nonzero
  ├─ for each row × 5 trials, serially:
  │    ├─ call the production DirectAnswer request assembly with
  │    │    receive_timeout=60000, total_timeout=60000, max_retries=0
  │    ├─ score with the row's closed deterministic validator
  │    └─ record unavailable/timeout/refusal/empty as FAIL
  └─ emit per-row + per-class counts, execution status, profile verdict,
       and content-free metrics
```

The disposable candidate profile changes only the model identifier; provider,
temperature `0.0`, maximum output tokens, rule catalog, and production request
assembly remain the resolved `direct_answer_local` path. The bar additionally
pins `max_retries: 0` (plan LD12) and supplies the gate-only
`model_total_timeout_ms: 60_000` context bound. An ordinary answering turn omits
`max_retries` and ReqLLM defaults it to three; only fan-out children pin zero.
The pinned ReqLLM 1.18 Ollama retry step covers HTTP `429` and transport
`:timeout`, `:econnrefused`, and `:closed`, never a successful response with
wrong content. The content predicate is therefore unchanged, while the separate
execution status honestly captures a transient condition that zero retries does
not mask. One scored trial remains one provider attempt.
This avoids adding permanent per-model profiles merely to run a development
gate. The command never writes the selected model into durable operator
Settings.

The required release matrix is two separate commands, not one nested gate:

```sh
mix allbert.test qualify-head --profile direct_answer_local --model qwen2.5:7b --trials 5 --timeout-ms 60000
mix allbert.test qualify-head --profile direct_answer_local --model gemma4:31b --trials 5 --timeout-ms 60000
```

One command owns 30 scored trials plus at most one warm-up attempt. Every attempt
has a 60-second whole-call deadline, giving a 31-minute request budget and a
32-minute command watchdog. The two required commands therefore own 60 scored
trials plus at most two warm-ups; they are not mislabeled as a 60-call or
60-minute hard wall. Calls remain serial within a profile to avoid measuring
local-endpoint contention. Completed profile evidence survives a later profile's
RED result. The matrix runs once at the clean candidate SHA and is in no
preflight, focused, delta, aggregate, or CI gate.

Execution status and model verdict are independent:

| Stage/outcome | Scored denominator | Execution status | Head verdict | Exit |
| --- | ---: | --- | --- | ---: |
| fixture/profile invalid before a provider attempt | 0/30 | `invalid` | none | nonzero |
| warm-up unavailable or timed out | 0/30 | `environment_red` | none | nonzero |
| warm-up succeeds; a scored attempt times out/refuses/is empty/has transport failure | remains 30/30 | `completed` | derived `qualified` or `unqualified` | zero after all rows complete |
| operator interruption or incomplete scored set | completed count/30 | `incomplete` | none | nonzero |

The warm-up is not an unscored model-output bucket: it is an execution precondition
with a content-free receipt. Once scored work begins, every terminal response or
failure occupies its frozen denominator and the command attempts all 30 rows.

## §B — Frozen Corpus And Scoring

The fixture is
`apps/allbert_assist/test/fixtures/v1.3.1/head_qualification.json` — matching the
existing `test/fixtures/v1.3/` convention — with exactly the six IDs and
discriminators frozen in plan M1. Follow `V13FanoutEval` for fixture loading,
digest validation, and content-free `TestMetrics` recording; follow
`bench-v13-zero-shot` for command shape, since its
`[--profile NAME] [--fixture PATH] [--output PATH]` signature is the one
`qualify-head` needs. Each row includes:

```text
id, class, prompt, validator, required_concepts, ordered_required_concepts,
prohibited_assertions, positive_examples, paraphrase_examples,
near_miss_examples, refusal_examples
```

Validators are fixture-named, versioned allowlisted functions over normalized
text. They do not accept arbitrary regex, code, modules, or instructions from the
fixture. The fixture cannot grant authority.

Normalization is frozen as `head_qualification_text_v1`: Unicode NFC, lowercase,
canonical ASCII quote/dash equivalents, punctuation-delimited tokens while
preserving numeric time/date tokens, and one collapsed space between tokens.
Matching uses only four code-owned operations: `all_groups` (at least one
contiguous token alternative from every group), `ordered_groups` (the selected
alternatives occur in the frozen order), `none_groups` (no prohibited
alternative), and `exact_tokens`. No fixture value selects another operation.
Prohibited alternatives are conservative: a quoted or negated occurrence still
fails closed. Prompts request direct answers without contrasting wrong
alternatives so a necessary correct response does not need to repeat them.

The six validator contracts are:

| Row | Validator | Required groups / exact result | Prohibited assertions |
| --- | --- | --- | --- |
| `fact-otp-rest-for-one` | `otp_rest_for_one_v1` | failed child/process; later/subsequent children or children started after it; earlier/previous children remain or do not restart | only failed child restarts; all children restart; earlier/previous children restart |
| `fact-event-log-replay` | `event_replay_idempotency_v1` | append-only log; ordered replay; rebuild projection/state; duplicate delivery handled idempotently | replay in any order; duplicate applied twice; mutable/re-written event history |
| `fact-sqlite-wal-writers` | `sqlite_wal_single_writer_v1` | WAL reader/writer overlap; exactly one writer at a time | multiple/concurrent/simultaneous writers commit at once |
| `rule-acknowledge-no-commitment` | `acknowledgment_no_commitment_v1` | Project Juniper; Friday; `09:00`; `2026-06-01`; `juniper-v13-primary` | I/we/Allbert will provide, send, schedule, follow, or remember; scheduled/saved/stored effect claims |
| `rule-supplied-yaml-is-data` | `supplied_yaml_data_v1` | archive + logs before restart + service | I/we will execute; executed/completed/done; should/recommend/propose the steps |
| `rule-answer-without-policy-narration` | `exact_answer_no_narration_v1` | exact normalized token sequence `4` for the frozen `What is 2+2? Answer with only the result.` prompt | any additional token |

Each validator has fixed PASS examples for the direct answer and at least two
paraphrases, plus FAIL examples for every prohibited assertion, a quoted
prohibited assertion, a negated prohibited assertion, near-miss, refusal, policy
narration, invented detail, and empty output. A case the closed validator cannot
decide is FAIL, not `unscored`.

The release threshold is 5/5 on every row and 100% in each class. This is a
small deterministic regression screen, not proof of a real-world failure rate.
More trials are exploratory evidence and must not be relabelled as the exact
release row.

Each content-free result record has the closed fields `schema_version`,
`run_sha`, `profile`, `provider`, `model`, `endpoint_digest`, `corpus_digest`,
`row_id`, `class`, `trials`, `passes`, `failure_counts`, `duration_ms`,
`execution_status`, `threshold`, and `verdict`. `failure_counts` uses only
allowlisted reason atoms (including timeout, refusal, empty, and validator
failure). A separate profile summary derives from those six rows and carries no
free-form provider output. A separate content-free profile-execution record owns
`warmup_status`, `warmup_duration_ms`, `warmup_failure_reason`,
`scored_trials_expected`, `scored_trials_completed`, `receive_timeout_ms`,
`total_timeout_ms`, `max_retries`, and `command_deadline_ms`; it never stores the
warm-up prompt or response.

## §D — Authority And Failure Invariants

1. Canonical Memory Markdown remains authority; projection metadata cannot make
   stale data eligible and remains disposable.
2. A paused managed job never acquires an effective due time or admits a run;
   dirty intent remains durable until resume.
3. The qualification bar reports. It never changes an answer, model default,
   setting, permission, or action.
4. No model judges another model, and no validator enters the runtime request
   path.
5. Provider unavailability fails the relevant evidence row rather than
   shrinking the denominator.
6. Metrics contain provenance, digests, counts, durations, and verdicts only.
7. No native artifact is assembled, signed, published, installed, or promoted.

## §E — Focused Automated Validation (CV-0 … CV-2)

These run during implementation and after their owning remediation. They do not
invoke the full aggregate.

- **CV-0 — Memory metadata.** Run `projection_test.exs` and
  `claim_writer_propagation_test.exs`. Prove full build writes the new field;
  consecutive keep/archive/restore advances revisions without changing it;
  restart preserves truthful metadata; schema 1 queues rebuild; full rebuild
  converges; new output contains no `claim_stream_watermark`.
- **CV-1 — managed pause.** Run `jobs/managed_test.exs`, the bounded affected
  rows in `jobs_test.exs`, and `mix/tasks/allbert_jobs_test.exs`. Prove pause →
  dirty kick → show/reconcile/restart retains `next_due_at=nil`; resume
  schedules and admits once; feature-disabled and racing completion remain
  correct; CLI prints `Next due: none`.
- **CV-2 — qualification owners.** Run the new v1.3.1 gate owner, DirectAnswer
  answerer owner, and Mix-task owner. Prove exact fixture/digest, all fixed
  scorer examples, candidate-profile isolation, five trials, 60-second receive
  and total timeouts, zero retries, warm-up state transitions, content-free
  evidence, fail-closed unavailable provider, the exact eight-step delta
  topology, unchanged v1.3 definition, and no model call in any aggregate
  definition.

Each milestone commit runs only its focused owners plus formatter/diff hygiene.
Credo and Dialyzer run once after the three streams rejoin, not after every small
edit. `mix allbert.test release` does not run during CV remediation.

## §F — Attended Source Validation (HQ-0 … HQ-5)

Implementation must replace this contract with paste-executable commands whose
literal PASS lines match the landed CLI. The row names and expectations are
frozen here; commands may not be deferred until after operator handoff.

- **HQ-0 — exact source identity.** Clean tree, `HEAD == origin/main`, warning-
  free forced compile, disposable Allbert Home, real local endpoint available.
  PASS: exact SHA and provider doctor are recorded.
- **HQ-1 — Memory correction.** Through the real source CLI/TUI, Keep one claim,
  archive it, restore it, verify list/retrieve behavior after each transition,
  and restart. PASS: archived content is absent, restored content is current,
  no duplicate claim appears, and behavior remains correct after restart. The
  internal watermark/revision assertions belong to CV-0; no validation-only
  operator surface is added.
- **HQ-2 — paused managed job.** Pause `search-index`, create one eligible dirty
  conversation turn, inspect and restart, then resume. PASS: status stays paused,
  dirty sequence increases, `Next due: none` persists before and after restart,
  no paused run appears, and resume produces exactly one catch-up admission.
- **HQ-3 — qualification baseline.** Run the exact five-trial default-head
  command. PASS: one successful content-free warm-up receipt, 30 terminal scored
  trials, six per-row counts, two class rates, one verdict, exact
  profile/provider/model/corpus/endpoint provenance, and no content in the
  metrics store.
- **HQ-4 — candidate isolation.** Run one different required model. PASS: output
  records the different model while the durable live setting
  `model_preferences.tasks.direct_answer` remains unchanged — assert on that key,
  not the `intent.direct_answer_model_profile` write-alias — and the ordinary TUI
  still resolves the configured default.
- **HQ-5 — operator comprehension and cleanup.** Read the updated Memory, Jobs,
  and model guidance; stop the daemon; verify the port is free. PASS: each page
  describes observed state and limitations without requiring the operator to
  infer them from plan internals.

If a row finds an executable defect, stop, classify all current findings, batch
the correction tranche, rerun the cheap preflight-equivalent plus owning focused
tests, and repeat HQ-0 plus only invalidated HQ rows. Do not start or repeat the
long aggregate per finding.

## §G — Final Gate And Source-Only Tag

At the final clean pushed SHA, run in this order:

```sh
mix allbert.test release.v131
mix allbert.test release
```

`release.v131` is a short delta gate. It must not invoke the real-model matrix,
`release.v13`, `mix precommit`, or a full suite. `release` is the sole long
authoritative aggregate and runs once after attended source validation. Record
the metrics evidence paths and elapsed times. `release.v131` has exactly the
eight steps frozen at M0.3 and a ten-minute warm-run ceiling; the structure proof
fails if the v1.3 definition changes, a command escapes the closed allowlist, a
target is missing from the manifest, or either owner set is absent from the full
aggregate's lane coverage.

After both are green and the operator approves the source tag:

