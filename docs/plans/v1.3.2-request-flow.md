## Inputs And Non-Goals

- v1.3.1 shipped source-only and is archived; its M0 constituent bundle is the
  thing M1 replaces.
- Neither flow adds an authority boundary. preflight decides *when expensive
  work may start*; role resolution decides *which concrete profile a name
  resolves to*. Neither grants, denies, or escalates anything at runtime.
- No artifact is built, signed, published, installed, or promoted.
- No suggestion, card, or automated process may propose a role remap in this
  release; that path is one whole authority boundary and ships in v1.8.

## §A — Preflight And Scope Selection

```text
any expensive phase or remediation
  └─▶ mix allbert.test preflight            (cheapest-first, < 2 min, pinned pair)
       ├─ forced warnings-as-errors compile (Elixir 1.19.5 / OTP 29.0.1)
       ├─ format + git diff --check
       ├─ docs gate (including archived Markdown links)
       ├─ registry + param-contract consistency
       ├─ owner-CWD test load (zero tests executed)
       ├─ inventory --check-tags
       ├─ inventory --check-manifest
       ├─ fixture-contract sentinel registry
       └─▶ exact-state attestation
            │
            ├─ red or stale ──▶ expensive phase REFUSED
            └─ green ────────▶ phase may start

  (separate, advisory) immutable Elixir 1.20.2 / OTP 29 compatibility probe
       — not in the two-minute budget, not a public support promise
```

```text
mix allbert.test scope --base <sha>
  ├─ classify changed paths by the test-strategy change-class table
  ├─ known class ──▶ the minimum required re-run set
  └─ unknown path ─▶ FAIL CLOSED to the shared spine / full aggregate
```

Before a run starts, any previous green attestation is invalidated. A successful
run atomically writes `.test_metrics/preflight-attestation.json`:

```text
schema_version, canonical_repo_root, head_sha,
worktree_content_digest, mix_lock_digest, gate_definition_digest,
elixir_version, otp_version, checks[], total_wall_ms, completed_at, status
```

`worktree_content_digest` covers tracked, staged, unstaged, and nonignored
untracked bytes, not merely a clean/dirty boolean. Dirty development trees may
produce exact attestations; release evidence additionally requires `clean=true`.
Every centrally classified expensive command validates the exact state before
spawning a subprocess and refuses a missing, red, or stale attestation. The
guarded set is `prepush`, high-coverage `fast-local`, `serial-core`, every
`release.v*`, `release`, external smokes, and real-provider/benchmark gates.
Focused, docs, inventory, scope, and preflight itself are unguarded.

The compatibility probe uses:

```text
elixir:1.20.2-otp-29@sha256:7ee41a9a8a8427dbd40c9133ee5b9047f585b58db4968fd675fbcd9498e3b22e
```

It runs after dependency, gate, or compiler-facing changes and at the final
clean rejoin. It does not run after documentation-only or unrelated focused
remediation. `mix allbert.test compatibility` encapsulates the Docker command,
keeps Linux build output outside the host source/build paths, verifies the
observed Elixir/OTP tuple, forces a warnings-as-errors compile, and records an
exact-SHA compatibility attestation.

`scope --base` validates that the base exists and is an ancestor; an invalid or
shallow base exits nonzero. It classifies committed, staged, unstaged, and
nonignored-untracked paths, both names of a rename, and the old name of a
deletion. Exact path/prefix matches are unioned and always widen. Unknown paths
produce a valid result with `aggregate_required=true` plus a diagnostic. Stable
human and JSON output report the base, merge base, changed paths, matched rules,
selected focused/lane/gate work, and aggregate obligation. Scope never runs a
test or waives the active release gate.

## §B — Role Resolution

```text
purpose key (model_preferences.tasks.*)
  │
  ├─ names a concrete profile ──▶ resolves exactly as today (unchanged)
  │
  └─ names role:fast|capable|thinking
        └─▶ model_roles.<role>.profile   (nil by default)
             ├─ nil ──▶ diagnostic, CONTINUE existing chain
             └─ concrete profile ─▶ Settings.Models (central resolver)
                  ├─ missing/provider-disabled/incapable ─▶ diagnostic, CONTINUE
                  └─ usable ─▶ role metadata retains
                       {requested_reference, requested_role, resolved_profile}
```

Role mappings accept **concrete profiles only** — a `role:*` mapping is rejected
at write time rather than discovered as a runtime cycle. Either write order is
valid: a task chain may hold an unconfigured role. Expansion deduplicates by
resolved physical profile after alias expansion while preserving first
occurrence. Concrete `fast` remains a profile and `role:fast` remains a role;
they never collide. `for/2` and `candidates_for/2` use the same expansion path.
No parallel resolver is introduced.

v1.3.2 integrates roles only for the `model_preferences.tasks.*` chains owned by
`Settings.Models`. Scalar coding/router selectors that currently bypass it are
not claimed; later consumers must enter through this same resolver.

**Nothing proposes a remap in this release.** The write path is ordinary
operator settings authority. The suggestion-driven remap, its allowlist entry,
and the same provider/endpoint/locality egress guard ship together in v1.8,
because shipping half an authority boundary is worse than shipping none.

## §D — Authority And Failure Invariants

1. preflight grants and denies nothing at runtime; it gates only when expensive
   work may start.
2. A missing or stale attestation refuses the expensive phase. Green-from-a-
   different-state is not reusable.
3. `scope --base` fails **closed**: an unclassifiable path escalates to the
   shared spine or full aggregate, never to a narrower set.
4. An unconfigured role or an unusable mapped profile records a diagnostic and
   continues the operator's existing chain. It never invents a fallback.
5. A role may not name a role. The write is rejected; no runtime cycle path
   exists.
6. Purpose keys naming concrete profiles resolve byte-for-byte as they do today.
7. Nothing in this release proposes, applies, or confirms a role remap.
8. No artifact is assembled, signed, published, installed, or promoted.

## §E — Focused Automated Validation (CV-0 … CV-2)

Run during implementation and after their owning remediation. They do not invoke
the aggregate.

- **CV-0 — preflight composition and budget.** Every named check runs in the
  frozen order; owner-CWD loading, `--check-tags`, and `--check-manifest` are
  separately reported and structure-tested; the
  pinned-pair run completes under two minutes with the duration recorded from
  the metrics store; the advisory probe is excluded from that budget; a red
  check fails the command non-zero.
- **CV-1 — stop-cause coverage.** One red-first row per recorded attempt in the
  test-strategy table: reintroduce that class and prove the mapped check fails.
  Six distinct checks cover seven attempts (two share a class). Also: a stale
  exact-state attestation refuses an expensive phase before subprocess launch;
  the fixture registry rejects invalid/duplicate sentinels; and `scope --base`
  covers renames, deletions, dirty/untracked state, invalid bases, and unknown
  fail-closed classification.
- **CV-2 — role resolution.** Nil, missing-profile, provider-disabled,
  incapable-profile, role-as-mapping rejection, write-order, namespace
  collision, post-expansion deduplication, and out-of-boundary rows; role
  provenance retained without changing concrete result maps; and
  the parity row proving existing concrete purpose chains are **byte-for-byte**
  unchanged. The shared catalog DTO and CLI/TUI/Web renderers prove all roles
  show `unconfigured` until assigned.
- **CV-3 — documentation and source identity.** The docs gate covers active and
  archived local Markdown links, including a red-first broken-archive-link row;
  all five source-version artifacts agree; package/latest/tap identity remains
  v1.3.0.

## §F — Attended Source Validation (SV-0 … SV-4)

Implementation must replace this contract with paste-executable commands whose
literal PASS lines match the landed CLI. Row names and expectations are frozen
here. Disposable Homes only; provider/credential failure is `BLOCKED`.

- **SV-0 — exact source identity.** Clean tree, `HEAD == origin/main`,
  warning-free forced compile, disposable Home. PASS: exact SHA recorded.
- **SV-1 — preflight, green path.** Run `mix allbert.test preflight` on the
  clean tree. PASS: every check reported, exit zero, wall time under two minutes
  and recorded, attestation written.
- **SV-2 — preflight, red path and refusal.** Introduce one trivial formatting
  violation; re-run. PASS: preflight fails non-zero naming the check; then run a
  validation-only guard probe (not an aggregate) and prove refusal occurs before
  any child command is spawned. Revert and confirm green returns. This row proves
  the gate is load-bearing rather than advisory without paying for a long gate.
- **SV-3 — scope selection.** Run `scope --base <sha>` against a docs-only
  change and against a shared-spine change in a temporary disposable worktree;
  create one harmless untracked unknown path there and remove the worktree after
  evidence capture. PASS: the docs-only case selects the documentation re-run
  set; the spine case selects the full aggregate; the unknown path returns
  `aggregate_required=true` rather than narrowing.
- **SV-4 — role resolution on a real Home.** With no role configured, confirm
  ordinary chat resolves exactly as before. Configure `model_roles.fast` to a
  concrete profile, point one purpose key at `role:fast`, and confirm resolution
  reports requested reference, role, and resolved profile through the central
  operator catalog/doctor output. Unset it and confirm the diagnostic followed
  by the next configured chain item rather than an invented fallback. PASS: all
  three observations,
  and no suggestion or card appears anywhere — this release has no remap path.

A finding is classified environment, documentation, or executable. Executable
findings batch into one tranche, then repeat preflight plus the owning focused
rows and only the invalidated SV rows. Do not repeat the aggregate per finding.

## §G — Final Gate And Source-Only Tag

At the final clean pushed SHA, in this order:

```sh
mix allbert.test preflight      # this release dogfooding its own gate
mix allbert.test release.v1     # still-binding pre-v1.4 regression signal
mix allbert.test release.v132   # bounded delta
mix allbert.test release        # the one authoritative aggregate
```

Attended source validation finishes before these gates. `release.v132` contains
the preflight owner rows, the model-roles owner rows, the docs/version contract,
the source-only-tag contract, and `inventory --check-tags` plus
`--check-manifest`. Its structure proof also freezes owner-CWD test loading and
both inventory checks in preflight, and freezes the expanded archive-link docs
gate for v1.4 M14 to inherit. It must not replay
`release.v13`, `release.v131`, `mix precommit`, or a full suite. A structure
owner test proves the v1.3 and v1.3.1 gate definitions are unchanged and that the
authoritative `release` phases cover every owner file set without nesting a
versioned gate.

After all three are green and the operator approves the source tag:

```sh
set -Eeuo pipefail
cd /Users/spuri/projects/lexlapax/allbert-assist
git fetch --quiet origin main
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"
test -z "$(git status --porcelain)"
test -z "$(git ls-remote --tags origin refs/tags/v1.3.2 'refs/tags/v1.3.2^{}')"
V132_ACCEPTED_SHA="$(git rev-parse HEAD)"
V132_TAP_SHA="$(git ls-remote https://github.com/lexlapax/homebrew-allbert refs/heads/main | awk 'NR == 1 {print $1}')"
git tag -a v1.3.2 -m 'Allbert 1.3.2 foundational enablers [skip-artifacts]'
git push origin v1.3.2
test "$(git rev-parse 'v1.3.2^{}')" = "$V132_ACCEPTED_SHA"
test "$(gh release view --repo lexlapax/allbert-assist --json tagName --jq .tagName)" = v1.3.0
if gh release view v1.3.2 --repo lexlapax/allbert-assist >/dev/null 2>&1; then exit 1; fi
test "$(git ls-remote https://github.com/lexlapax/homebrew-allbert refs/heads/main | awk 'NR == 1 {print $1}')" = "$V132_TAP_SHA"
echo "PASS V132-SOURCE-TAG: v1.3.2 -> $V132_ACCEPTED_SHA; no release assets or tap movement; v1.3.0 remains packaged Latest"
```

Expected terminal line:

```text
PASS V132-SOURCE-TAG: v1.3.2 -> <40-hex accepted SHA>; no release assets or tap movement; v1.3.0 remains packaged Latest
```

Then update the release record, move this triad to `archives/`, run the docs
gate, and commit the administrative closeout. The tag stays bound to the
accepted implementation SHA; the later archive commit is not retagged.

## Explicitly Out Of Scope

Profiling, usage events, distill, suggestions, confirmed customization, and the
role-remap path (all v1.8); kernel inversions, param-contract enforcement,
PermissionGate deletion, and the migration runner (v1.4); putting preflight in
CI or inside an aggregate; changing any shipped default profile; native
artifacts, signing, GitHub Release publication, Homebrew changes, and package
validation. Any scope expansion requires a new explicit operator decision.
