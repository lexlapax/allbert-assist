# Allbert v1.6.0 Connectivity Enablers

Enabler release. Everything outward-facing — delegated authentication, protocol
parity, and network hardening — sequenced after the v1.5 spine and before v1.8
Knowledge ingest.

Constraining ADRs: **new ADR 0096** (delegated OAuth authority and token
lifecycle), plus the existing MCP client ADRs and the external-network approval
path.

Companion: `docs/plans/v1.6-request-flow.md`.

Status: **planned — triad drafted 2026-07-30, readiness passes not yet run.**
No Locked Decision below is operator-signed.

## Build Progress

Not started.

## Purpose

Make Allbert's outward-facing edges current and safe, once, in one release.

1. **One OAuth substrate, two consumers.** Email XOAUTH2 for Gmail and Microsoft
   OAuth-only mailboxes — increasingly the only way to reach a real mailbox —
   and OAuth-authenticated hosted LLM providers using subscription plans rather
   than metered API keys.
2. **MCP 2025-11-25 spec parity.** The client has drifted from the current spec;
   the delta is verified before it is scoped.
3. **Network hardening, consolidated.** Non-local bind hardening for public
   surfaces, and free-form provider URLs and probe targets routed through the
   external-network approval path so LAN and self-hosted model endpoints stop
   being a special case.

## Sequencing Note (why these ride together)

Three reuse relationships put these in one release rather than three:

**The two OAuth consumers share an entire substrate.** Authorization-code flow
with PKCE, tier-vault token storage, refresh, expiry tracking, and revocation are
identical for a mailbox and a model provider. They were previously tracked as
unrelated backlog entries — email OAuth in the enabler list, hosted-LLM OAuth
reachable only from the 2.0 roadmap entry — and would have been built twice.

**Bind hardening and free-form provider URLs both terminate in `HttpPolicy` and
the external-network approval path.** That is also where a 2026-07-29 survey
found the SSRF private-address table triplicated byte-for-byte across
`external/http_policy.ex:164`, `voice/provider_http.ex:401`, and
`settings/model_doctor.ex:496`. Three copies of an SSRF guard means a fix to one
leaves two holes. Consolidating it belongs to whichever milestone touches that
path, and this is it.

**OAuth's callback listener is a bound network surface.** It lands in the same
release as bind hardening deliberately: one bind policy, no OAuth exception.
Deciding those separately is how they end up inconsistent — which is why ADR 0096
settles the listener rules rather than leaving them to a milestone.

**Downstream:** v1.8 Knowledge ingest calls a model in a loop over
operator-supplied documents. Landing subscription-plan authentication and a
hardened egress path first materially improves that release's cost posture and
its untrusted-source containment.

## Locked Decisions

Numbering continues from the v1.5 plan. None is operator-signed yet.

10. **One OAuth substrate.** Both consumers configure it; neither reimplements
    it. Proven by a shared contract test, not by two parallel implementations.
    (ADR 0096 §3)
11. **Provider scope is never Allbert authority.** Granted scopes are recorded
    for diagnostics and gated through the same permission class a static
    credential would use. (ADR 0096 §1)
12. **Refresh tokens are a distinct credential class** — vault-only, redacted
    everywhere, never in export, backup, trace, log, audit body, or model
    context. (ADR 0096 §2)
13. **The callback listener binds loopback only**, on an ephemeral port, for one
    `state`-matched exchange, torn down on completion, timeout, and failure. It
    obeys the same bind policy as everything else — no OAuth exception.
    (ADR 0096 §4)
14. **Revocation and expiry fail closed** with a typed needs-re-authorization
    state naming provider and consumer; no automatic re-authorization.
    (ADR 0096 §5)
15. **Authorization is always an explicit operator act** — never initiated by
    model output, a channel message, or a schedule. (ADR 0096 §6)
16. **MCP scope is verified before it is committed.** The 2025-11-25 delta is
    established at M0; scope follows the delta rather than the entry title.
17. **One private-address table.** The three copies are consolidated into a
    single owner in this release, with behaviour proven identical first.
18. **Free-form provider URLs route through the existing external-network
    approval path.** No new permission class, no bypass for "local" endpoints —
    a LAN address is still an egress decision.

## Security Posture

This release adds a credential class, a network listener, and a broader set of
reachable endpoints. Each is bounded:

- Refresh tokens never leave the vault in plaintext and are redacted on every
  surface using the existing secret-ref mechanism, not a new one.
- The callback listener is loopback-only, single-use, `state`-matched, and
  short-lived.
- Free-form provider URLs are an egress decision every time, including LAN and
  loopback targets. "Local" is not an exemption.
- The consolidated private-address table is proven behaviour-identical to all
  three current copies before they are removed, so consolidation cannot silently
  widen what is reachable.
- Provider-granted scopes are recorded, never trusted as authority.

## Non-Goals

Device-code and client-credentials OAuth flows; multi-tenant or shared grants;
hosted multi-user authorization (parked); IMAP IDLE push; SMTP provider API
delivery; channel adapter remainders. Knowledge (v1.7/v1.8).

## Validation Design (churn guardrails, binding)

- OAuth is validated against **real providers**, not fixtures. Fakes are
  automated-test fixtures only; acceptance uses configured real endpoints.
- The private-address consolidation is proven by running the merged table against
  every input the three prior copies handled, before any copy is deleted.
- Revocation is tested by actually revoking a grant at the provider, not by
  simulating a 401.

## Definition Of Done

- One OAuth substrate serves both consumers, proven by a shared contract test.
- A real OAuth-only mailbox and a real subscription LLM provider both authorize,
  refresh, and survive revocation with a typed needs-re-authorization state.
- Refresh tokens never appear in export, backup, trace, log, audit body, or model
  context.
- The callback listener binds loopback only, accepts one `state`-matched
  callback, and tears down on completion, timeout, and failure.
- Provider scope cannot widen an Allbert permission decision, proven
  adversarially.
- MCP parity closes the measured 2025-11-25 delta.
- One private-address table remains, behaviour-identical to the three it
  replaced.
- Free-form provider URLs are approval-gated with no local or loopback exemption.
- `release.v16` composes the exact `release.v15` prefix and is green at one clean
  pushed SHA; `v1.6.0` is built, signed, published, tap-installed, and
  revalidated; ADR 0096 is Accepted.
