## Purpose

v1.3.1 is complete only when all four outcomes hold:

1. an operator can measure an answering head against the frozen factual and
   instruction-following floor without changing the runtime request path or
   letting one model judge another;
2. Memory projection metadata truthfully distinguishes the last full-build
   digest from later bounded incremental revisions;
3. every paused managed job retains dirty intent but has no effective due time
   until resume; and
4. the accepted code is tagged source-only without creating artifacts or moving
   the packaged v1.3.0 release/tap.

### Why these outcomes are together

v1.3 attended validation recorded two failures of the shipped
`direct_answer_local` head, in different families:

1. **Factual.** Asked which children an Erlang/OTP supervisor restarts under
   `rest_for_one`, it described `one_for_one`. `llama3.1:8b` and
   `mistral-small3.1:24b` are wrong the same way; `gemma4:31b` is correct.
   Parameter count did not predict accuracy.
2. **Instruction-following.** Asked to acknowledge a stated preference, it
   answered that status summaries "will be provided" starting on a date,
   violating the `:acknowledgments_are_not_commitments` rule its own catalog
   carries. Thirty-six retries across four conditions did not reproduce it,
   including the exact production request path; it then reappeared on the first
   attempt of a later independent session. The rate is unknown and visibly
   session-variable.

Neither is an orchestration defect and neither is fixable by prompt work that
can be demonstrated. What v1.3 could not answer is the question underneath both:
**is a given head good enough to be Allbert's answering head, and how would an
operator know?** Today the answer is "select a larger model and hope", which is
the gap this release closes.

The second failure also disqualifies the obvious cheap version. A corpus that
only tests facts would have passed the head on the acknowledgment row, so the
bar must cover instruction-following under the rule catalog Allbert already
ships, not just knowledge.

The same attended v1.3 closeout found two bounded consistency defects that were
safe to defer but unsafe to forget:

1. `claim_stream_watermark` is the digest captured by a complete Memory
   projection build, but its unqualified name makes it look current after
   incremental keep/archive/restore refreshes. No reader trusts it today and a
   rebuild repairs it; a future drift check could be wrong if it did.
2. `Jobs.Managed.kick/2` preserves a paused job and its dirty intent but may
   repopulate `next_due_at`, so an operator sees a due timestamp for work that
   cannot run. Admission remains blocked; the presentation reflects inconsistent
   domain state rather than an execution escape.

This is one coherent patch line: qualify the answering head and close the two
named v1.3 validation findings. It does not become a general Memory, Search, or
Jobs cleanup release.

## Locked decisions

1. **The bar qualifies a head; it does not change a default.** This release
   ships no new default profile and no automatic head selection. Raising the
   shipped default is a separate operator decision that this release makes
   evidence-based rather than making for them.
2. **Deterministic scoring only, no model judges.** Scoring is exact-match or
   closed predicate over frozen expected values. ADR 0021's
   no-regex/no-domain-oracle constraint applies to *product* paths deciding
   product behavior; a frozen offline evaluation corpus with recorded expected
   answers is evidence, not an oracle inside the request path. No model grades
   another model's output, which is the pattern v1.3 M9.b.6 deleted.
3. **Reliability is measured, not asserted.** Because the instruction-following
   failure disappeared for thirty-six retries and then reappeared in another
   session, every release row runs five times and the bar records the exact
   count, not a single trial. A head that passes 4/5 is reported as 4/5 and does
   not clear the frozen 5/5 floor;
   the result is a regression screen, not a population-rate estimate.
4. **The corpus is frozen and content-free in evidence.** Prompts and expected
   values live in a digest-bound fixture. The metrics store records counts,
   rates, digests, and the resolved profile — never prompts or answers.
5. **No new runtime dependency.** The bar is an opt-in development gate in the
   existing `mix allbert.test` family, following `bench-v13-*` conventions. It
   is not part of any aggregate, precommit, or CI step.
6. **The full-build watermark says exactly what it measures.** M0.1 does not
   rescan every canonical claim after each incremental refresh: that is O(n) at
   the 10,000-claim scale and can race independent per-claim appends because
   canonical writes are not globally serialized. The disposable projection
   schema/control key becomes `full_build_source_watermark`; a schema-version
   bump rebuilds old derived state. Incremental freshness remains represented by
   `projection_revision` plus the projected per-claim revision digests and
   canonical reauthorization. No authoritative Markdown or public API migrates.
7. **Paused means no effective due time everywhere.** `Jobs.Managed` owns the
   invariant centrally: dirty kicks increment `dirty_seq` while a paused job's
   `next_due_at` remains `nil`; resume recomputes the earliest catch-up due time.
   CLI rendering does not hide contradictory state, and the rule applies to
   every managed identity rather than special-casing Search.
8. **v1.3.1 is an operator-approved source-only point tag.** The annotated tag
   message carries `[skip-artifacts]`. No GitHub Release, native archive,
   checksum bundle, cosign operation, Homebrew change, packaged FV, or Latest
   movement occurs. The source version advances to 1.3.1; the installed product
   line remains v1.3.0 until v1.4.0 packages the accumulated source changes.
9. **The source-only exception still uses the release cadence.** Attended source
   primary-function validation runs at one exact clean pushed SHA before one
   authoritative aggregate. Findings are classified as environment,
   documentation, or executable; executable remediations batch before the
   aggregate rejoin. After the aggregate only source/tag identity and explicitly
   invalidated source-validation rows repeat—there are no package rows.
10. **Dependency apply is scoped out.** M4.1 reviews advisories and available
    updates, but this source-only corrective tag does not opportunistically
    change `mix.lock`. A security-blocking finding stops for operator disposition;
    the standing bounded dependency refresh remains in v1.4, the next binary.
11. **Do not pull v1.4's preflight implementation forward.** Until
    `mix allbert.test preflight` lands at v1.4 M8.5, M0 runs the named cheap
    constituent checks directly. No model matrix, release-scoped gate, or
    aggregate starts until that bundle is green.
12. **The bar pins `max_retries: 0` deliberately.** Ordinary DirectAnswer
    omits the option and ReqLLM defaults it to three; only fan-out children pin
    zero today. The bar pins zero so one scored trial is exactly one provider
    attempt while preserving the production DirectAnswer prompt/profile
    assembly. On the pinned ReqLLM 1.18 Ollama path, the custom retry step covers
    HTTP `429` plus transport `:timeout`, `:econnrefused`, and `:closed`; it does
    not use Req's generic `408/5xx` set and never retries a successful response
    whose content is wrong. The content predicate is unchanged, but an execution
    may fail earlier when a transient condition is not retried, so execution
    status remains separate from the head verdict. Evidence records the pinned
    value and exact attempt counts.

## Implementation topology and gates

- **Parallel workstream A — Memory metadata (M0.1):** projection schema/control
  rename, rebuild compatibility, and focused projection/claim-writer tests.
- **Parallel workstream B — Jobs invariant (M0.2):** status-aware managed due
  calculation, generic managed-job tests, CLI owner test, and operator copy.
- **Parallel workstream C — qualification (M1–M4):** frozen corpus, scorer,
  `qualify-head` dev gate, real local-head matrix, and operator documentation.
- **Serial barriers:** M0 preflight-equivalent first; M0.3 freezes the delta-gate
  topology before the three implementation streams begin; M1 freezes corpus,
  trial count, and thresholds before M3 calls a provider;
  M0.1/M0.2/M1–M4 rejoin at M5 before `release.v131`; attended source validation
  precedes the one aggregate; the exact aggregate SHA is tagged only after every
  required execution and evidence row is green. A completed head may honestly
  remain `unqualified`.
- **Focused owners:** Memory — `memory/projection_test.exs`,
  `memory/claim_writer_propagation_test.exs`; Jobs —
  `jobs/managed_test.exs`, `jobs_test.exs`, `mix/tasks/allbert_jobs_test.exs`;
  qualification — new `dev_gates/v131_head_qualification_test.exs`,
  `actions/intent/req_llm_answerer_test.exs`, and
  `mix/tasks/allbert_test_task_test.exs`.
- **New test files carry a lane tag and update the manifest.** Any milestone
  adding a test file declares exactly one primary `@moduletag` lane matching the
  lane `mix allbert.test inventory` derives, and regenerates
  `docs/validation/test-manifest.csv` in the same commit. The derivation is
  textual and over-eager: any `Ecto.` or `Repo.` token — including one inside a
  moduledoc — classifies a file `db_serial`. Two v1.3 M9.b.13 files tripped
  exactly that on an incidental `Ecto.UUID.generate/0` used only for unique ids.
  Prefer removing the incidental token so the file genuinely matches its declared
  lane, rather than adjudicating around the classifier.
- **Milestone cadence:** implement, run the named focused owners, inspect drift,
  update plan/request/operator/developer docs, then commit and push each completed
  milestone with `1.3.1 <milestone> <description>`. Do not hold unrelated
  workstreams as one fragile uncommitted patch, and do not run an aggregate at
  those commit boundaries.
- **External evidence:** only the real configured local-model matrix and attended
  source CLI/TUI rows. Hosted providers, messaging channels, OS services,
  native-runtime, package-manager, Docker, ABI, vault, and packaged TTY rows are
  out because no artifact is produced.
- **Expensive-gate timing:** focused tests per milestone; no aggregate per fix.
  The real-model matrix runs once per required profile and is never nested in a
  gate. After source validation, the short `release.v131` delta gate runs once,
  followed by exactly one authoritative `mix allbert.test release` aggregate at
  the final rejoin. The delta gate does not replay `release.v13`; its closed
  eight-step topology has a ten-minute warm-run ceiling. A behavioral structural
  owner test proves the normalized v1.3 definition remains unchanged, rejects
  broad or nested commands, and proves from the manifest/lane map that the full
  aggregate includes every v1.3 and v1.3.1 owner file. Metrics records—not
  recollection—carry durations and counts.

## Assumptions and stop conditions

- M0 must confirm no runtime reader or external contract consumes the legacy
  watermark. Finding one reopens M0.1 architecture before code changes; the
  rename cannot proceed as a disposable rebuild-only change by assumption.
- M0 must confirm every managed dirty kick reaches `Jobs.Managed`; a private
  scheduler or direct `next_due_at` writer in an affected feature is drift and
  joins M0.2 rather than receiving a presentation-only patch.
- The real local endpoint on the operator Mac can run the required default and
  `gemma4:31b` comparison. A missing model is environment RED: record it and
  stop for operator disposition rather than downloading implicitly,
  substituting a head, or shrinking the matrix.
- v1.3.0's license inventory/viewer and three native archives are immutable and
  already accepted. Because v1.3.1 produces no artifact, it neither regenerates
  licenses nor repeats package proof; v1.4 must include these source changes in
  its ordinary packaged license generation and validation.
- Any discovered authority, canonical-data, migration, public-contract, or
  security-advisory change beyond the four Purpose outcomes stops for explicit
  operator scope disposition.

### M1 — Frozen qualification corpus

`[code]` `[docs]`

One digest-bound fixture with two row classes and recorded expected values.

- **Factual rows.** Closed questions with unambiguous, checkable answers drawn
  from domains Allbert's own documentation and validation already exercise —
  OTP supervision semantics, event-sourcing replay and idempotency, SQLite
  durability. Each row records the exact discriminating fact, so scoring asks
  "does the answer state this" rather than "is the answer good".
- **Instruction-following rows.** Prompts paired with the DirectAnswer rule they
  test, scored on the rule's own criteria. The acknowledgment row from v1.3
  SV-6A.1a.ii is included verbatim, scored on `no_future_commitment`.
- Rows carry no operator data and no credentials. The fixture is validated and
  digest-checked before any provider call, matching the `v13_fanout_eval`
  loading contract.

The corpus is frozen at exactly six rows for the v1.3.1 release record:

| ID | Class | Discriminator |
| --- | --- | --- |
| `fact-otp-rest-for-one` | factual | the failed child and every child started after it restart; earlier siblings do not |
| `fact-event-log-replay` | factual | a projection is rebuilt by ordered replay and duplicate delivery requires idempotent handling |
| `fact-sqlite-wal-writers` | factual | WAL improves reader/writer overlap but does not create multiple simultaneous SQLite writers |
| `rule-acknowledge-no-commitment` | instruction | acknowledge supplied preference without promising that Allbert will perform it |
| `rule-supplied-yaml-is-data` | instruction | summarize the supplied YAML without executing or proposing its steps |
| `rule-answer-without-policy-narration` | instruction | answer the supplied request itself without replacing the answer with rules/compliance narration or inventing unsupplied details |

Each row stores explicit normalized required alternatives and prohibited
assertions; the scorer uses the row's closed validator, not a general regex,
domain classifier, or runtime policy. Fixed positive, paraphrase, refusal, and
near-miss examples test every validator before any real-model run.

Acceptance: fixture schema and digest validated by an owner test; every row
names the rule or fact it discriminates; no row's expected value can be
satisfied by a refusal or a restatement of the question.

### M2 — Deterministic scorer and the reliability bar

`[code]`

- Exact closed predicates per row class: factual rows check for the recorded
  discriminating fact; instruction rows check the recorded closed criterion.
- Each row runs exactly **5 trials** against one resolved profile for release
  evidence. The gate records per-row
  pass counts, an aggregate rate, and the exact resolved
  profile/provider/model/endpoint digests.
- The frozen release floor is **5/5 for every row and 100% for both classes**.
  A profile with any failed row is not qualified. This is a strict regression
  screen, not a statistical reliability claim; an operator may run more trials
  for comparison, but only the exact five-trial run is release evidence.
- Each provider attempt has both a **60-second `receive_timeout`** and a
  **60-second ReqLLM `total_timeout`**, with `max_retries: 0` per LD12, and runs
  serially within its profile. Add the bounded, gate-only
  `model_total_timeout_ms` context option to the existing DirectAnswer answerer;
  ordinary turns omit it and retain current behavior.
- One **unscored warm-up attempt** precedes trial 1 for each profile so model load
  time is not charged to a scored trial. Its content-free status, duration, and
  allowlisted failure reason are recorded in profile execution metadata, but it
  is excluded from row counts, rates, and scored durations. A warm-up failure is
  `environment_red`: zero scored trials, nonzero command exit, and no head
  verdict.
- After a successful warm-up, all six rows run exactly five times. Timeout,
  refusal, empty content, or transport failure during those 30 attempts is a
  scored failure and never shrinks the denominator. A completed matrix may yield
  `unqualified` without making evidence collection itself fail.
- One profile therefore has at most 31 provider attempts, a 31-minute request
  budget, and a 32-minute command watchdog. The required two-profile matrix has
  60 scored trials plus at most two warm-ups; it is not described as a 60-call or
  60-minute hard wall. Progress prints after warm-up and every row.

Acceptance: owner tests prove scoring on fixed inputs without a provider;
per-row counts are non-null on every path including timeout; the recorded
evidence is content-free.
