# Allbert v1.2.6 Foundation → v1.3.0 Long-Term Memory And Search Central

Request flow: `docs/plans/v1.3-request-flow.md`

Architecture decisions:

- ADR 0002 — markdown-first memory (amended here for append-only claim streams)
- ADR 0076 — packaging, distribution, and unified CLI (amended here for
  packaged license material and daemon-only TUI attachment)
- ADR 0089 — long-term user memory and consent (amended here for the Corpus
  boundary, immutable bi-temporal claims, proposals, Forget, and independent
  Search consent)
- ADR 0091 — daemon-backed TUI sessions (new)
- ADR 0092 — Search Central and conversation-corpus projections (new)
- ADR 0093 — canonical conversation deletion and retention boundary (new;
  extracted from ADR 0092 §3 by the fifth readiness pass because deletion is a
  Corpus-owned destructive capability, not a search concern)

Status: **Stage 1 shipped; Stage 2 M1–M9.a2 implementation and rehearsals
complete; M9.b release-candidate freeze, aggregate rejoin, exact-SHA artifact
qualification, and closeout are in progress.**
The operator approved the decisions in this plan, including the recommended
defaults for the remaining questions. This is one active planning triad and a
two-stage binary release train:

1. **v1.2.6 foundation:** packaged license inventory/viewer and the
   daemon-backed thin TUI, each in its own milestones.
2. **v1.3.0 flagship:** canonical conversation Corpus, reviewed bi-temporal
   long-term memory, and Search Central with managed ingestion/maintenance.

The v1.2.6 binary acceptance is a serial barrier before v1.3 implementation
begins. Keeping both stages in this plan avoids a release-planning sidecar while
preserving separate tags, acceptance bars, gates, dependency-refresh work, and
release evidence. It also matches the documented post-1.0 model, in which one
versioned plan ships one or more point tags accumulating to the next minor.
Stage closeout and triad archive are therefore different events — see LD 63.

**Corrective release identity (2026-07-29).** `v1.2.6` is the active Stage 1
binary after immutable `v1.2.5` failed post-build manifest composition. Stable
internal `v121` milestone/gate/harness identifiers and historical evidence keep
their literal names. Any still-unqualified forward-looking Stage 1 reference
to `v1.2.5` below means the unchanged foundation scope now shipping as
`v1.2.6`; literal tag/SHA/run history continues to mean the failed `v1.2.5`
attempt.

**Stage 1 closeout (2026-07-29).** Immutable `v1.2.6` at `f457b1fe` shipped
from source run `30491295028` through protected promotion `30492163551`; tap
commit `7ce955c` passed strict online audit, style, install, formula test, and
packaged license/TUI acceptance. M0.c3 is closed in place. Stage 2 may begin;
the active triad remains here until v1.3.0 closeout.

**Third readiness pass 2026-07-28 (operator-signed, this revision).** A
cross-check against the code found the second pass had designed the new memory
world without dispositioning the old one: `search_memory`, the compiled memory
index and its managed job, `prune_nominated`, `memory.auto_promote_sensitive_
entries`, and the v0.47 memory drafts all overlap something v1.3 introduces,
and one of them contradicted the plan's own Definition of Done. It also found
the canonical conversation delete action required by LD 50 and FV-02 does not
exist, an assistant-context rule whose eval row could not be proven, and no
writer-ownership policy for the two new databases. LD 58–63 resolve these.

**Fifth readiness pass 2026-07-28 (operator-signed, this revision).** A final
cross-document audit found five missing items and three inconsistencies, all
narrow: the Search feature switch was never named, the LD 62 shared promote
helper was never named as a module, the Forget/conversation-retained disclosure
existed in ADR 0089 and the request flow but not in the plan that gates it, the
Memory projection had no export-exclusion row, Purpose outcome 9's "bounded
latency" had no Definition-of-Done line, `e2ee_operator` was absent from the
plan, request-flow invariant 10 lacked the promote-helper carve-out the plan
had added, and canonical conversation deletion was architecturally homed in the
Search ADR. LD 79 and ADR 0093 resolve the last of those; the rest are named in
place.

**Final readiness pass 2026-07-28 (operator-signed, this revision).** The final
cross-document/code pass closed the remaining implementation ambiguities:
origin-scoped grants, canonical-versus-consumer-scoped invalidation,
Jobs-owned dirty kicks, crash-safe Memory review/Forget, legacy compatibility
behavior, mechanically grounded spans, Search repair/paging/query
confidentiality, exact deletion targets, evidence-bound binary promotion, and
milestone/rejoin ownership. LD 64–78 record the decisions; the milestone and
test matrices assign their work.

## Purpose

### v1.2.6 foundation

1. **A self-describing binary, without a license-management subsystem.** Every
   supported artifact carries Allbert's license and notice, a deterministic
   best-effort inventory of known shipped components, the corresponding
   required license texts, exact source-availability metadata, and a pure
   `allbert licenses` viewer. The
   inventory is derived at final artifact composition, not guessed from the
   development dependency tree.
2. **One runtime behind every terminal session.** `allbert tui` becomes a thin
   terminal client attached to the already-running daemon. The daemon owns
   runtime state, identity, confirmation, Pi-mode work, and event delivery; the
   client owns only input and rendering. No second embedded runtime or silent
   fallback remains.
3. **Artifact and toolchain claims are reproducible and honest.** All three
   native targets use exact toolchain inputs, clean current web assets, and the
   same finalization contract. The release evidence identifies target-specific
   bytes and external runtimes without claiming cross-platform byte identity or
   universal file ownership.

### v1.3.0 flagship

4. **One canonical corpus, two independent consumers.**
   `AllbertAssist.Conversations` remains the owner of conversation truth.
   Memory and Search consume a typed `Conversations.Corpus` contract; neither
   reaches into the other's projection, and surfaces never query storage
   directly.
5. **Memory that is useful, reviewable, temporal, and repairable — and one of
   it.** Periodic local consolidation proposes facts from verified
   operator-authored conversation turns, with span provenance for every
   accepted field. Only explicit review makes a proposal retrievable. Claims
   retain valid-time and knowledge-time history in append-only Markdown
   streams, and a complete disposable projection makes prompt-time lookup
   bounded. The release **supersedes** the previous compiled memory index, its
   managed rebuild job, and the v0.47 memory-draft suggestion path rather than
   shipping beside them (LD 58).
6. **Search as a central engine and API.** Web, TUI, CLI, mapped DMs, and later
   surfaces use one typed Search action/API over a dedicated rebuildable SQLite
   projection. Query-time Corpus authorization prevents stale, deleted,
   revoked, or cross-scope results from escaping.
7. **Balanced consent and low operator burden.** Consent is granted once per
   feature and eligible source class rather than per job or per message.
   Routine local indexing and recurring work do not repeatedly prompt.
   Scope expansion, E2EE-origin indexing, cross-surface DM disclosure,
   protected memory review, Forget, and secure purge remain explicit acts.
8. **Recurring work uses the recurring engine.** Memory consolidation and
   Search ingestion, reconcile, maintenance, and rebuild are visible managed
   entries in the existing Jobs system. v1.3 adds ownership/reconciliation,
   not another scheduler.
9. **Measured quality without a long aggregate-build loop.** Extraction gates
   precision, recall, protected-data exclusion, knowledge update, temporal
   retrieval, and abstention. Search gates scope, freshness, deletion, ranking,
   rebuild, and bounded latency. Focused milestone tests, targeted static checks,
   and named artifact/external smokes run throughout. No aggregate or full-project
   command runs during v1.2.5 or an intermediate v1.3 milestone: this includes
   `mix precommit`, `release.v1`, `release.v12`, `release.v121`, `release.v13`,
   and the full release gate. Gate definitions may be composed earlier, but the
   sole cumulative/authoritative aggregate execution is the final v1.3 M9.b
   closeout rejoin at one clean pushed SHA.

## Research Basis

Research informs these decisions but does not import an external product's
architecture:

- Mix releases can bundle ERTS and expose ordered post-assembly release steps;
  the final release filesystem, not `release.applications` alone, is the
  artifact-composition boundary:
  <https://hexdocs.pm/mix/Mix.Tasks.Release.html> and
  <https://hexdocs.pm/mix/Mix.Release.html>.
- setup-beam documents exact/strict input versions and resolved version
  outputs, which support one toolchain contract on every target:
  <https://github.com/erlef/setup-beam#input-versioning>.
- GitHub Actions environments can require approval before a job starts, so the
  public repository's publish job can wait after artifact staging and before
  signing/upload without occupying a runner or rebuilding. Environment branch/
  tag rules match the workflow run's `GITHUB_REF`, and `workflow_dispatch`
  accepts a branch or tag `ref`; promotion therefore dispatches at the exact
  product-tag ref rather than merely accepting an untrusted tag input. A
  different-run artifact download requires the source run id and token, and
  artifacts disappear after their configured retention:
  <https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments>,
  <https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event>,
  and
  <https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts>.
- Mozilla's CA material remains MPL-2.0 when converted into curl's CA extract.
  MPL obligations are file-scoped:
  <https://curl.se/docs/caextract.html>,
  <https://www.mozilla.org/en-US/MPL/2.0/>, and
  <https://www.mozilla.org/en-US/MPL/2.0/FAQ/>.
- SQLite FTS5 documents tokenizers, BM25, snippets, merge/rebuild/integrity,
  external-content synchronization hazards, and FTS-specific secure deletion:
  <https://www.sqlite.org/fts5.html>. WAL permits concurrent readers but one
  writer per database: <https://www.sqlite.org/wal.html>. VACUUM rebuilds the
  database and needs free space/exclusive conditions:
  <https://www.sqlite.org/lang_vacuum.html>. Core secure-delete behavior is
  documented at <https://www.sqlite.org/pragma.html>.
- LongMemEval measures information extraction, multi-session reasoning,
  temporal reasoning, knowledge updates, and abstention:
  <https://arxiv.org/abs/2410.10813>. Zep/Graphiti records valid and learned
  time on graph edges: <https://arxiv.org/abs/2501.13956> and
  <https://www.getzep.com/platform/graphiti/>. Mem0 separates extraction,
  consolidation, and retrieval:
  <https://arxiv.org/abs/2504.19413>. These support the evaluation dimensions;
  they do not justify adding a graph, vector store, or external memory service.
- External memory projects change behavior independently of their papers
  (including Mem0's current public ADD-focused interface). Implementation pins
  research fixtures and claimed versions rather than treating a moving project
  README as a stable Allbert contract.

## Locked Decisions

### Release and additive-contract decisions

1. **Two binary stages, one plan.** v1.2.5 ships licensing and daemon-backed
   TUI before v1.3 memory/Search work. Each stage tags, builds natively, signs,
   publishes, fills the tap, and validates the installed product.
2. **Additive evolution only.** Existing public action/request shapes, memory
   files, settings, database rows, and explicit write paths retain their
   meanings. New optional fields, actions, statuses, files, and projection
   stores may be added. No migration-runner pull-forward is authorized.
3. **Scope deferral stays an operator decision.** If a Purpose outcome would
   require materially more code than this plan's bounded design, stop with
   evidence and propose the smallest alternative. Do not build a framework to
   avoid asking, and do not silently move the outcome out of the release.

### Packaged-license decisions

4. **One generator, one catalog, one viewer.** A small offline deterministic
   finalizer consumes resolved release applications/locks plus one reviewed
   catalog of known extras/exceptions. `allbert licenses` is a pure reader of
   packaged files, dispatched before CLI runtime/Req startup. There is no
   runtime license process, SBOM platform, recursive universal ownership
   scanner, or per-file license database.
5. **Honest best-effort claim.** The product says “best-effort inventory of
   known shipped components.” It does not claim universal completeness,
   complete legal compliance, or that every arbitrary byte has an attributable
   package owner.
6. **Fail closed at managed seams only.** Finalization fails for an unknown
   shipped BEAM application, a known catalog component with missing/unapproved
   license or required text, an expected path missing, a known special payload
   whose provenance digest drifted, or a known external runtime unexpectedly
   bundled. Unclassified arbitrary bytes produce bounded evidence/warnings;
   they do not trigger a complex scanner.
7. **Canonical union plus target truth.** Commit one deduplicated
   cross-platform `THIRD-PARTY-LICENSES.md` and the reviewed catalog. Generate a
   per-target `THIRD-PARTY-MANIFEST.json` from the final artifact. Root
   `LICENSE` and minimal `NOTICE` are staged beside them.
8. **Known-component coverage.** The catalog accounts for bundled OTP/ERTS and
   sublicenses, Elixir, SQLite/Exqlite amalgamation/NIF, OpenSSL when copied,
   Castore/Mozilla CA material, IANA timezone data, compiled/vendored web
   assets, staged plugins, and packaged helpers. Node/Playwright/Chromium and
   TradingAgents/Python remain marked external unless their bytes are actually
   present in the artifact.
9. **Narrow MPL exception.** Castore code remains Apache-2.0; its
   Mozilla-derived `priv/cacerts.pem` receives one file-level MPL-2.0 exception.
   The catalog records full source provenance and digest, ships the MPL text,
   and supplies an immutable exact-source retrieval reference with digest and
   conversion provenance. Missing source availability or payload drift fails
   closed. External release qualification performs an unauthenticated fetch of
   the immutable reference and matches its exact source digest; failure blocks
   publication. Generation/viewing stays offline.
   Schema v1 selects the immutable-reference route and rejects companion-mode
   catalog entries; a later schema may add companion packaging additively.
   This is not a blanket MPL allowlist.
10. **Finalize last, verify before archive.** Clean/current assets are required.
    The license finalizer runs after plugin staging, target-specific OpenSSL
    mutation, and dispatcher installation; verification then proves the
    manifest against an unchanged tree before archive/sign/publish.
11. **One exact toolchain contract.** Linux and macOS use an exact strict
    setup-beam path pinned by full action SHA, record resolved OTP/Elixir
    versions, and do not run a floating `brew update && brew install erlang
    elixir` build. Requalify macOS once; retain the OpenSSL patch only if the
    final dependency closure proves it remains necessary.

### Daemon-backed TUI decisions

12. **Daemon owns behavior; client owns the terminal.** Runtime submission,
    operator identity, confirmations, Pi-mode lifecycle, subscriptions, and
    event fan-out remain in the daemon. The client owns TTY mode, input,
    rendering, bounded local presentation state, and restoration on exit.
13. **One TUI attachment per Home initially.** A second TUI receives a stable
    occupied diagnostic. There is no live-session replay/resume in v1.2.5.
14. **No silent embedded fallback.** When the daemon is absent, TUI/attached
    commands fail with paste-executable start/repair guidance. A bind failure
    may leave Web healthy-but-degraded, but attached TUI/CLI fail closed.
15. **Additive Attach v1 shape.** An optional request `kind` distinguishes
    `command` and `tui_session`; an absent kind retains legacy unary behavior.
    Session frames are typed, size-bounded, sequence-aware, and limited to the
    TUI need. This is not a general transport framework.
16. **Disconnect and overload are explicit.** Socket loss ends the terminal
    attachment; a surviving client that observes the close restores its own TTY
    state. Durable background work may finish; effectful Pi coding work tied to
    the lost session cancels fail-closed.
    Bounded queues coalesce/drop presentation-only updates before authority or
    confirmation events, and surface the gap rather than hiding it.

### Corpus, identity, and consent decisions

17. **Conversations owns canonical truth.** Add a deep
    `AllbertAssist.Conversations.Corpus` interface and typed/versioned
    `SourceEnvelope`. Do not add a generic storage behavior while SQLite is the
    only canonical store.
18. **No schema-leaking consumers.** Memory and Search use snapshot/keyset
    pages and canonical batch rehydration/authorization. Neither reads
    conversation Repo tables directly; Memory never reads Search/FTS; Search
    references are advisory until Corpus reauthorizes them.
19. **No new durable event platform.** Existing successful writes emit a
    dirty marker plus `Jobs.Managed.kick/2` for the existing consumer identity;
    Jobs performs coalescing and an hourly managed reconcile catches missed
    kicks, deletes, identity remaps, and policy drift. Canonical delete actions
    request immediate managed reconciliation. Query/review-time
    reauthorization suppresses ineligible material before physical projection
    repair, so correctness does not depend on a perfect event delivery log.
20. **Verified principal, not role.** Operator authorship requires the
    canonical principal/author identity and channel trust mapping. Each remote
    message carries an immutable normalized origin-principal digest/version and
    exact thread-channel-ref id captured at admission/persistence; inbound
    provider message refs bind the same exact thread ref. Assistant authorship
    remains distinct while its origin evidence records the verified request
    context. Current reauthorization compares that evidence with the enabled
    identity mapping.
    Local authenticated rows use canonical operator ownership and local trust.
    `role == "user"` alone is insufficient. Role stays a separate field.
21. **Consent is per consumer, source class, and origin scope.** Search and
    Memory each have a separate feature grant over the eligible
    `private_operator` trust class. The frozen origin-scope identifiers are
    exactly `local_operator`, `mapped_operator_dm`, and `e2ee_operator`; M1
    freezes no others. `local_operator` covers local Web/CLI/TUI;
    Search is implicitly enabled there via `search.enabled` (LD 60) while
    Memory collection remains an explicit default-off grant.
    `mapped_operator_dm` is one explicit grant per
    consumer and covers current/future verified mapped one-to-one operator DMs
    without per-channel prompts. `e2ee_operator` is an additional per-consumer
    audited overlay (LD 22) and is never implied by either other scope. Grants
    are non-transitive: Search never
    authorizes Memory collection and Memory never authorizes Search projection.
    Group/shared/programmatic/unknown sources remain excluded.
22. **E2EE needs separate opt-in.** The disclosure states that indexing creates
    local plaintext-derived FTS content. No SQLCipher or application encryption
    layer is added. Canonical source deletion, visibility loss, verified-
    principal invalidation, or an unverified principal remap makes the source
    ineligible for both consumers. Once a remap is verified, each consumer
    re-evaluates it under its own current origin/E2EE grant. A Memory grant/
    E2EE revocation invalidates only pending Memory proposals; a Search grant/
    E2EE revocation suppresses only Search results. No consumer-scoped
    transition grants or revokes the other consumer implicitly.
23. **Kept memory is independently authorized.** Source revocation/deletion
    does not silently delete a fact the operator separately kept. Its
    provenance reports the unavailable/revoked source until the operator
    archives or Forgets it.

### Memory decisions

24. **Authenticated immutable claim streams are the authority.** Each logical claim is one
    human-readable Markdown file with append-only immutable revision blocks:
    stable `claim_id`, immutable `revision_id`/sequence, previous-revision
    digest, `recorded_at`, valid-time bounds, review transition, source
    IDs/digest/classification, and optional `supersedes_claim_id`. Every
    post-v1.3 action-authored authority transition also carries a
    domain-separated Key Custody integrity tag. Hash chaining detects mutation;
    the tag distinguishes an authorized action transition from hand-authored
    text without adding a second authority ledger.
25. **True bi-temporality.** Valid time describes when a fact applies in the
    operator's world. Knowledge/system time describes when Allbert recorded a
    revision. Default retrieval is “valid now, known now”; typed explicit dates
    may select either axis. Ambiguous natural-language time asks for
    clarification rather than silently shifting the query.
26. **No mutation disguised as history.** `recorded_at` is chronology, not a
    winner rule. Automation may exact-dedupe, accept provably non-overlapping
    validity intervals, or construct explicit supersession when the operator
    statement supplies the relation/effective date. Overlapping or
    underspecified conflicts remain unresolved proposals.
27. **Legacy and manual editing stay additive.** Existing flat files read as a
    grandfathered synthetic revision zero and upgrade lazily only on the next
    change, whose signed native transition binds the exact legacy digest and
    synthetic claim id. Before adoption, derive that id with UUIDv5 namespace
    `3a933b90-6d58-5d8c-9cdb-1233c996532f` over
    `legacy-memory-v1\0<category>\0<normalized-Home-relative-path>`. A move is a
    removed legacy source plus a newly discovered one until the first native
    transition embeds the id; value-bound Forget suppression still prevents a
    copied/moved forgotten value from reappearing. The only
    supported raw manual change shape is an append-only revision, and it remains
    quarantined until the operator confirms that exact revision through
    registered action `confirm_manual_memory_revision`. Confirmation appends a
    content-free `manual_import_confirmed` transition over the unchanged pending
    revision digest with the suppression/normalizer version, non-secret key
    reference/version, and a domain-separated integrity tag from existing Key
    Custody. Rebuild requires that valid transition; no Repo ledger becomes a
    second authority. A file copied without the referenced key quarantines its
    tagged authority chain and permits one exact-whole-chain re-confirmation
    under the destination Home's key; a full same-Home restore with the key
    verifies unchanged.
    Modification/removal of an earlier revision or an invalid confirmation tag
    quarantines the claim; file contents never silently gain authority or
    trigger a rewrite.
28. **One complete disposable Memory projection.** A separate SQLite
    projection under Allbert Home represents all valid claim streams and can be
    rebuilt from Markdown; existing Key Custody verifies native authority,
    manual-import, and Forget domains and carries no claim content or lifecycle
    state. One auto-provisioned per-Home 32-byte integrity secret uses a fixed
    reference plus explicit version; a Settings master-key rotation rewraps it
    rather than changing material, referenced old versions remain readable, and
    a missing referenced key fails closed instead of auto-regenerating. It is
    not the canonical Repo, is not the Search database, and is not a generic
    projection framework.
29. **Conversations originate consolidation proposals.** In v1.3 only verified
    operator-authored conversation turns can originate a consolidation-proposed
    fact. Existing explicit remember/update actions, confirmed manual imports,
    and exact-digest legacy-draft confirmations remain additive claim origins
    with typed actor/action provenance; they are not relabeled as conversation
    extraction.
    Assistant replies may provide a tight, transient same-conversation
    disambiguation window but never originate, corroborate, strengthen, or
    persist as proposal evidence. Traces/objectives may contribute bounded
    correlation IDs, never facts.
30. **Proposals minimize copied content.** An ordinary durable proposal stores
    the normalized proposed claim plus typed source IDs, source digest, trust
    classification, and extraction version. Review fetches a bounded redacted
    source excerpt. Protected third-party/minor/dependent proposals store only
    a redacted stub before individual review; secrets are dropped. After an
    accepted Keep/Edit appends the claim revision, the proposal is reduced to
    content-free result/provenance identifiers rather than retaining a second
    copy of the claim. Review excerpts are transient and never durably cached.
31. **Review is frozen, partially successful, and crash-resumable.** Bulk/
    digest review freezes proposal revision IDs/digests. Valid items apply;
    stale/ineligible items skip with durable per-item results. Before appending
    a claim, existing proposal state records an `applying` phase keyed by a
    deterministic transition ID. The ID binds proposal revision/digest,
    operator/namespace, and the normalized review-decision payload digest,
    including edited claim, validity, and relationship fields. The claim append
    embeds that ID. Until append succeeds, the existing applying row retains
    that frozen normalized decision payload so startup can retry the same edit;
    it is scrubbed with the proposal immediately after the canonical append.
    Retry detects the identical committed append, then finishes proposal
    scrubbing and the content-free result. If no append exists, retry first
    repeats Corpus source/grant/digest authorization; an already-ineligible
    item becomes stale instead of being kept. This avoids duplicating a
    revision or accepting a differently edited/stale retry. Protected proposals are
    never part of Keep All. Rejecting unchanged evidence suppresses repeat
    proposals. Frozen batch/result records contain ids, digests, and outcomes,
    not copied claim or excerpt content. All claim mutations use one
    `Memory.Claims.append(claim_id, expected_tail_digest, transition)` boundary:
    a per-claim lock rechecks the tail and Forget tombstone, fails stale writers,
    and commits a complete same-directory temp file with file sync, atomic
    rename, and directory sync. This is a storage function, not a new process.
32. **Conservative defaults.** `memory.consolidation.enabled` defaults false
    until the Memory consumer's eligible source-class/origin grant. The managed cadence is weekly, initial
    lookback 30 days, at most 20 new proposals per run, and at most 50 pending.
    The registered managed action uses additive `:memory_propose`: the current
    verified collection grant authorizes inert proposal writes without a
    per-run prompt, but cannot keep/edit/archive/restore/Forget a claim. Those
    remain separate operator actions, and Forget remains destructively
    confirmed.
33. **Deterministic safety, bounded local assistance.** Deterministic policy,
    secret, identity, normalization, conflict, and suppression gates remain
    authoritative. A configured local model may advise extraction within
    bounds. If absent/failing, use the deterministic high-confidence subset or
    abstain; never broaden or fall back to a hosted model.
34. **Review surfaces share actions.** Web and CLI provide full proposal and
    history review. TUI may show counts and invoke the same per-item typed
    actions, but does not gain a separate review engine. DMs notify/link and do
    not offer bulk Keep.
35. **Archive and Forget are different.** The existing delete-memory action
    remains a compatibility alias for reversible append-only archive/retire.
    A separately confirmed Forget writes the canonical content-free suppression
    tombstone **first** at `<memory_root>/tombstones/<claim_id>.md`, where
    `memory_root` is resolved through `AllbertAssist.Paths`, then idempotently
    removes the claim stream, every matching content-bearing proposal/review/
    batch or legacy-draft/applying payload and artifact, and the disposable
    Memory projection generation. Pending and completed tombstones immediately
    deny retrieval, claim append, and reproposal; startup/retry reconciles
    incomplete phases.
    The tombstone contains only `claim_id`, time, actor, a closed safe reason code, normalizer
    version, non-secret key reference/version, keyed token, and phase. Forget is
    the explicit operator-authorized exception to immutability.
36. **Forget is bounded honestly — including about the conversation.** The
    pre-confirmation disclosure states that Forget **does not delete the
    originating conversation**, which remains canonical and remains findable
    through Search, and it names the ADR 0093 canonical delete action as the
    further step for an operator who wants both. Shipping conversation search
    in the same release makes this the boundary an operator is most likely to
    misread; "Forget" must not be heard as "erase". Forget guarantees logical
    inaccessibility,
    prompt/proposal suppression, canonical claim removal, and replacement of
    the disposable Memory generation from the remaining claims. Repo
    secure-delete and WAL checkpoint/truncation are best effort because locks,
    free pages, filesystem behavior, and open readers can retain unreachable
    bytes. The claim excludes unreachable SQLite pages or untruncated WAL,
    backups, exported copies, snapshots, filesystem remnants, and storage
    forensics. Suppression
    uses a per-Home domain-separated HMAC key through existing Settings Secrets/
    Key Custody; no new crypto service is built. Exact forgotten content stays
    suppressed while a genuinely new value for the same predicate may be
    proposed.
37. **Key-bound portability is deliberately narrow.** The redacted portability
    envelope exports neither suppression tokens nor key material and remains
    dry-run on import. A same-Home full restore preserves suppression only when
    tombstones and the existing key survive together. A copied tombstone with a
    missing/mismatched key pauses proposal-producing actions with
    `tombstone_key_unavailable`; a fresh Home/new key has no cross-Home
    suppression guarantee. Any copied tagged claim chain with a missing source
    key follows LD 27's exact-whole-chain quarantine-and-reconfirm path; do not
    add a key-export subsystem.
38. **Retrieval stays lexical and prompt scope stays narrow.** No embeddings or
    learned ranking. The direct-answer/vision prompt seam remains the v1.3
    proof target. Search matches never enter memory or prompt context
    automatically.
39. **STM remains volatile.** The existing working-memory scratchpad receives
    a documented sensitive-data contract and nested patch semantics without
    becoming a persistent store or consolidation source.

### Search Central decisions

40. **One central engine.** `AllbertAssist.Search` owns the typed query contract
    and registered actions. Web/TUI/CLI/DM surfaces render and dispatch; they do
    not parse FTS, rank, authorize sources, or query projection storage.
41. **One dedicated disposable database.** Search uses a separate
    `<ALLBERT_HOME>/projections/search/` generation family (LD 84), excluded from
    authoritative backup/export. One content-storing FTS5 table is paired with
    one minimal content-free document/locator table whose integer rowid, unique
    `(source_type, source_id)`, source version/digest, fixed-unit timestamp,
    author/origin/surface/thread/trust/source-class fields, and projection
    revisions make typed filters, total ordering, upsert/delete, and one-to-one
    integrity checks implementable with M1-frozen B-tree indexes. The FTS table
    holds only redacted searchable text at the shared rowid; locator, FTS, and
    control revision update in one Search transaction. This is not a duplicate
    content table, Ecto domain, or external-content mirror/trigger. Canonical
    conversation rows are never attached as FTS content.
42. **Visible conversation content only.** Index verified operator messages and
    visible assistant replies, labeled by author/trust/surface/thread. Exclude
    system prompts, hidden tool/model payloads, raw action logs, and secrets.
    Redaction occurs before projection write.
43. **Typed bounded query grammar.** Support words, quoted phrases, explicit
    prefixes, and typed filters; never expose raw `MATCH` syntax.
    `unicode61 remove_diacritics 2` and exact total-order tuples are the v1.3
    contract: relevance `(bm25 ASC, timestamp_us DESC, source_id ASC)`, newest
    `(timestamp_us DESC, source_id ASC)`, oldest `(timestamp_us ASC, source_id
    ASC)`, with Unix-microsecond storage and UTC-microsecond DTO output.
    Default limit is 20, maximum 100, with bounded snippets.
44. **No semantic-search extras.** No substring/trigram/fuzzy index,
    embeddings, vectors, learned reranking, hidden recency blend, autonomous
    model search, or surface-specific search logic. Explicit “summarize these
    results” is a later action in the ordinary provider/egress policy, not part
    of lexical Search.
45. **Reauthorize every result.** FTS yields bounded candidate IDs/rank only.
    Corpus batch-rehydrates current rows and rechecks operator, source
    eligibility, scope, and digest before snippets/results are returned.
    Mismatch omits the candidate, requests repair, and reports freshness; it is
    never shown with a warning. Search overfetches/rechecks in bounded batches
    until the requested page is full, projection EOF is reached, or the M1 scan
    budget is exhausted; results report scanned/filtered counts and a typed
    incomplete flag.
46. **Verified generations, no canonical fallback.** Rebuild a temporary
    projection, verify it, require `wal_checkpoint(TRUNCATE)` to return
    `busy = 0`, and self-contained-reopen/integrity-query check with no required
    sidecar. The sole projection owner then stops new admissions, drains bounded
    readers, closes builder and serving handles, atomically swaps current/
    previous, opens/verifies the new current, and only then re-admits calls; a
    drain timeout or reopen failure leaves/reopens the previous verified
    generation. No renamed live SQLite handle survives promotion. Repair/rebuild metadata
    persists two independent Corpus boundaries—the append-only source high-
    water and the `eligibility_epoch` advanced by deletion, visibility,
    principal/remap, Search-grant, or E2EE eligibility shrink/move—plus starting
    projection revision and redactor/schema/tokenizer versions. Sweep only the
    starting population; incompatible eligibility/configuration change invalidates/restarts a
    builder, and purge invalidates every resumable builder/cursor before
    recovery. Serve the last verified generation with `indexed_through` while
    rebuilding. With no verified generation return `search_not_ready`; never
    live-scan canonical tables.
47. **Generation/revision-bound pagination.** Every committed incremental
    mutation advances a monotonic projection revision. A stable cursor includes
    generation, projection revision, an opaque
    `allbert.search.cursor.v1` keyed binding
    of normalized request/scope/order, non-secret key ref/version, and the last **scanned** rank tuple, not
    merely the last returned result. The cursor payload/MAC uses the same small
    existing Key Custody helper as query-chain confirmation and exposes no plain
    query/filter digest. A generation or revision mismatch returns restart-
    required rather than mixing pages after BM25 statistics change. Schema/
    tokenizer/redactor-version changes trigger rebuild, not a migration maze.
48. **Surface privacy.** Local Web/TUI/CLI default to all eligible retained
    history. A verified mapped operator DM defaults to its same
    channel/thread, defined as canonical-thread equality **and** exact current
    origin tuple `(owner_scope, channel, receiver_account_ref,
    provider_thread_key)` equality on each message—not thread membership alone;
    cross-surface results require explicit confirmation. One
    approval authorizes exactly one normalized query/cursor chain, expires
    exactly 300 seconds after approval, and covers its pagination without
    reprompt. Durable
    confirmation state contains scope, expiry, request IDs, safe filter shape,
    non-secret key ref/version,
    and an `allbert.search.query-scope.v1` keyed request binding but never the raw query,
    snippets, operands, or a plain query/filter digest. Audit summaries omit
    even the keyed binding. Continuation must match the opaque binding. One
    registered `authorize_search_query_scope` action is `resumable?: true` and
    explicitly added to `ApproveConfirmation`'s generic-resume allowlist. Its
    resume params contain only principal/origin/scope/expiry/safe shape and keyed
    binding; it returns `query_resubmit_required` and writes no second grant
    store. `query_chain_id` is the resolved confirmation id. Search recomputes
    the binding from the transient client resubmission; no query enters
    `resume_params_ref`.
    Search-result rendering turns carry a typed result marker and are excluded
    from projection so snippets are not recursively reindexed or laundered into
    a later same-DM default query.
49. **Freshness without blocking writes.** Successful canonical writes mark
    Search dirty and call the generic `Jobs.Managed.kick/2` seam for the one
    `search-index` managed entry. Jobs owns coalescing, due-state, pause
    semantics, Runner execution, and run history; there is no Search wakeup
    process. A paused entry stays paused while dirty state survives, and resume
    or hourly reconcile catches up. A dirty kick coalesces for 60 seconds and
    the normal freshness SLO is 90 seconds; canonical writes never wait for
    Search.
50. **Deletion and pruning stay distinct — and deletion is not a Search
    decision.** Canonical conversations remain indefinitely until an explicit
    confirmed delete, which is owned by **LD 79 and ADR 0093** because deleting
    the operator's history is a destructive capability over canonical user data
    built by the Corpus workstream. Search consumes it only as a reconciliation
    input: the delete commits canonically first, Corpus reports the source
    ineligible immediately so query-time reauthorization covers the repair
    interval, and the action marks Search dirty. Search maintenance may prune
    stale projection rows and obsolete generations, never canonical history;
    automatic retention is not in scope. The historical full specification below
    is retained for continuity and is normative through LD 79/ADR 0093:
    One registered
    Conversations action accepts `target_kind: message | thread`, previews the
    exact target owned by the verified canonical user/operator and its
    conversation-owned cascade, requires destructive confirmation,
    commits canonically first, and returns a content-free idempotent typed
    result. The server preview binds message/thread rows and the ordered exact
    channel/message-reference identities, versions, and content digests that
    the Repo transaction will cascade; confirmation stores only safe target
    shape, verified user/operator id, non-secret key ref/version, plus an
    `allbert.conversations.delete-preview.v1` HMAC of that ordered cascade plus
    versioned known-core survivor/blocker counts and disclosure version, never message
    content or plain content digests. An immediate canonical Repo transaction
    re-resolves that exact set and bound count/disclosure vector before mutation
    so concurrent expansion/dependency drift fails stale.
    A message delete sets `thread.last_message_at` to surviving-message
    `MAX(inserted_at)`, or the thread's own `inserted_at` when none survive, and
    retains/discloses the thread title even if it was derived from that message,
    because no title-provenance field exists. A thread delete removes its
    canonical title with the thread row and blocks while an active objective/
    job, nonterminal fan-out, or open
    workspace still depends on the thread until the operator finishes,
    cancels, or rehomes it; approval rechecks those blockers in the same
    immediate transaction as deletion. `delete_conversation_content` is `resumable?: true` and is
    explicitly added to `ApproveConfirmation`'s generic-resume allowlist. The
    already-durable pending confirmation id plus bound preview is its retry key:
    after a post-commit crash, rerunning that same pending approval sees the
    target absent, returns `already_deleted`, and re-drives idempotent reconcile;
    an ordinary fresh absent request returns `not_found`. No nonexistent Repo
    receipt or new deletion ledger is invented. Message delete removes only the
    message and conversation-owned references; thread delete cascades only the
    conversation thread/messages/channel references. Historical Objectives,
    Jobs/runs, StockSage records, channel events/deliveries, traces, artifacts,
    and closed workspace records survive as separately governed unavailable-
    source provenance. The preview uses a best-effort inventory of known core
    schemas—never a universal plugin-data claim—and discloses counts plus the
    fact that those records, separately kept Memory claims, provider/server
    copies, backups, and exports are not deleted. Pending Memory
    proposal/legacy-draft payloads derived only from the deleted source are
    scrubbed to content-free stale outcomes. Search maintenance may prune stale
    projection rows/generations, not canonical history; automatic retention is
    not in scope.
51. **Secure purge is manual and narrowly claimed.** A confirmed action first
    requires affected canonical content to be ineligible/deleted or the
    affected Search source class/feature to be disabled, so ingestion cannot
    restore it. It uses FTS/core secure-delete for new deletes, but replaces any
    generation that may contain historical tombstoned terms from the currently
    eligible canonical set and deletes obsolete generations wholesale. It
    covers every Search-owned current, previous, build-temp, failed, retired,
    and pending-prune DB plus `-wal`/`-shm`; no openable or startup-recoverable
    managed generation may retain the fixture text. The registered action is
    `purge_search_projection`, is `resumable?: true`, and is explicitly added
    to the generic-resume allowlist with content-free safe parameters. A
    `allbert.search.purge-preview.v1` and recorded non-secret key ref/version
    bind its safe target/file scope. A control
    record outside every generation progresses through `pending`,
    `connections_closed`, `files_replaced`, `verified`, and `complete`; while
    incomplete, every other Search operation returns
    `search_purge_in_progress`, managed kicks coalesce without reopening files,
    and pause state is preserved. Retry count and safe last-error code are
    diagnostic fields, not phases. The claim excludes backups, filesystem
    remnants, and hardware erasure.
52. **Trace-safe query audit.** Raw query text, snippets, and filter operand
    values never enter traces, audits, validation errors, job action logs, or
    durable confirmation/resume parameters. Add one optional action-defined
    Runner summary callback that runs **before** `action_requested` and also
    controls completed/error summaries. Callback failure omits params/result
    rather than falling back to raw values. Its safe fields are action name,
    auth scope, filter kinds/count, sort/limit, result count, generation/
    revision/freshness, latency, query-chain/correlation IDs, and request IDs.
    Query and filter digests, including the keyed confirmation binding, are not
    trace fields. Existing actions retain current behavior.
53. **Runtime capability proof.** Each native artifact asserts SQLite
    >= 3.42 and `ENABLE_FTS5` before enabling Search, then proves tokenizer,
    phrase/prefix behavior, BM25, WAL, integrity, and FTS secure-delete on the
    shipped runtime.

### Managed-job decisions

54. **Existing scheduler, small ownership seam.** `AllbertAssist.Jobs.Managed`
    owns stable managed identity, action target/invariant parameters, desired
    cadence/pause policy, dirty kicks, and reconcile diagnostics. Jobs still
    owns scheduling, coalescing, pause semantics, Runner dispatch, and run
    history; Memory/Search own cursors, leases, and projection state. Each spec's
    stable managed identity is itself the deterministic reserved existing-row
    name (`memory-index-rebuild`, `memory-consolidation`, `search-index`,
    `search-maintain`, or `search-rebuild`) and resolves by the existing unique
    `(user_id, name)` key; managed identity is not a second uniqueness system.
    The Home is implicit in its Repo and reconcile uses the canonical local-
    operator `user_id`; plan shorthand `(Home, managed_identity)` means that
    concrete `(Home Repo, user_id, name)` key.
55. **Visible and operator-controllable.** Exactly one managed entry per
    `(Home, managed_identity)` is visible and manually triggerable in normal
    Jobs surfaces; different Memory/Search identities coexist. Operators may
    adjust allowed cadence or pause an entry. Jobs has no generic delete path
    today, and this release does not add one merely to prohibit deletion; any
    future delete path must reject a live managed spec with feature-disable
    guidance. A disabled feature retains the one entry plus its stored operator
    cadence/pause intent, gates effective admission/due state as disabled, and
    restores only that stored intent when re-enabled; no deletion tombstone is
    needed. If an operator-created row
    already owns the reserved name, or invariant managed metadata differs,
    reconcile reports `managed_name_conflict`/degraded state and never
    overwrites, renames, or duplicates it. The sole adoption exception is an
    existing `memory-index-rebuild` row with exact legacy
    `template_name: memory-index-rebuild`,
    `managed_by: memory.review_cadence`, compatible legacy target, and canonical
    local operator. Reconcile preserves id/history/cadence/pause while
    atomically installing the new owner/spec metadata and projection target;
    template-only or ambiguous rows conflict.
56. **Minimal Search job set.**
    - `search-index`: coalesced dirty kick plus hourly reconciliation through
      one registered management action; no-op runs write no projection work.
    - `search-maintain`: bounded weekly integrity, stale-row/generation prune,
      and incremental merge.
    - `search-rebuild`: on-demand/manual/resumable generation rebuild, not a
      periodic full rebuild. A nil due time is an active manual schedule, not a
      paused row. Bootstrap/reconcile kicks it when no compatible verified
      generation exists (including restore or schema/tokenizer/redactor policy
      incompatibility); incomplete runs become due again with bounded
      recoverable backoff, while a missing runtime capability reports degraded
      state rather than retrying forever.
    Secure purge is not recurring. Memory additionally retains exactly one
    `memory-index-rebuild` identity retargeted at projection rebuild and one
    separately managed weekly consolidation identity that remains disabled
    until its grant.
57. **Authority remains action-backed.** Search queries are read-only.
    Managed projection work uses `:search_manage` through registered actions
    and the Runner; job IDs, objective IDs, and schedule metadata confer no
    authority.
### Third-pass readiness decisions (operator-signed 2026-07-28)

58. **Legacy memory subsystems are absorbed, not left beside the new model —
    and absorption is behavioral, not deletion.** The second pass designed the
    new memory world without dispositioning the old one, leaving two indexes,
    two suggestion surfaces, two search entry points, and one setting that
    contradicts the consent boundary. v1.3 retires each into the new model
    (table under Current Code State). Retirement is executed as **compatibility
    absorption**: every existing action name, setting key, and request shape
    keeps responding and routes into the new model, and the old store/job stops
    being a second authority. Nothing public is deleted, because deletion would
    break LD 2 and the v1.0 Tier-2 freeze. The `delete_memory_entry` alias is
    the precedent this follows.
59. **Conversation consolidation carries mechanically grounded span
    provenance.** Every semantic field of a consolidation proposal must be
    derivable from recorded operator-authored source spans. Its evidence stores
    canonical source ID/digest, UTF-8 byte start/end, raw-span digest,
    normalized value, and a small versioned deterministic transform kind.
    Bounded same-conversation assistant context may resolve deixis only to
    another operator-authored span and can never supply a field value; if the
    value exists only in assistant text, extraction abstains. Explicit
    remember/update, manual import, and legacy-draft paths use typed action
    provenance instead of inventing spans. This
    replaces the unprovable "no corroboration weight" formulation: an opaque
    local model cannot be shown to have ignored assistant text in its prompt,
    but span coverage is checkable mechanically, so the invariant becomes a
    real gate instead of an assertion.
60. **Search defaults on for local surfaces; Memory collection does not.** The
    key is **`search.enabled`, default true** — the `search` settings namespace
    is currently unused, and `active_memory.enabled` / `artifacts.enabled` are
    the naming precedent. It is the single Search feature setting of ADR 0092
    §7: one switch governs both query availability and the ordinary local
    managed set (`search-index`, `search-maintain`, `search-rebuild`), so
    "feature disabled" is unambiguous and the purge precondition remains
    testable. Disabling stops indexing and querying and leaves the projection
    on disk; removing bytes is the separate confirmed purge. A fresh Home
    therefore indexes local Web/CLI/TUI history by default. Mapped operator
    DMs require one origin-scoped grant per consumer covering current/future
    verified 1:1 mappings, and E2EE origins require an additional overlay. The
    asymmetry
    with `memory.consolidation.enabled` (default false) is deliberate and must
    be stated wherever both appear: Search is local, read-only, produces no
    proposals, writes nothing into any prompt, and is deletable/rebuildable,
    whereas collection produces durable candidate facts about the operator.
61. **Each database has one named writer owner.** The canonical Repo, the
    Memory projection, and the Search projection are three separate SQLite
    databases with three separate single-writer processes. `pool_size: 1`
    (`config/runtime.exs:49`, `config/dev.exs:31`) is the canonical Repo's
    v1.1-hardened posture and is unchanged. Each projection process owns its
    own connection and is the only writer to its file; no cross-database
    transaction is claimed. The plan names, for each database, its writer
    owner, its supervision parent, and what a non-attached one-shot CLI path
    may do with it: attach to the daemon or fail closed with guidance. Surfaces
    do not open projection files directly. The
    v1.1 lesson was that resource ownership — not fan-out logic — was the
    systemic root cause, so ownership is stated before code.
62. **One shared promote-protocol helper — `AllbertAssist.Projection.
    PromoteProtocol` — which is not a projection framework.** Memory and
    Search both need checkpoint `busy = 0` → close →
    self-contained reopen → integrity/query proof → bounded owner quiescence/
    serving-handle close → atomic same-filesystem promote → verified reopen →
    retain previous. Implementing that subtle sequence twice invites
    divergence in exactly the code whose failure mode is silent data loss. One
    small private helper owns the sequence; each domain keeps its own schema,
    verification predicates, generation metadata, and rebuild source. The
    Complexity Budget's "no generic projection framework" bar excludes this
    helper explicitly so a later reviewer does not delete it as scope creep.
63. **Stage closeout is distinct from triad archive.** This triad covers two
    tags, so it cannot move to `docs/plans/archives/` when v1.2.5 closes. At
    v1.2.5 closeout the stage is marked shipped **in place** with its evidence,
    roadmap item 7 flips to shipped, its backlog entries are dispositioned, and
    the triad stays on the docs-gate active-plan list. The triad archives once,
    after v1.3.0 is published and accepted. This is the one place the two-stage
    plan diverges from the standard lifecycle, and it is recorded rather than
    discovered at closeout.

### Final readiness decisions (operator-signed 2026-07-28)

64. **Grant and invalidation matrices are explicit.** LD 21/22/60 define
    origin-scoped grants and distinguish canonical ineligibility from
    Memory-only and Search-only revocation. Jobs and surfaces consume that one
    policy; they do not infer effects from a generic "consent revoked" event.
65. **Memory mutations are fail-closed across stores.** Review uses a
    deterministic transition ID and resumable applying phase. Forget writes a
    pending tombstone first. A signed, expected-tail, per-claim serialized append
    is the Markdown linearization point. Canonical claim state is rechecked
    before bounded projection candidates enter a prompt, so a crash between
    Markdown, Repo, and projection effects cannot expose, forge, overwrite, or
    duplicate a stale claim.
66. **Generation and revision are different.** Incremental Memory/Search
    commits advance a projection revision. Only verified rebuild/schema-policy
    replacement promotes a generation through the shared helper. Recovery may
    replay an idempotent revision but may never use a generation flip as a
    substitute for a commit protocol.
67. **Active-store deletion claims match SQLite reality.** Forget provides
    immediate logical denial and rebuilds disposable derived state; Repo
    secure-delete/checkpoint is bounded best effort. Tests prove the stated
    boundary rather than requiring routine whole-Repo VACUUM or a new erasure
    subsystem.
68. **Compatibility is per caller, not by slogan.** The LD 58 matrix freezes
    each public action, setting, job identity, producer, fallback, and result
    shape. Compatibility paths may read canonical Markdown but never preserve
    a second compiled index or a direct draft-to-file writer.
69. **Search repair is policy-epoch bound.** Repair/rebuild records its starting
    population, source high-water, eligibility epoch, and configuration
    versions; purge or incompatible eligibility/configuration drift
    invalidates resumable state. Post-authorization filtering refills pages in
    bounded batches and cursors advance after the last scanned tuple.
70. **DM elevation is one query chain.** One explicit approval covers a single
    normalized query and its cursor chain for exactly 300 seconds, with no
    pagination reprompt and no durable raw query/snippet. A stale generation/
    revision cursor may restart page one under the same still-valid exact-
    request binding; a changed scope/request binding or expiry requires a new
    approval.
71. **Canonical delete has one additive interface.** One registered,
    destructively confirmed action accepts `target_kind: message | thread` and
    preserves narrow-copy disclosure, exact conversation-owned cascade, and
    crash-safe idempotency by using the pending confirmation id and its bound
    preview as the retry key. It adds the action to the existing explicit
    confirmation-resume allowlist and adds no receipt table.
72. **Dirty wakeups stay inside Jobs.** Corpus writers only mark consumer work
    dirty and kick an existing managed identity. Pause, coalescing, run history,
    and Runner authority remain in Jobs; Search/Memory add no wakeup processes.
73. **Projection ownership is closed before parallel work.** M3 owns the small
    shared promote helper and its contract rejoin; M6 consumes it after that
    rejoin. Projection-dependent CLI commands attach or fail closed, and each
    projection keeps one daemon-owned writer.
74. **Key-bound history remains portable without key export.** Native authority,
    manual confirmations, and suppression tombstones record normalizer/key
    versions. Missing destination keys quarantine exact content and permit one
    deliberate exact-whole-chain re-confirmation; no key-copy feature or hidden
    history rewrite is added.
75. **Promotion consumes evidence, never rebuilds.** The tag workflow's
    downstream no-build qualification jobs consume its staged archives and
    upload attempt-qualified, digest-bound qualification evidence into that
    same source run, which then ends before signing/publication. Manifests bind
    workflow-run attempt plus immutable artifact IDs/names; successful builders
    do not rerun merely to retry qualification. A
    separately dispatched promotion runs at the exact product-tag ref and
    receives the same tag, source run ID/attempt, staged digest-manifest artifact
    ID/digest, and qualification-evidence artifact ID/digest. It authenticates
    repository, workflow, `push` event, successful conclusion, tag SHA, and
    attempt before accepting artifacts. The environment gate is job-level and
    passes before a runner or environment secrets are available; after approval
    the job downloads, re-verifies, and publishes only those bytes. A partial
    promotion skips byte-identical existing assets, uploads only missing assets,
    and stops on any differing asset; it never clobbers. Staging/evidence
    retention is 30 days and any selected native artifact whose GitHub
    `created_at` is older than 21 days is rejected,
    preserving a qualification buffer. Expiry, missing evidence, byte/source
    fixes, or immutable-tag conflicts stop for operator disposition. The
    protected dispatch also requires the operator to type `confirmed` after a
    real-provider turn through the exact macOS archive; hosted CI retains no
    provider credential. M0.c3 owns the v1.2.6 in-place stage closeout; M9.b
    owns final triad archive.
76. **Per-message identity evidence closes the Corpus boundary.** Remote source
    eligibility requires an exact message-to-thread-ref binding plus immutable
    principal digest/version. Legacy external rows are backfilled only when one
    mapping is provable; ambiguous rows remain `legacy_principal_unverified` and
    ineligible. Local authenticated rows need no synthetic provider reference.
77. **Recovery has an existing owner and order.** `Memory.Projection` loads and
    verifies tombstone suppression before becoming retrieval-ready, then kicks
    the existing managed Memory rebuild/reconcile action to resume applying rows,
    tombstone phases, legacy-draft scrubs, and projection repair. No coordinator,
    private retry loop, or new managed identity is added.
78. **Managed admission and completion preserve concurrent intent.** Scheduled,
    manual, dirty-kick, and recovery triggers all enter the existing Jobs
    admission transaction, which counts `queued`, `running`, and
    `needs_confirmation` as overlap. A run records the exact due/dirty value it
    claimed. Completion reloads the job and advances or clears only that
    claimed value, preserving a newer kick, operator pause, or cadence edit;
    typed continuation scheduling is merged after action completion rather than
    overwritten by the generic completion update. This is the lost-wakeup rule
    for every managed entry, not Search-specific orchestration.

### Fifth-pass readiness decisions (operator-signed 2026-07-28)

79. **Canonical conversation deletion is Corpus-owned and has its own ADR.**
    The fifth pass found `delete_conversation_content` — a destructive
    capability over canonical user data, with cascade scope, live-dependency
    blockers, survivor disclosure, and crash-safe idempotency — specified
    inside ADR 0092 (Search Central) and filed under Search Central decisions,
    while being built in M2 by WS-C as a Conversations action. **ADR 0093**
    now owns it; ADR 0092 §3 keeps only the reconciliation-input relationship.
    The contract is unchanged: one registered destructively confirmed action,
    bound preview re-resolved inside the deletion transaction, exact
    conversation-owned cascade, live-dependency blocking, best-effort
    known-core survivor disclosure, `already_deleted`/`not_found` idempotency
    without a receipt table, and no deletion of separately kept Memory claims.
    Deletion and Memory Forget are a deliberate pair — Forget removes what
    Allbert concluded, deletion removes what was said — and each disclosure
    names the other as the further step.

### M1 calibration decisions (frozen 2026-07-29)

80. **Corpus contracts are closed and count-bounded.** `SourceEnvelope` schema
    version `1` is a typed struct, not a free map. Required fields are
    `source_type: :conversation`, string `source_id`, `thread_id`, `operator_id`,
    `user_id`, `principal_digest`, `role`, `author`, `trust`, `origin_scope`,
    `origin_overlays`, `surface`, `thread_kind`, `content`, `content_digest`,
    UTC-microsecond `inserted_at`, integer `source_version`, and nullable typed
    `origin` and `trace_refs`. `role` is `"user" | "assistant"`; `author` is
    `:operator | :assistant`; `trust` is
    `:private_operator`; base `origin_scope` is `:local_operator |
    :mapped_operator_dm` and `origin_overlays` is `[] | [:e2ee_operator]`, so
    LD 21's E2EE overlay never erases the transport origin; digest
    strings are `sha256:` plus 64 lower-case hex characters. `origin` is nil for
    local sources or `%{thread_channel_ref_id, owner_scope, channel,
    receiver_account_ref, provider_thread_key, origin_principal_digest,
    principal_normalizer_version}` for remote sources. `trace_refs` contains at
    most `4` opaque references, each at most `128` UTF-8 bytes. The envelope
    carries no grant.

    `snapshot/2` returns opaque schema `1` state bound to operator, source
    policy `%{consumer: :memory | :search, origin_scope: :local_operator |
    :mapped_operator_dm, e2ee?: boolean}`, inclusive high-water
    `(inserted_at, id)`, and integer
    `eligibility_epoch`. `page/3` is ascending keyset order on that tuple,
    defaults to `200` rows, and rejects limits above `500`; its cursor binds the
    snapshot and last **scanned** canonical tuple, including an ineligible row
    omitted from the returned envelopes. Rehydration accepts at most `100` unique
    refs and returns one ordered typed result per ref—an envelope or one of
    `:missing | :deleted | :ineligible | :scope_denied | :digest_mismatch |
    :legacy_principal_unverified | :legacy_origin_unverified`. Conversation
    context is the source plus at most `4` preceding and `4` following messages
    in the same canonical thread, at most `9` messages and `32_768` UTF-8 bytes;
    it drops farthest context first at grapheme boundaries and reports
    `truncated: true`. If the authoritative source message alone exceeds the
    byte cap, the read returns `:source_context_too_large`; canonical message
    content itself is never silently truncated in an envelope.

81. **Search bounds fit the public maximum without an unbounded refill.** One
    candidate batch is `100`; one page scans at most `500` candidates across at
    most `5` batches, including a public `limit: 100` request. Default result
    limit remains `20`, maximum `100`. Every result has at most one snippet;
    `search.snippet.max_bytes` defaults to `320`, accepts `64..1024`, and cuts at
    a UTF-8 grapheme boundary with an omission marker inside the byte limit.
    Query text accepts at most `1_024` UTF-8 bytes, `16` lexical clauses, one
    phrase of at most `12` tokens, and `8` typed filters; excess is a typed
    validation error, not truncation. Cross-surface mapped-DM authorization
    expires exactly `300` seconds after approval and no cursor extends it.
    Projection promotion stops admissions and drains admitted readers for at
    most `2_000` milliseconds before aborting the swap.

    The schema-1 query is `%{query: String.t(), order: :relevance | :newest |
    :oldest, limit: 1..100, cursor: nil | String.t(), filters: map(),
    query_chain_id: nil | String.t()}`. Closed filter keys are `authors`
    (`[:operator | :assistant]`), `surfaces` (at most `8` strings), `thread_ids`
    (at most `8` strings), nullable UTC-microsecond `after`/`before`, base
    `origin_scope`, and nullable boolean `e2ee`; unknown keys fail validation.
    The parser accepts Unicode word terms, double-quoted phrases, and a trailing
    `*` only on a word prefix of at least `2` Unicode codepoints. Operators,
    parentheses, column selectors, embedded `*`, and raw FTS punctuation fail
    validation. Filters are ANDed; values within one list are ORed.

    The schema-1 page result is `%{results, next_cursor, generation_id,
    projection_revision, indexed_through, freshness_ms, scanned_count,
    filtered_count, incomplete, incomplete_reason}`. Each result is
    `%{optional(:source_type) => :conversation, source_id, thread_id, author, trust, surface,
    timestamp, snippet, score, generation_id, projection_revision}`. Closed
    query errors are `:invalid_query | :invalid_filter | :invalid_limit |
    :search_disabled | :search_not_ready | :search_changed | :scope_denied |
    :query_confirmation_required | :query_resubmit_required |
    :query_chain_expired`. Cursors are
    `allbert.search.cursor.v1:<base64url-payload>.<base64url-tag>` and bind the
    final scanned tuple without plain query/filter material.

    The locator indexes are exactly unique `(source_type, source_id)`,
    `(timestamp_us DESC, source_id ASC)`, `(timestamp_us ASC, source_id ASC)`,
    `(thread_id, timestamp_us DESC, source_id ASC)`, `(author, timestamp_us DESC,
    source_id ASC)`, `(surface, timestamp_us DESC, source_id ASC)`, and
    `(origin_scope, e2ee, timestamp_us DESC, source_id ASC)`, where
    `timestamp_us` is Unix microseconds. Compound filters may
    use bounded locator intersection; v1.3 adds no index-per-filter-combination.
    The schema-1 locator columns are `fts_rowid`, `source_type`, `source_id`,
    `thread_id`, `author`, `trust`, `surface`, `thread_kind`, `origin_scope`,
    `e2ee`, nullable remote origin-tuple fields, `timestamp_us`,
    `source_version`, `content_digest`, compatibility versions, and immutable
    `first_projected_revision`. `search_fts` stores only `searchable_text` at the
    shared rowid; one-row `generation_meta` mirrors LD 84. ADR 0092 §2 owns the
    exact SQL types/checks.

82. **Quality and performance have numeric release floors.** The committed
    hand-authored Memory fixture pins optional advisory extraction to
    `local_ollama/llama3.2:3b` on a local endpoint; no hosted fallback is
    permitted. Its complete field-transform allowlist is `identity_v1`,
    `trim_ascii_whitespace_v1`, `ascii_lower_v1`, `operator_pronoun_v1`, and
    `explicit_iso8601_date_v1`; it contains no inferred synonym/date/number
    transform. Micro-averaged eligible-proposal precision must be `>= 0.90`,
    eligible-fact recall `>= 0.80`, and required abstention over assistant-only,
    trace-only, ambiguous, question, ephemeral, and hard-drop rows is `>= 0.95`
    over `20` frozen rows (at most one miss).
    Temporal-update correctness is `4/4`, protected secret/financial drops are
    `2/2` without value storage, and protected individual-review routing is
    `2/2`. The eligible denominator is the fixture's `14` fact/update rows. A
    true positive requires the expected decision plus exact normalized fields
    recoverable through the recorded allowlisted spans; every ordinary proposal
    on a non-eligible row is a false positive. Precision is `TP / (TP + FP)`,
    recall is `TP / 14`; protected-routing stubs are neither TP nor FP.

    Active Memory keeps the existing direct-answer/vision budget of `8_000`
    UTF-8 bytes, `top_k: 5`, and `2_048`-byte maximum chunk. At a warmed single-
    caller projection of `10_000` current claims, canonical revalidation plus
    prompt selection must be p95 `<= 75 ms` and p99 `<= 250 ms` across `200`
    fixture-derived queries. At a warmed `25_000`-message Search generation,
    every document averaging at least `256` UTF-8 bytes across at least `250`
    threads, query plus Corpus reauthorization must be p95 `<= 200 ms` and p99
    `<= 750 ms` across `300` mixed term/phrase/prefix/filter queries. Normal
    dirty ingestion is visible within `90` seconds; hourly repair is the missed-
    wakeup bound. Metrics run on the packaged macOS arm64 operator host and the
    packaged Linux x86_64 Serenity host, warmed after one unmeasured pass, with
    each host reported separately; neither host may be averaged away.

83. **Runtime capability and managed-job evidence are exact.** Every packaged
    target interrogates the Exqlite-loaded library, never the workstation
    `sqlite3`: `sqlite_version() >= 3.42.0`; functional FTS5 create/insert/term/
    phrase/prefix/BM25/snippet with `unicode61 remove_diacritics 2`; WAL mode;
    `PRAGMA integrity_check`; FTS integrity; `secure_delete`; FTS
    `secure-delete=1`; `wal_checkpoint(TRUNCATE)` with `busy = 0`; partial
    unique indexes; and locator/FTS shared-rowid bijection. Missing deterministic
    capability is typed degraded state and blocks Search enablement/promotion.

    External M5/M8 prerequisites are a clean pushed SHA, exact packaged
    `macos-arm64` artifact on the operator Mac, exact packaged `linux-x86_64`
    artifact at `~/projects/lexlapax/allbert-assist` on `lexlapax@serenity`, a
    disposable migrated `ALLBERT_HOME` plus daemon/TUI attach on each host; the
    model-assisted Memory smoke on the operator Mac additionally uses configured
    profile `local`, whose doctor reports `provider=local_ollama`,
    `model=llama3.2:3b`, `endpoint_ok=true`, and `model_available=true` against
    localhost. The `linux-arm64` artifact runs the same SQLite/package smoke in
    the pinned native-architecture container; it is not used to average away a
    host latency failure. A mapped-DM smoke additionally requires one real
    configured mapped one-to-one channel; absence is recorded as unavailable
    external evidence and never replaced by a fake acceptance provider.

    The five exact registered targets are `memory-consolidation` →
    `consolidate_memory`, `memory-index-rebuild` → `rebuild_memory_projection`,
    `search-index` → `ingest_search_index`, `search-maintain` →
    `maintain_search_index`, and `search-rebuild` → `rebuild_search_index`.
    Managed job metadata
    uses string keys `managed_by: "jobs.managed"`,
    `managed_schema: 1`, `managed_identity`, `managed_spec_version: 1`, and
    `managed_spec_digest` (`sha256:` plus 64 lower-case hex); mutable operator
    cadence/pause remains in ordinary Job fields. `dirty_seq` is a monotonic
    non-negative integer, `clean_dirty_seq` is the greatest fully applied
    sequence, and `feature_enabled` caches the effective Settings gate; pending
    dirty work is exactly `dirty_seq > clean_dirty_seq`. Startup/hourly
    reconciliation is invoked by the existing Jobs scheduler agent, not a new
    supervisor or timer. A run stores nullable UTC-microsecond
    `claimed_due_at`, non-negative integer `claimed_dirty_seq`, string
    `managed_identity`, and integer `managed_spec_version`; `admission_key` is
    the string job id. An overlapping
    admission returns `{:ok, %{outcome: :coalesced, job_id: id,
    open_run_id: id, claimed_dirty_seq: non_neg_integer}}`. Completion clears
    dirty state only when the current sequence equals the claimed sequence and
    merges an action continuation with any newer dirty due time by choosing the
    earliest non-nil due time, without unpausing an operator-paused row. These
    fields add no second job state machine.

84. **Projection paths and revision metadata are fixed without a pointer
    service.** `AllbertAssist.Paths` derives one non-configurable
    `<ALLBERT_HOME>/projections` root and domain roots `memory/` and `search/`.
    Each contains `control.json`, `current.sqlite3`, `previous.sqlite3`, and at
    most one live `build-<generation_id>.sqlite3` plus SQLite-owned sidecars.
    `generation_id` is a UUIDv7 string. Promotion renames these fixed files; no
    symlink, mutable pointer file, Ecto Repo, or generic projection registry is
    added. Authoritative Home export/backup excludes the entire projections
    root, while diagnostic export may report content-free control metadata.

    Each domain's schema-1 `control.json` contains string `domain`, nullable
    `current_generation_id`/`previous_generation_id`/`builder_generation_id`,
    non-negative 64-bit `projection_revision`, positive integer
    `schema_version`, `state: "not_ready" | "ready" | "degraded" |
    "rebuilding" | "purging"`, boolean `dirty`, non-negative `dirty_seq`,
    `rebuild_phase: nil | "paging" | "verifying" | "promoting"`, and safe
    `last_error_code`. Search's separately frozen purge phase is also stored
    here. Search additionally records
    source high-water `(inserted_at, id)`, non-negative `eligibility_epoch`, and
    `tokenizer_version`/`redactor_version`; Memory records its claim-stream
    watermark plus `claim_normalizer_version` and
    `tombstone_normalizer_version`. The same immutable compatibility values and
    generation id live in a one-row metadata table inside each generation DB so
    a self-contained reopen can verify the manifest. Every committed
    incremental transaction increments the current generation's revision by
    exactly one; a rebuilt generation starts at revision `0`, promotion does
    not increment it, and its first later mutation advances it to `1`. Revisions
    never cross generation IDs and are cursor/provenance coordinates, not
    authority.

## Complexity Budget

The following are explicit non-goals for v1.2.5/v1.3:

- universal license scanner, complete SBOM platform, recursive byte ownership,
  runtime license server, or per-file ownership database;
- generalized bidirectional Attach transport, terminal-session replay, or a
  second embedded TUI runtime;
- generic Corpus adapter registry, event-sourcing platform, durable cross-domain
  event bus, or consumer access to canonical Repo schemas;
- generic projection framework, second scheduler, managed-job DSL, or private
  job loops in Search/Memory — the LD 62 promote-protocol helper is explicitly
  **in** scope and is not the framework this bar excludes: it owns one
  checkpoint/close/reopen/promote sequence and no schema, verification
  predicate, or rebuild source;
- Search Ecto domain, query DSL, external-content triggers over canonical rows,
  fuzzy/trigram/semantic/vector search, SQLCipher, or canonical-table fallback;
- Memory sourced from Search matches, assistant assertions, traces, objectives,
  hidden prompts, or raw tool/model payloads;
- mutable revision-history records, automatic conflict winner selection,
  automatic memory promotion, automatic Forget, or promises to erase backups;
- hosted consolidation fallback, automatic canonical conversation retention,
  multi-user/remote sync, or prompt injection beyond direct-answer/vision;
- validation-only product capabilities or long repeated aggregate test builds.

- `Runtime.Attach.TUISession` — bounded daemon-side session lifecycle using

### Shared v1.3 Corpus

`AllbertAssist.Conversations.Corpus` owns:

- `snapshot(operator_id, source_policy)` → opaque high-water snapshot;
- `page(snapshot, cursor, limit)` → stable keyset page of `SourceEnvelope`;
- `rehydrate_authorized(operator_id, refs, scope)` → current authorized
  envelopes or typed unavailable reasons;
- bounded same-conversation context for memory disambiguation;
- eligibility/digest checks shared by proposal review and Search results.

`SourceEnvelope` is versioned and carries stable source/message/thread/operator/
principal IDs; role separately from verified author; trust/surface/thread kind;
canonical timestamps/order; redacted-or-canonical content as permitted; content
digest; source classification; and bounded origin/trace references. It is data,
not authority. Remote envelopes are admitted only from message references that
carry an exact `thread_channel_ref_id`, immutable `origin_principal_digest`, and
`principal_normalizer_version`; Corpus compares those with the current enabled
identity mapping. Legacy remote rows are backfilled only on a single provable
match and otherwise return `legacy_principal_unverified`. Local authenticated
rows derive their principal from canonical user/operator ownership plus local
trust rather than inventing a provider ref.

### v1.3 Memory

- `Memory.Claims` — one plain domain/storage module for claim-stream parsing,
  validation, digest-chain checks, synthetic legacy revision-zero views,
  current/as-of reduction, append/archive, and confirmed Forget filesystem
  effects, including verification/append of signed native authority and the
  content-free manual-import confirmation transition. Its sole mutation API is
  `append(claim_id, expected_tail_digest, transition)`: it serializes per claim,
  rechecks tail/tombstone under the lock, and syncs a same-directory temporary
  replacement before rename and directory sync. It also revalidates the bounded top-N projection
  candidates against canonical claim digest/state before prompt use. Its
  codec/reducer functions stay pure internally,
  while all effects are reached only through registered actions; do not add a
  separate codec or repository layer merely to relabel the same implementation.
- `Memory.Proposals` — one Memory-owned set of additive tables in the existing
  application Repo for durable normalized proposals, protected stubs, and
  frozen batch results. It is authoritative only for inert review state—not
  kept claims—and adds no third database. It stores no transcript, durable
  excerpt cache, or retained proposal-text duplicate after accepted claim
  append. Redacted portability export contains no proposal content; raw/full
  Home backups follow existing Repo lifecycle and the documented active-store
  Forget limitation. Applying recovery and accepted legacy-draft absorption use
  the same deterministic transition ID; successful append replaces proposal/
  draft YAML and referenced draft artifact payloads with a content-free terminal
  result, while Forget traverses and scrubs matching in-flight legacy state.
- `AllbertAssist.Projection.PromoteProtocol` — the LD 62 shared helper, owned by
  M3 and consumed by M6 after its contract rejoin. It owns exactly one sequence:
  checkpoint `busy = 0`, self-contained proof, bounded owner quiescence and
  serving-handle close, atomic same-filesystem swap, verified reopen, retain
  previous. It holds no schema, verification predicate, generation metadata, or
  rebuild source — those stay in each domain's projection module. Its focused
  contract suite is `test/allbert_assist/projection/promote_protocol_test.exs`.
- `Memory.Consolidation` — bounded producer using Corpus and deterministic
  policy/extraction with optional local-model advice.
- `Memory.Projection` — one plain state/storage process owning the separate
  rebuildable SQLite projection, incremental projection revision, and verified
  rebuild generations. Its moduledoc records the plain-GenServer
  choice because storage lifecycle has no useful smarter-agent successor. On
  startup it verifies/loads tombstone suppression before declaring retrieval
  ready, then kicks the existing managed rebuild/reconcile action for applying,
  pending-Forget, legacy-scrub, and projection recovery.
- Existing `ActiveMemory` and registered retrieval actions consume the
  projection and retain deterministic lexical ranking/direct-answer budget.

Claims remain under the established Markdown memory tree; new claim-stream
files use the existing category/namespace ownership rather than a parallel
canonical hierarchy. Projection/database paths derive through
`AllbertAssist.Paths`.

### v1.3 Search

- `AllbertAssist.Search` — domain facade, typed query/result/cursor/error DTOs,
  source scoping, and registered query/manage actions.
- `Search.Projection` — one plain state/storage process owning the dedicated
  SQLite connection, one content-storing FTS5 table plus its minimal
  content-free unique source/rowid locator, cursor, snapshot/page ingestion,
  redaction, digest/upsert/delete, rebuild verification, and generation
  promotion. There is no useful smarter-agent successor and no separate
  Store/Projector layer.
- Search declares managed-job specs as data reconciled by `Jobs.Managed`; it
  does not add a Search-specific timer or job service. Canonical writers call
  `Jobs.Managed.kick/2` for the existing `search-index` identity after marking
  projection work dirty.

Search results carry canonical source IDs, author/trust/surface/thread/time,
post-reauthorization redacted snippet, lexical score, generation/projection
revision/freshness, and stable cursor. They never return a raw full transcript.

### v1.3 Jobs and Settings

- `Jobs.Managed` is a small context/helper over existing Jobs rows/actions. Its
  stable key is `(Home, managed_identity)` and it owns reconcile plus a bounded
  dirty `kick/2`; Jobs continues to own pause, due-state, execution, and run
  history.
- Settings Central owns feature grants, enablement, cadence, run/query caps,
  snippet bounds, E2EE-origin consent, and maintenance policy. The two feature
  switches are named and have deliberately opposite defaults:
  `memory.consolidation.enabled` (default **false**, LD 32) and
  `search.enabled` (default **true**, LD 60). Origin scopes are
  `local_operator`, `mapped_operator_dm`, and `e2ee_operator` (LD 21), granted
  per consumer and non-transitive.
- Search projection state and Memory claim/projection state are not encoded in
  job metadata.
- M0.b2 additively extends existing Settings Secrets/Key Custody with one
  serialized system-owned `fetch_or_create` path and provisions one per-Home
  32-byte secret at `secret://system/integrity_v1` (record version `1`). TUI,
  native claim authority, manual/destination confirmation, Forget suppression,
  Search cursors/query grants/purge, and canonical-delete previews derive
  distinct fixed domains through one two-step helper: HMAC the UTF-8 domain
  string with the Home key, then HMAC the canonical length-prefixed payload with
  that domain key. Consumers receive only tag/verification results, not the raw
  Home key. Settings master-key rotation rewraps but does
  not replace it; referenced versions remain and disappearance fails closed.
  No new key service, encryption layer, or process is introduced.

## Workstreams, Serial Barriers, And Rejoins

### v1.2.5 workstreams

- **WS-L — licensing:** catalog/generator/viewer → release finalizer → native
  artifact qualification.
- **WS-T — TUI:** ADR/protocol → daemon session → thin client/lifecycle.
- **WS-D121 — docs/gates/dependency refresh:** may prepare in parallel, but
  version/gate/release docs cannot close until WS-L and WS-T rejoin.

WS-L and WS-T are independent until final artifact composition. Both touch
release packaging and therefore rejoin before native artifacts are built.
The three targets are built once from an unchanged candidate and those exact
bytes are reused for viewer/TUI smokes, signing, publication, and install
rehearsal.

Serial barriers:

1. ADR 0091 and the license artifact contract before corresponding code.
2. Final release-step order frozen before target manifest generation.
3. Both workstreams, dependency refresh, focused tests, targeted static checks,
   docs drift, lane/inventory reconciliation, and the structurally verified
   `release.v121` ordered-step definition at one clean pushed SHA.
4. No aggregate/full-project command runs at the v1.2.5 rejoin; the focused
   source rejoin authorizes the immutable tag/build and named artifact/FV lanes.
5. The tag build stages one digest set; M0.a3 evidence is bound into the
   separately dispatched protected promotion before signing/publication.
6. Published/validated v1.2.5 and M0.c3 in-place stage closeout before v1.3
   implementation begins.

### v1.3 workstreams

- **WS-C — Corpus/policy:** SourceEnvelope, snapshots/pages, canonical
  reauthorization, consent, identity/remap/revocation, and Jobs.Managed.
- **WS-M — Memory:** claims/proposals/review/projection/consolidation/retrieval.
- **WS-S — Search:** projection/query/generations/management/deletion.
- **WS-U — surfaces/docs/evals:** shared DTO/action consumers, operator docs,
  security rows, external/FV preparation.

Serial barriers:

1. M1 current-HEAD/calibration contract before schema/storage code.
2. Corpus identity/digest/authorization and consumer grants before Memory or
   Search ingests canonical content.
3. Claim-stream validator, crash protocol, and Memory projection before
   consolidation or prompt retrieval; M3 also owns the shared promote-helper
   contract/rejoin before M6 may integrate Search promotion.
4. Search redaction, generation verification, and query-time Corpus
   reauthorization before any surface displays a result.
5. Deletion/revocation/E2EE semantics before DM or cross-surface rollout.
6. Integrated Memory/Search revocation rejoin before the final M9.b aggregate
   release rejoin.
7. Dependency refresh, Purpose/drift review, and docs, then at M9.b the sole
   cumulative/authoritative aggregate execution, followed by FV and publication.

After M2, WS-M and WS-S may proceed in parallel because they own different
projections and consume only Corpus contracts. Search DTO/parser/schema work may
continue while M3 builds the shared promote helper, but Search generation
promotion waits for that first rejoin. WS-U may build render-only shells and
fixtures after DTOs freeze; no surface ships before its authority barrier.

Rejoin proofs:

- v1.2.5 artifact rejoin: license finalization + TUI attachment over the same
  exact target release tree.
- v1.3 Corpus rejoin: one canonical visibility/principal-mapping invalidation
  immediately suppresses Search and invalidates pending proposals while
  independently kept Memory remains; separate consumer origin/E2EE revocations
  affect only their named consumer.
- v1.3 lifecycle rejoin: canonical source delete, projection repair, pending
  proposal staleness, archive, and Forget each exhibit their distinct contract.
- v1.3 storage rejoin: the M3-owned promote helper passes Memory verification,
  then the same checkpoint/close/reopen/promote contract is consumed by Search
  without importing either domain's schema or policy.
- Release rejoin: request flow, ADRs, operator/developer docs, metrics,
  inventory/no-loss manifests, dependency dispositions, structurally verified
  gate composition, and the final M9.b exact-SHA aggregate executions.

  a prompt to run every inherited gate.

## Security And Privacy Posture

- Packaging/license inspection adds no runtime authority and performs no
  network access.
- Attach remains local-only, Home/uid/version/protocol/token bound, size-bounded,
  and fail-closed for attached clients. A TUI session does not bypass Runtime,
  Security Central, actions, confirmations, or trace redaction.
- `SourceEnvelope`, Search rank, cursor, source ID, job ID, proposal ID,
  objective ID, and model output are never authority.
- Memory proposals are inert; only registered audited review actions make kept
  memory. Protected facts are individually reviewed.
- Search is local and read-only at the query boundary. `:search_manage` covers
  projection effects, not canonical deletion or cross-surface disclosure.
- Corpus authorization is checked again at proposal review and result return,
  not only at ingestion.
- Secrets are rejected/redacted before projection/proposal writes. Raw search
  text/snippets/filter operands, source excerpts, HMAC material, and forgotten
  content are excluded from traces/audits/logs/tests and durable confirmation/
  resume parameters; Search's safe summary is computed before requested-signal
  emission and fails closed to omission.
- E2EE indexing is an explicit privacy trade: decrypted local derived text
  exists in the Search projection. File permissions, backup exclusion, policy,
  reauthorization, and purge constrain exposure; encryption is not implied.
- Archive, canonical source deletion, projection purge, and Forget are separate
  typed/confirmed operations with separate consequences.

## Assumptions, Risks, And Stop Conditions

- **Best effort is intentionally not completeness.** A requirement for a
  complete universal SBOM/byte inventory is a new architecture/scope decision.
- **macOS needs one-time requalification.** Replacing floating Homebrew
  toolchains can alter dynamic closure. The OpenSSL patch is evidence-driven.
- **Manual append-only memory is a tighter contract.** Editing/removing old
  revisions is treated as corruption because silent mutation would destroy
  knowledge-time truth.
- **Forget cannot reach every copy.** Backups, exports, filesystem snapshots,
  and physical media are outside the active-store guarantee and must be
  disclosed before confirmation.
- **Search is plaintext-derived.** No encryption overhead is planned; local
  compromise/storage copying remains a residual risk documented to operators.
- **Search freshness is bounded, not synchronous.** Canonical reauthorization
  prevents stale disclosure, while physical repair may lag to the stated
  freshness/reconcile window.
- **FTS ordering is projection-revision-relative.** Scores may move after any
  ingestion. Cursors fail stale across generation or revision changes rather
  than promising continuity.
- **SQLite is one-writer per database.** Separate Search/Memory projections
  reduce contention and failure coupling but do not create a cross-database
  atomic transaction. v1.3 takes the Home from one database to three, inside
  the daemon that ADR 0091 makes the sole owner of writer discipline. v1.1's
  systemic root cause was resource ownership rather than fan-out logic, so
  LD 61 fixes each database's writer owner, supervision parent, and
  non-attached-CLI behavior before code lands. A non-attached CLI operation
  that depends on projection state attaches to the daemon or fails closed with
  guidance; surfaces never open projection databases directly. Two more
  writers is the risk this release most resembles v1.1.
- **Retiring legacy subsystems is not additive, so it is done by absorption.**
  LD 58 keeps every public action, setting, and request shape responding while
  routing behavior into the new model. A future release may delete the
  deprecated shapes under the ordinary Tier-2 process; v1.3 does not, because
  removal inside a frozen line is a separate operator decision.
- **`memory.auto_promote_sensitive_entries` shipped a promise the new model
  contradicts.** It is behaviorally inert and deprecated rather than deleted;
  the operator's stored value is not rewritten. Anyone
  reading the settings schema during v1.3 will still see the key and must find
  its deprecation note beside it.
- **External memory literature drifts.** Tests freeze Allbert behavior; no
  external service/API becomes a runtime dependency.
- **Purpose remains the bar.** If an outcome cannot be completed within the
  bounded design, implementation stops for operator disposition rather than
  adding substantial framework code or quietly cutting scope.
