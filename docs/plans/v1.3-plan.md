Request flow: `docs/plans/v1.3-request-flow.md`

Architecture decisions:

- ADR 0076 — packaging, distribution, and unified CLI (amended here for
  packaged license material and daemon-only TUI attachment)

Status: **implementation-ready after the 2026-07-28 second-pass review.**
The operator approved the decisions in this plan, including the recommended
defaults for the remaining questions. This is one active planning triad and a
two-stage binary release train:

1. **v1.2.1 foundation:** packaged license inventory/viewer and the
   daemon-backed thin TUI, each in its own milestones.
2. **v1.3.0 flagship:** canonical conversation Corpus, reviewed bi-temporal

begins. Keeping both stages in this plan avoids a release-planning sidecar while
preserving separate tags, acceptance bars, gates, dependency-refresh work, and
release evidence.

## Purpose

### v1.2.1 foundation

1. **A self-describing binary, without a license-management subsystem.** Every
   supported artifact carries Allbert's license and notice, a deterministic
   best-effort inventory of known shipped components, the corresponding
   required license/source texts, and a pure `allbert licenses` viewer. The
   inventory is derived at final artifact composition, not guessed from the
   development dependency tree.
2. **One runtime behind every terminal session.** `allbert tui` becomes a thin
   terminal client attached to the already-running daemon. The daemon owns
   runtime state, identity, confirmation, Pi-mode work, and event delivery; the
   client owns only input and rendering. No second embedded runtime or silent
   fallback remains.
3. **Artifact and toolchain claims are reproducible and honest.** All three
   native targets use exact toolchain inputs, clean current web assets, and the
   same finalization contract. The release evidence identifies target-specific
   bytes and external runtimes without claiming cross-platform byte identity or
   universal file ownership.

### v1.3.0 flagship

4. **One canonical corpus, two independent consumers.**
   `AllbertAssist.Conversations` remains the owner of conversation truth.
   Memory and Search consume a typed `Conversations.Corpus` contract; neither
   reaches into the other's projection, and surfaces never query storage
   directly.
5. **Memory that is useful, reviewable, temporal, and repairable.** Periodic
   local consolidation proposes facts from verified operator-authored
   conversation turns. Only explicit review makes a proposal retrievable.
   Claims retain valid-time and knowledge-time history in append-only Markdown
   streams, and a complete disposable projection makes prompt-time lookup
   bounded.
6. **Search as a central engine and API.** Web, TUI, CLI, mapped DMs, and later
   surfaces use one typed Search action/API over a dedicated rebuildable SQLite
   projection. Query-time Corpus authorization prevents stale, deleted,
   revoked, or cross-scope results from escaping.
7. **Balanced consent and low operator burden.** Consent is granted once per
   feature and eligible source class rather than per job or per message.
   Routine local indexing and recurring work do not repeatedly prompt.
   Scope expansion, E2EE-origin indexing, cross-surface DM disclosure,
   protected memory review, Forget, and secure purge remain explicit acts.
8. **Recurring work uses the recurring engine.** Memory consolidation and
   Search ingestion, reconcile, maintenance, and rebuild are visible managed
   entries in the existing Jobs system. v1.3 adds ownership/reconciliation,
   not another scheduler.
9. **Measured quality without a long aggregate-build loop.** Extraction gates
   precision, recall, protected-data exclusion, knowledge update, temporal
   retrieval, and abstention. Search gates scope, freshness, deletion, ranking,
   rebuild, and bounded latency. Focused gates run throughout; cumulative and
   authoritative aggregate gates run once at clean release-candidate rejoins.

## Current Code State To Re-Verify At Build Start

The readiness review established these anchors. M0/M1 re-verify them against
build-start HEAD and record drift before implementation:

- The root release definition bundles ERTS and currently composes
  `build_web_assets → :assemble → stage_plugins → patch_macos_openssl →
  install_dispatcher`. License finalization is absent and must follow the last
  artifact mutation.
- Published artifacts currently contain no coherent root license inventory.
  The root `NOTICE` is stale; the Homebrew formula says MIT; the first-party
  browser bridge says `UNLICENSED`; development/install prose incorrectly
  describes the full shipped tree as permissive and copyleft-free.
- `.github/workflows/release-artifacts.yml` currently signs and publishes every
  product-tag build automatically. v1.2.1 must split that job at a protected
  digest-bound promotion gate so exact tag-built archives can be qualified
  before the same bytes are signed/published without a second build.
- macOS release CI currently takes a floating Homebrew toolchain path while
  Linux uses setup-beam inputs. macOS may still copy `libcrypto.3.dylib`;
  Linux treats OpenSSL as external.
- `phx.digest` output is not cleaned before release composition, so historical
  digest files can survive locally unless the build seam rejects them.
- Attach v1 is a one-request/one-response, packet-4 Unix-domain-socket protocol
  authenticated by Home, uid, version, protocol, and a per-Home token. Requests
  are argv-shaped and an absent request kind therefore means the legacy unary
  command.
- The TUI runtime/channel already has mature rendering, subscription, steering,
  and confirmation behavior, but packaged CLI dispatch may still fall back to
  an embedded runtime. That fallback is removed only for the TUI/attached path;
  unrelated legacy unary CLI compatibility remains additive.
- `AllbertAssist.Conversations` owns user/thread-scoped message reads and
  writes. There is no typed corpus snapshot/page/rehydration interface and no
  central conversation-history search.
- A message `role == "user"` is not proof of operator authorship. Channel
  mapping and verified principal/trust metadata must be consulted before a
  turn can originate a memory claim.
- Active Memory retrieves only `:kept` Markdown entries but performs a bounded
  filesystem candidate scan and has a write-recency floor unsuitable for
  durable facts. Existing entry files are flat mutable records rather than
  immutable logical-revision streams.
- `Memory.ReviewCadence` is the current managed-job precedent, but stable
  managed identity/invariants are encoded privately rather than owned by one
  reusable `Jobs.Managed` seam.
- Exqlite ships SQLite with FTS5 in the current dependency tree, but every
  artifact must prove its runtime SQLite version and compile options rather
  than relying on the workstation `sqlite3` binary.
- `mix precommit` is a compatibility shortcut for the commit gate. The
  authoritative release runner and version-specific cumulative gates record
  structured metrics; repeating nested aggregate gates adds wall time without
  adding coverage.

## Research Basis

Research informs these decisions but does not import an external product's
architecture:

- Mix releases can bundle ERTS and expose ordered post-assembly release steps;
  the final release filesystem, not `release.applications` alone, is the
  artifact-composition boundary:
  <https://hexdocs.pm/mix/Mix.Tasks.Release.html> and
  <https://hexdocs.pm/mix/Mix.Release.html>.
- setup-beam documents exact/strict input versions and resolved version
  outputs, which support one toolchain contract on every target:
  <https://github.com/erlef/setup-beam#input-versioning>.
- GitHub Actions environments can require approval before a job starts, so the
  public repository's publish job can wait after artifact staging and before
  signing/upload without occupying a runner or rebuilding:
  <https://docs.github.com/en/actions/concepts/workflows-and-actions/deployment-environments>.
- Mozilla's CA material remains MPL-2.0 when converted into curl's CA extract.
  MPL obligations are file-scoped:
  <https://curl.se/docs/caextract.html>,
  <https://www.mozilla.org/en-US/MPL/2.0/>, and
  <https://www.mozilla.org/en-US/MPL/2.0/FAQ/>.
- SQLite FTS5 documents tokenizers, BM25, snippets, merge/rebuild/integrity,
  external-content synchronization hazards, and FTS-specific secure deletion:
  <https://www.sqlite.org/fts5.html>. WAL permits concurrent readers but one
  writer per database: <https://www.sqlite.org/wal.html>. VACUUM rebuilds the
  database and needs free space/exclusive conditions:
  <https://www.sqlite.org/lang_vacuum.html>. Core secure-delete behavior is
  documented at <https://www.sqlite.org/pragma.html>.
- LongMemEval measures information extraction, multi-session reasoning,
  temporal reasoning, knowledge updates, and abstention:
  <https://arxiv.org/abs/2410.10813>. Zep/Graphiti records valid and learned
  time on graph edges: <https://arxiv.org/abs/2501.13956> and
  <https://www.getzep.com/platform/graphiti/>. Mem0 separates extraction,
  consolidation, and retrieval:
  <https://arxiv.org/abs/2504.19413>. These support the evaluation dimensions;
  they do not justify adding a graph, vector store, or external memory service.
- External memory projects change behavior independently of their papers
  (including Mem0's current public ADD-focused interface). Implementation pins
  research fixtures and claimed versions rather than treating a moving project
  README as a stable Allbert contract.

## Locked Decisions

### Release and additive-contract decisions

1. **Two binary stages, one plan.** v1.2.1 ships licensing and daemon-backed
   TUI before v1.3 memory/Search work. Each stage tags, builds natively, signs,
   publishes, fills the tap, and validates the installed product.
2. **Additive evolution only.** Existing public action/request shapes, memory
   files, settings, database rows, and explicit write paths retain their
   meanings. New optional fields, actions, statuses, files, and projection
   stores may be added. No migration-runner pull-forward is authorized.
3. **Scope deferral stays an operator decision.** If a Purpose outcome would
   require materially more code than this plan's bounded design, stop with
   evidence and propose the smallest alternative. Do not build a framework to
   avoid asking, and do not silently move the outcome out of the release.

### Packaged-license decisions

4. **One generator, one catalog, one viewer.** A small offline deterministic
   finalizer consumes resolved release applications/locks plus one reviewed
   catalog of known extras/exceptions. `allbert licenses` is a pure reader of
   packaged files. There is no runtime license process, SBOM platform,
   recursive universal ownership scanner, or per-file license database.
5. **Honest best-effort claim.** The product says “best-effort inventory of
   known shipped components.” It does not claim universal completeness,
   complete legal compliance, or that every arbitrary byte has an attributable
   package owner.
6. **Fail closed at managed seams only.** Finalization fails for an unknown
   shipped BEAM application, a known catalog component with missing/unapproved
   license or required text, an expected path missing, a known special payload
   whose provenance digest drifted, or a known external runtime unexpectedly
   bundled. Unclassified arbitrary bytes produce bounded evidence/warnings;
   they do not trigger a complex scanner.
7. **Canonical union plus target truth.** Commit one deduplicated
   cross-platform `THIRD-PARTY-LICENSES.md` and the reviewed catalog. Generate a
   per-target `THIRD-PARTY-MANIFEST.json` from the final artifact. Root
   `LICENSE` and minimal `NOTICE` are staged beside them.
8. **Known-component coverage.** The catalog accounts for bundled OTP/ERTS and
   sublicenses, Elixir, SQLite/Exqlite amalgamation/NIF, OpenSSL when copied,
   Castore/Mozilla CA material, IANA timezone data, compiled/vendored web
   assets, staged plugins, and packaged helpers. Node/Playwright/Chromium and
   TradingAgents/Python remain marked external unless their bytes are actually
   present in the artifact.
9. **Narrow MPL exception.** Castore code remains Apache-2.0; its
   Mozilla-derived `priv/cacerts.pem` receives one file-level MPL-2.0 exception.
   The catalog records full source provenance and digest, ships the MPL text,
   and supplies either the corresponding source companion or an immutable
   exact-source retrieval reference with digest and conversion provenance.
   Missing source availability or payload drift fails closed. External release
   qualification digest-verifies the packaged companion or performs an
   unauthenticated fetch of the immutable reference and matches its exact
   source digest; failure blocks publication. Generation/viewing stays offline.
   This is not a blanket MPL allowlist.
10. **Finalize last, verify before archive.** Clean/current assets are required.
    The license finalizer runs after plugin staging, target-specific OpenSSL
    mutation, and dispatcher installation; verification then proves the
    manifest against an unchanged tree before archive/sign/publish.
11. **One exact toolchain contract.** Linux and macOS use an exact strict
    setup-beam path pinned by full action SHA, record resolved OTP/Elixir
    versions, and do not run a floating `brew update && brew install erlang
    elixir` build. Requalify macOS once; retain the OpenSSL patch only if the
    final dependency closure proves it remains necessary.

### Daemon-backed TUI decisions

12. **Daemon owns behavior; client owns the terminal.** Runtime submission,
    operator identity, confirmations, Pi-mode lifecycle, subscriptions, and
    event fan-out remain in the daemon. The client owns TTY mode, input,
    rendering, bounded local presentation state, and restoration on exit.
13. **One TUI attachment per Home initially.** A second TUI receives a stable
    occupied diagnostic. There is no live-session replay/resume in v1.2.1.
14. **No silent embedded fallback.** When the daemon is absent, TUI/attached
    commands fail with paste-executable start/repair guidance. A bind failure
    may leave Web healthy-but-degraded, but attached TUI/CLI fail closed.
15. **Additive Attach v1 shape.** An optional request `kind` distinguishes
    `command` and `tui_session`; an absent kind retains legacy unary behavior.
    Session frames are typed, size-bounded, sequence-aware, and limited to the
    TUI need. This is not a general transport framework.
16. **Disconnect and overload are explicit.** Socket loss ends the terminal
    attachment and restores TTY state. Durable background work may finish;
    effectful Pi coding work tied to the lost session cancels fail-closed.
    Bounded queues coalesce/drop presentation-only updates before authority or
    confirmation events, and surface the gap rather than hiding it.

### Corpus, identity, and consent decisions

17. **Conversations owns canonical truth.** Add a deep
    `AllbertAssist.Conversations.Corpus` interface and typed/versioned
    `SourceEnvelope`. Do not add a generic storage behavior while SQLite is the
    only canonical store.
18. **No schema-leaking consumers.** Memory and Search use snapshot/keyset
    pages and canonical batch rehydration/authorization. Neither reads
    conversation Repo tables directly; Memory never reads Search/FTS; Search
    references are advisory until Corpus reauthorizes them.
19. **No new durable event platform.** Existing successful writes emit a
    coalesced ingestion wakeup; an hourly managed reconcile catches missed
    wakeups, deletes, identity remaps, and policy drift. Canonical delete
    actions request immediate reconciliation. Query/review-time reauthorization
    suppresses ineligible material before physical projection repair, so
    correctness does not depend on a perfect event delivery log.
20. **Verified principal, not role.** Operator authorship requires the
    canonical principal/author identity and channel trust mapping.
    `role == "user"` alone is insufficient. Role stays a separate field.
21. **Consent is per consumer and source class.** Search and Memory each have a
    separate feature grant. One `private_operator` grant covers local Web,
    CLI, TUI, and current/future verified mapped one-to-one operator DMs.
    A grant is non-transitive: Search never authorizes Memory collection and
    Memory never authorizes Search projection. Group/shared/programmatic/
    unknown sources remain excluded.
22. **E2EE needs separate opt-in.** The disclosure states that indexing creates
    local plaintext-derived FTS content. No SQLCipher or application encryption
    layer is added. Identity remap, grant revocation, E2EE opt-out, or source
    deletion applies only to the affected consumer: it immediately suppresses
    affected Search results and/or invalidates affected pending Memory
    proposals without granting or revoking the other consumer implicitly.
23. **Kept memory is independently authorized.** Source revocation/deletion
    does not silently delete a fact the operator separately kept. Its
    provenance reports the unavailable/revoked source until the operator
    archives or Forgets it.

### Memory decisions

24. **Immutable claim streams are the authority.** Each logical claim is one
    human-readable Markdown file with append-only immutable revision blocks:
    stable `claim_id`, immutable `revision_id`/sequence, previous-revision
    digest, `recorded_at`, valid-time bounds, review transition, source
    IDs/digest/classification, and optional `supersedes_claim_id`.
25. **True bi-temporality.** Valid time describes when a fact applies in the
    operator's world. Knowledge/system time describes when Allbert recorded a
    revision. Default retrieval is “valid now, known now”; typed explicit dates
    may select either axis. Ambiguous natural-language time asks for
    clarification rather than silently shifting the query.
26. **No mutation disguised as history.** `recorded_at` is chronology, not a
    winner rule. Automation may exact-dedupe, accept provably non-overlapping
    validity intervals, or construct explicit supersession when the operator
    statement supplies the relation/effective date. Overlapping or
    underspecified conflicts remain unresolved proposals.
27. **Legacy and manual editing stay additive.** Existing flat files read as a
    synthetic revision zero and upgrade lazily only on the next change. The only
    supported raw manual change shape is an append-only revision, and it remains
    quarantined until the operator confirms that exact revision through one
    registered one-claim repair/import action. Confirmation appends a
    content-free `manual_import_confirmed` transition over the unchanged pending
    revision digest with a domain-separated integrity tag from existing Key
    Custody. Rebuild requires that valid transition; no Repo ledger becomes a
    second authority. Modification/removal of an earlier revision or an invalid
    confirmation tag quarantines the claim; file contents never silently gain
    authority or trigger a rewrite.
28. **One complete disposable Memory projection.** A separate SQLite
    projection under Allbert Home represents all valid claim streams and can be
    rebuilt from Markdown; existing Key Custody is consulted only to verify
    integrity-tagged manual-import transitions and carries no claim content or
    lifecycle state. It is not the canonical Repo, is not the Search database,
    and is not a generic projection framework.
29. **Conversations originate claims.** In v1.3 only verified
    operator-authored conversation turns can originate a proposed fact.
    Assistant replies may provide a tight, transient same-conversation
    disambiguation window but never originate, corroborate, strengthen, or
    persist as proposal evidence. Traces/objectives may contribute bounded
    correlation IDs, never facts.
30. **Proposals minimize copied content.** An ordinary durable proposal stores
    the normalized proposed claim plus typed source IDs, source digest, trust
    classification, and extraction version. Review fetches a bounded redacted
    source excerpt. Protected third-party/minor/dependent proposals store only
    a redacted stub before individual review; secrets are dropped. After an
    accepted Keep/Edit appends the claim revision, the proposal is reduced to
    content-free result/provenance identifiers rather than retaining a second
    copy of the claim. Review excerpts are transient and never durably cached.
31. **Review is frozen and partially successful.** Bulk/digest review freezes
    proposal revision IDs/digests. Valid items apply; stale/ineligible items
    skip with durable per-item results. Retry/resume is idempotent. Protected
    proposals are never part of Keep All. Rejecting unchanged evidence
    suppresses repeat proposals. Frozen batch/result records contain ids,
    digests, and outcomes, not copied claim or excerpt content.
32. **Conservative defaults.** `memory.consolidation.enabled` defaults false
    until the source-class grant. The managed cadence is weekly, initial
    lookback 30 days, at most 20 new proposals per run, and at most 50 pending.
    The registered managed action uses additive `:memory_propose`: the current
    verified collection grant authorizes inert proposal writes without a
    per-run prompt, but cannot keep/edit/archive/restore/Forget a claim. Those
    remain separate operator actions, and Forget remains destructively
    confirmed.
33. **Deterministic safety, bounded local assistance.** Deterministic policy,
    secret, identity, normalization, conflict, and suppression gates remain
    authoritative. A configured local model may advise extraction within
    bounds. If absent/failing, use the deterministic high-confidence subset or
    abstain; never broaden or fall back to a hosted model.
34. **Review surfaces share actions.** Web and CLI provide full proposal and
    history review. TUI may show counts and invoke the same per-item typed
    actions, but does not gain a separate review engine. DMs notify/link and do
    not offer bulk Keep.
35. **Archive and Forget are different.** The existing delete-memory action
    remains a compatibility alias for reversible append-only archive/retire.
    A separately confirmed Forget removes the claim stream, every matching
    content-bearing proposal/review/batch payload, and Memory projection/
    WAL content. It leaves only content-free result/audit identifiers and the
    suppression tombstone (`claim_id`, time, actor, reason, non-secret key
    reference/version, keyed token). It is the explicit operator-authorized
    exception to immutability.
36. **Forget is bounded honestly.** Forget covers active Allbert-managed data,
    not backups, exported copies, snapshots, or storage forensics. Suppression
    uses a per-Home domain-separated HMAC key through existing Settings Secrets/
    Key Custody; no new crypto service is built. Exact forgotten content stays
    suppressed while a genuinely new value for the same predicate may be
    proposed.
37. **Tombstone portability is deliberately narrow.** The redacted portability
    envelope exports neither suppression tokens nor key material and remains
    dry-run on import. A same-Home full restore preserves suppression only when
    tombstones and the existing key survive together. A copied tombstone with a
    missing/mismatched key pauses proposal-producing actions with
    `tombstone_key_unavailable`; a fresh Home/new key has no cross-Home
    suppression guarantee. Do not add a key-export subsystem.
38. **Retrieval stays lexical and prompt scope stays narrow.** No embeddings or
    learned ranking. The direct-answer/vision prompt seam remains the v1.3
    proof target. Search matches never enter memory or prompt context
    automatically.
39. **STM remains volatile.** The existing working-memory scratchpad receives
    a documented sensitive-data contract and nested patch semantics without
    becoming a persistent store or consolidation source.

### Search Central decisions

40. **One central engine.** `AllbertAssist.Search` owns the typed query contract
    and registered actions. Web/TUI/CLI/DM surfaces render and dispatch; they do
    not parse FTS, rank, authorize sources, or query projection storage.
41. **One dedicated disposable database.** Search uses a separate
    `search.sqlite3`-family projection under Allbert Home, excluded from
    authoritative backup/export. The simplest content-storing FTS5 shape is
    preferred over external-content mirrors/triggers. Canonical conversation
    rows are never attached as FTS content.
42. **Visible conversation content only.** Index verified operator messages and
    visible assistant replies, labeled by author/trust/surface/thread. Exclude
    system prompts, hidden tool/model payloads, raw action logs, and secrets.
    Redaction occurs before projection write.
43. **Typed bounded query grammar.** Support words, quoted phrases, explicit
    prefixes, and typed filters; never expose raw `MATCH` syntax.
    `unicode61 remove_diacritics 2` and exact total-order tuples are the v1.3
    contract: relevance `(bm25 ASC, timestamp DESC, source_id ASC)`, newest
    `(timestamp DESC, source_id ASC)`, oldest `(timestamp ASC, source_id ASC)`.
    Default limit is 20, maximum 100, with bounded snippets.
44. **No semantic-search extras.** No substring/trigram/fuzzy index,
    embeddings, vectors, learned reranking, hidden recency blend, autonomous
    model search, or surface-specific search logic. Explicit “summarize these
    results” is a later action in the ordinary provider/egress policy, not part
    of lexical Search.
45. **Reauthorize every result.** FTS yields bounded candidate IDs/rank only.
    Corpus batch-rehydrates current rows and rechecks operator, source
    eligibility, scope, and digest before snippets/results are returned.
    Mismatch omits the candidate, requests repair, and reports freshness; it is
    never shown with a warning.
46. **Verified generations, no canonical fallback.** Rebuild a temporary
    projection, verify it, require `wal_checkpoint(TRUNCATE)` to return
    `busy = 0`, close the builder, self-contained-reopen/integrity-query check
    with no required sidecar, then atomically promote the DB and keep the
    previous verified generation for bounded rollback. Serve the last verified
    generation with `indexed_through` while rebuilding. With no verified
    generation return `search_not_ready`; never live-scan canonical tables.
47. **Generation/revision-bound pagination.** Every committed incremental
    mutation advances a monotonic projection revision. A stable cursor includes
    generation, projection revision, normalized query/scope/order digest, and
    rank tuple. A generation or revision mismatch returns restart-required
    rather than mixing pages after BM25 statistics change. Schema/tokenizer/
    redactor-version changes trigger rebuild, not a migration maze.
48. **Surface privacy.** Local Web/TUI/CLI default to all eligible retained
    history. A verified mapped operator DM defaults to its same
    channel/thread; cross-surface results require explicit confirmation.
49. **Freshness without blocking writes.** Successful canonical writes
    coalesce a Search wakeup. Search targets a 60–90 second normal freshness
    window; hourly reconcile repairs drift. Canonical writes never wait for
    Search.
50. **Deletion and pruning stay distinct.** Canonical conversations remain
    indefinitely until an explicit confirmed delete. Search maintenance may
    prune stale projection rows/generations, not canonical history. Confirmed
    canonical delete plus Search suppression/removal is in scope; automatic
    canonical retention is not.
51. **Secure purge is manual and narrowly claimed.** A confirmed action first
    requires affected canonical content to be ineligible/deleted or the
    affected Search source class/feature to be disabled, so ingestion cannot
    restore it. It uses FTS/core secure-delete for new deletes, but replaces any
    generation that may contain historical tombstoned terms from the currently
    eligible canonical set and deletes obsolete generations wholesale. It
    covers every Search-owned current, previous, build-temp, failed, retired,
    and pending-prune DB plus `-wal`/`-shm`; no openable or startup-recoverable
    managed generation may retain the fixture text. The claim excludes backups,
    filesystem remnants, and hardware erasure.
52. **Trace-safe query audit.** Raw query text, snippets, and filter operand
    values never enter traces or audits. Add one optional action-defined Runner
    summary callback for action name, auth scope, filter kinds/count, sort/
    limit, result count, generation/revision/freshness, latency, and request
    IDs. Existing actions retain current behavior.
53. **Runtime capability proof.** Each native artifact asserts SQLite
    >= 3.42 and `ENABLE_FTS5` before enabling Search, then proves tokenizer,
    phrase/prefix behavior, BM25, WAL, integrity, and FTS secure-delete on the
    shipped runtime.

### Managed-job decisions

54. **Existing scheduler, small ownership seam.** `AllbertAssist.Jobs.Managed`
    owns stable managed identity, action target/invariant parameters, desired
    cadence/pause policy, and reconcile diagnostics. Jobs still owns scheduling
    and run history; Memory/Search own cursors, leases, and projection state.
55. **Visible and operator-controllable.** Exactly one managed entry per
    operator/Home is visible and manually triggerable in normal Jobs surfaces.
    Operators may adjust allowed cadence or pause it. Deleting offers
    feature-disable guidance; incompatible invariant mutation reports degraded
    state rather than silently repairing or duplicating.
56. **Minimal Search job set.**
    - `search-index`: coalesced dirty kick plus hourly reconciliation through
      one registered management action; no-op runs write no projection work.
    - `search-maintain`: bounded weekly integrity, stale-row/generation prune,
      and incremental merge.
    - `search-rebuild`: on-demand/manual/resumable generation rebuild, not a
      periodic full rebuild.
    Secure purge is not recurring. Memory consolidation is one separately
    managed weekly job and remains disabled until its grant.
57. **Authority remains action-backed.** Search queries are read-only.
    Managed projection work uses `:search_manage` through registered actions
    and the Runner; job IDs, objective IDs, and schedule metadata confer no
    authority.

## Complexity Budget

The following are explicit non-goals for v1.2.1/v1.3:

- universal license scanner, complete SBOM platform, recursive byte ownership,
  runtime license server, or per-file ownership database;
- generalized bidirectional Attach transport, terminal-session replay, or a
  second embedded TUI runtime;
- generic Corpus adapter registry, event-sourcing platform, durable cross-domain
  event bus, or consumer access to canonical Repo schemas;
- generic projection framework, second scheduler, managed-job DSL, or private
  job loops in Search/Memory;
- Search Ecto domain, query DSL, external-content triggers over canonical rows,
  fuzzy/trigram/semantic/vector search, SQLCipher, or canonical-table fallback;
- Memory sourced from Search matches, assistant assertions, traces, objectives,
  hidden prompts, or raw tool/model payloads;
- mutable revision-history records, automatic conflict winner selection,
  automatic memory promotion, automatic Forget, or promises to erase backups;
- hosted consolidation fallback, automatic canonical conversation retention,
  multi-user/remote sync, or prompt injection beyond direct-answer/vision;
- validation-only product capabilities or long repeated aggregate test builds.

## Planned Interfaces And Storage Shape

### v1.2.1 licensing

- One small pure `AllbertAssist.Licenses` domain module owns catalog
  validation, offline finalization over an explicit release root/target, and
  reads of the generated packaged format. The Mix-task and CLI entrypoints are
  thin calls into it; do not split catalog/finalizer/viewer into services,
  processes, registries, or a runtime subsystem. Output uses canonical order
  and line endings with no host paths or timestamps.
- The packaged viewer exposes summary/list/JSON/show/notices only. It uses no
  Repo, daemon, HTTP, dependency scan, or runtime regeneration.
- Committed canonical union:
  `THIRD-PARTY-LICENSES.md` plus catalog and exceptional source/text assets.
- Per artifact: `LICENSE`, minimal `NOTICE`,
  `THIRD-PARTY-LICENSES.md`, and `THIRD-PARTY-MANIFEST.json`.

### v1.2.1 TUI

- `Runtime.Attach` request extension: optional `kind` with legacy default
  `command`.
- `Runtime.Attach.TUISession` — bounded daemon-side session lifecycle using
  existing TUI/channel/runtime/confirmation services.
- A thin CLI client loop for terminal frames, input, resize, close, diagnostics,
  and TTY restoration. No domain logic moves into the client.
- ADR 0091 freezes request/frame/version/backpressure/disconnect behavior before
  the transport implementation starts.

### Shared v1.3 Corpus

`AllbertAssist.Conversations.Corpus` owns:

- `snapshot(operator_id, source_policy)` → opaque high-water snapshot;
- `page(snapshot, cursor, limit)` → stable keyset page of `SourceEnvelope`;
- `rehydrate_authorized(operator_id, refs, scope)` → current authorized
  envelopes or typed unavailable reasons;
- bounded same-conversation context for memory disambiguation;
- eligibility/digest checks shared by proposal review and Search results.

`SourceEnvelope` is versioned and carries stable source/message/thread/operator/
principal IDs; role separately from verified author; trust/surface/thread kind;
canonical timestamps/order; redacted-or-canonical content as permitted; content
digest; source classification; and bounded origin/trace references. It is data,
not authority.

### v1.3 Memory

- `Memory.Claims` — one plain domain/storage module for claim-stream parsing,
  validation, digest-chain checks, synthetic legacy revision-zero views,
  current/as-of reduction, append/archive, and confirmed Forget filesystem
  effects, including verification/append of the content-free manual-import
  confirmation transition. Its codec/reducer functions stay pure internally,
  while all effects are reached only through registered actions; do not add a
  separate codec or repository layer merely to relabel the same implementation.
- `Memory.Proposals` — one Memory-owned set of additive tables in the existing
  application Repo for durable normalized proposals, protected stubs, and
  frozen batch results. It is authoritative only for inert review state—not
  kept claims—and adds no third database. It stores no transcript, durable
  excerpt cache, or retained proposal-text duplicate after accepted claim
  append. Redacted portability export contains no proposal content; raw/full
  Home backups follow existing Repo lifecycle and the documented active-store
  Forget limitation.
- `Memory.Consolidation` — bounded producer using Corpus and deterministic
  policy/extraction with optional local-model advice.
- `Memory.Projection` — one plain state/storage process owning the separate
  rebuildable SQLite projection. Its moduledoc records the plain-GenServer
  choice because storage lifecycle has no useful smarter-agent successor.
- Existing `ActiveMemory` and registered retrieval actions consume the
  projection and retain deterministic lexical ranking/direct-answer budget.

Claims remain under the established Markdown memory tree; new claim-stream
files use the existing category/namespace ownership rather than a parallel
canonical hierarchy. Projection/database paths derive through
`AllbertAssist.Paths`.

### v1.3 Search

- `AllbertAssist.Search` — domain facade, typed query/result/cursor/error DTOs,
  source scoping, and registered query/manage actions.
- `Search.Projection` — one plain state/storage process owning the dedicated
  SQLite connection, cursor, snapshot/page ingestion, redaction,
  digest/upsert/delete, rebuild verification, and generation promotion. There
  is no useful smarter-agent successor and no separate Store/Projector layer.
- `Search.IngestWakeup` — a tiny coalescing timer that invokes the registered
  management action through the Runner and never writes the projection.
- Search declares managed-job specs as data reconciled by `Jobs.Managed`; it
  does not add a Search-specific job service.

Search results carry canonical source IDs, author/trust/surface/thread/time,
post-reauthorization redacted snippet, lexical score, generation/projection
revision/freshness, and stable cursor. They never return a raw full transcript.

### v1.3 Jobs and Settings

- `Jobs.Managed` is a small context/helper over existing Jobs rows/actions.
- Settings Central owns feature grants, consolidation/search enablement,
  cadence, run/query caps, snippet bounds, E2EE-origin consent, and maintenance
  policy.
- Search projection state and Memory claim/projection state are not encoded in
  job metadata.
- Existing Settings Secrets/Key Custody provides one small domain-separated
  integrity helper for Forget suppression and manual-import confirmation; no
  new key service, encryption layer, or process is introduced.

## Workstreams, Serial Barriers, And Rejoins

### v1.2.1 workstreams

- **WS-L — licensing:** catalog/generator/viewer → release finalizer → native
  artifact qualification.
- **WS-T — TUI:** ADR/protocol → daemon session → thin client/lifecycle.
- **WS-D121 — docs/gates/dependency refresh:** may prepare in parallel, but
  version/gate/release docs cannot close until WS-L and WS-T rejoin.

WS-L and WS-T are independent until final artifact composition. Both touch
release packaging and therefore rejoin before native artifacts are built.
The three targets are built once from an unchanged candidate and those exact
bytes are reused for viewer/TUI smokes, signing, publication, and install
rehearsal.

Serial barriers:

1. ADR 0091 and the license artifact contract before corresponding code.
2. Final release-step order frozen before target manifest generation.
3. Both workstreams, dependency refresh, focused tests, static checks, docs
   drift, lane/inventory reconciliation, and `release.v121` at one clean SHA.
4. One authoritative `mix allbert.test release` at that SHA before FV/artifact
   publication.
5. Published/validated v1.2.1 before v1.3 implementation begins.

### v1.3 workstreams

- **WS-C — Corpus/policy:** SourceEnvelope, snapshots/pages, canonical
  reauthorization, consent, identity/remap/revocation, and Jobs.Managed.
- **WS-M — Memory:** claims/proposals/review/projection/consolidation/retrieval.
- **WS-S — Search:** projection/query/generations/management/deletion.
- **WS-U — surfaces/docs/evals:** shared DTO/action consumers, operator docs,
  security rows, external/FV preparation.

Serial barriers:

1. M1 current-HEAD/calibration contract before schema/storage code.
2. Corpus identity/digest/authorization and consumer grants before Memory or
   Search ingests canonical content.
3. Claim-stream validator and Memory projection before consolidation or prompt
   retrieval.
4. Search redaction, generation verification, and query-time Corpus
   reauthorization before any surface displays a result.
5. Deletion/revocation/E2EE semantics before DM or cross-surface rollout.
6. Integrated Memory/Search revocation rejoin before release gates.
7. Dependency refresh, Purpose/drift review, docs, cumulative gate, one
   authoritative release run, then FV and publication.

After M2, WS-M and WS-S may proceed in parallel because they own different
projections and consume only Corpus contracts. WS-U may build render-only shells
and fixtures after DTOs freeze; no surface ships before its authority barrier.

Rejoin proofs:

- v1.2.1 artifact rejoin: license finalization + TUI attachment over the same
  exact target release tree.
- v1.3 Corpus rejoin: one source revocation immediately suppresses Search and
  invalidates pending proposals while independently kept Memory remains.
- v1.3 lifecycle rejoin: canonical source delete, projection repair, pending
  proposal staleness, archive, and Forget each exhibit their distinct contract.
- Release rejoin: request flow, ADRs, operator/developer docs, metrics,
  inventory/no-loss manifests, dependency dispositions, and exact-SHA gates.

## Security And Privacy Posture

- Packaging/license inspection adds no runtime authority and performs no
  network access.
- Attach remains local-only, Home/uid/version/protocol/token bound, size-bounded,
  and fail-closed for attached clients. A TUI session does not bypass Runtime,
  Security Central, actions, confirmations, or trace redaction.
- `SourceEnvelope`, Search rank, cursor, source ID, job ID, proposal ID,
  objective ID, and model output are never authority.
- Memory proposals are inert; only registered audited review actions make kept
  memory. Protected facts are individually reviewed.
- Search is local and read-only at the query boundary. `:search_manage` covers
  projection effects, not canonical deletion or cross-surface disclosure.
- Corpus authorization is checked again at proposal review and result return,
  not only at ingestion.
- Secrets are rejected/redacted before projection/proposal writes. Raw search
  text/snippets, source excerpts, HMAC material, and forgotten content are
  excluded from traces/audits/logs/tests.
- E2EE indexing is an explicit privacy trade: decrypted local derived text
  exists in the Search projection. File permissions, backup exclusion, policy,
  reauthorization, and purge constrain exposure; encryption is not implied.
- Archive, canonical source deletion, projection purge, and Forget are separate
  typed/confirmed operations with separate consequences.

## Assumptions, Risks, And Stop Conditions

- **Best effort is intentionally not completeness.** A requirement for a
  complete universal SBOM/byte inventory is a new architecture/scope decision.
- **macOS needs one-time requalification.** Replacing floating Homebrew
  toolchains can alter dynamic closure. The OpenSSL patch is evidence-driven.
- **Manual append-only memory is a tighter contract.** Editing/removing old
  revisions is treated as corruption because silent mutation would destroy
  knowledge-time truth.
- **Forget cannot reach every copy.** Backups, exports, filesystem snapshots,
  and physical media are outside the active-store guarantee and must be
  disclosed before confirmation.
- **Search is plaintext-derived.** No encryption overhead is planned; local
  compromise/storage copying remains a residual risk documented to operators.
- **Search freshness is bounded, not synchronous.** Canonical reauthorization
  prevents stale disclosure, while physical repair may lag to the stated
  freshness/reconcile window.
- **FTS ordering is projection-revision-relative.** Scores may move after any
  ingestion. Cursors fail stale across generation or revision changes rather
  than promising continuity.
- **SQLite is one-writer per database.** Separate Search/Memory projections
  reduce contention and failure coupling but do not create a cross-database
  atomic transaction.
- **External memory literature drifts.** Tests freeze Allbert behavior; no
  external service/API becomes a runtime dependency.
- **Purpose remains the bar.** If an outcome cannot be completed within the
  bounded design, implementation stops for operator disposition rather than
  adding substantial framework code or quietly cutting scope.
